# 制作底稿与按任务条款

本文件是 Skill 自带的完整制作底稿与按任务条款，供仓库内外的制作任务直接使用；不要求先提交另一份任务文档。底稿中提到的库内路径按实际库根理解，接口与资料通过查询 CLI 按需读取。

收到制作请求时直接完成作品；底稿帮助理解和补足本次要求，不要求先提交另一份任务文档。占位项按当前任务替换，无关条款按范围裁剪。

## 通用制作底稿

派发时将占位项替换为实际内容，删除无关条款。需要的知识纠错、试用目标或特殊权限并入对应位置，不在末尾不断追加补丁。

```text
你负责制作指定知识的 HTML 可视化。以本次内容和操作范围为准，交付可阅读、可回顾的成果。

一、本次演示主题

<粘贴对应 MD 预留或简要需求：要解释的问题、表达对象或过程、理解目标及必要边界。已有明确的展示意图一并保留。>

二、执行上下文与范围

- 源 MD：<实际文件路径>
- 对应位置：<标题、预留编号或明确范围>
- 组件库：<实际可用目录>
- 制作与输出位置：<实际目录和必要文件名>
- 允许改动范围：<源 MD、参考资料、组件库和输出目录分别怎样处理>
- 交付形式：<例如独立离线 HTML，并保留必要作者源文件和重新生成方式>
- 本次专属要求：<仅在需要时填写，例如固定参数的阶段试用、明确要覆盖的公共能力、或与既有作品比较的范围>

先理解本次材料中相关内容，补读必要上下文。核对知识、单位、规则和适用条件；示意、省略和比例简化清楚说明。开始观看所需的对象与记号应容易识别，无须复制整章 MD。

三、表达与阅读要求

沿用本 Skill 的阅读与演示共识（见 `references/principles.md`），优先保证：

- 演示是视觉中心。简短前提、主要图解和回顾说明沿自然阅读路径组织；当前理解所需信息集中，减少来回寻找。
- 步骤演示的解说紧贴画面下方并保持稳定。同一理解停点内不按计时连续替换多句，换句有轻提示；读者可先看图再读说明，也可反过来。对象名称、数值、单位与必要短标注紧贴图形，结果读数与状态记录集中呈现，本步变化及意义由字幕讲清；字段组成、推导等扩展内容放在正常知识正文。先确定本步理解目标和主要阅读顺序，避免同一解释分散到路径、帧下、记录和字幕多处。
- 步进按有独立理解价值的稳定状态划分，一次推进可包含多个配合动作。完成后停住，保留必要依据和结果；提供与实际过程相适应的回退或重看能力。类 PPT 描述的是演示区，不要求整页幻灯片化。接受步进后执行态立即清楚可见，运行中阻止重复推进，必要变化收束后恢复。
- 图形表达操作与关系，前后对象可追踪。当前关注与本步变化形成主次，需要分别辨认的主要变化有先后承接，相关动作和辅助状态可以配合。对象运动、对齐窗口等已能引导观察时，不必再叠公共 Focus 框。结合文字的可见性和分布，检查主要变化是否容易跟踪、依据与结果是否对应、视线是否需要无谓寻找，避免独立区域同时争抢注意。
- 使用公共聚焦时，正常连续推进承接上一停点的观察位置；必要依据看清后再落到变化部分，内容与焦点按公共机制交接。字幕换句不要求焦点巡视；回退、重看和重来可按对应步骤初态重新开始。
- 读数按语义更新：阶段、模式、目标参数可以随目标提交；"已收到/已发出/已完成"等事实必须随领域事件或实际展示进度更新；预期值可以提前显示，但名称要明确是目标/预期。是否需要 Focus 巡视与何时更新分别判断，不强制所有计数分组、动画或逐处巡视。
- 过程中的重要变化来得及辨认，停稳后仍能理解。用合理承接、缓动和必要强调组织节奏，不以统一加速、统一放慢或末尾空等代替判断。
- 画面、解说和基本控制便于一起查看，推进不推挤操作区。必要文字正常可读，不藏在角落小字、悬停或必须展开的区域；也不为塞入窗口把图缩到看不清。
- 用对齐、留白、比例和视觉层级形成完成度。提示含义在本篇内自洽，具体图形随知识适配；不固定所有作品的步骤数、句数、颜色、时长或页面比例。

组织文字前先确定本步的理解目标和主要阅读顺序，不要求页面固定设置四个区域。对象名称、数值、单位和必要短标注紧贴对应图形；结果读数与状态记录集中呈现；本步发生什么、为什么变化主要由稳定字幕解释；字段组成、推导等扩展内容放在正常知识正文。图内必要注释可以保留，不规定统一句数、字数、标注数量或页面比例。布局后检查：是否需要在多个位置拼接本步解释，是否重复讲述同一道理，当前必要条件是否仍能直接看到，移入正文的内容是否确实不影响本步理解。不要用缩小字号、角落小字、悬停或折叠隐藏解决解释拥挤。

静态图解和参数联动按各自观察目标组织，不为凑齐步骤、字幕、控制或焦点而增加无意义结构。交互默认服务于观察、推进和回顾，不自行增加测验、评分或闯关内容。

四、实现与取用

如果已有有效上下文，直接沿用；缺什么再补读什么。定位实际库目录后，已知能力用查询 CLI 的 show 取当前接法，未知能力先 search；需要了解资料范围时用 info，完整参数与示例沿 read 继续读取。资料不足或存在具体疑点时，再查取用文档、API 或源码，不要求先通读全部资产清单和公共层手册。

复用公共组件、布局和运行能力，并按本次内容编写必要宿主图形。调用真实接口，不凭名称猜参数或强行把不适配的组件当作另一种图形。

需要多停点、回退和动作协调时使用现有 NoteDemo，内容、对象身份、必要因果与注意顺序由作者明确表达。使用 attention 等能力前核对当前接口和边界；不复制另一套播放器或用硬编码等待模拟公共完成机制。

领域模型决定知识状态与计算。注意编排和视觉过渡不改变模型中的时间、因果或并行关系。无合适组件时，在本次允许范围内做必要的局部实现，并说明真实缺口，不静默省略重要表达或擅自扩大共享库开发。

五、必要核对与交付

核对知识模型和代表状态，以实际速度观察需要动态理解的过程，并检查实际采用的关键操作。对具体疑点再补针对性探针，局部修改后只复核相关影响。

确认最终交付文件能在约定方式下打开、必要资源完整、关键操作正常。离线交付使用随成果提供或内嵌的资源；有动效时，减少动效仍应呈现正确且可理解的状态。

不默认做逐对象像素断言、全数值遍历、全视口截图或组件库完整回归。共享实现有改动时按实际影响扩大验证；必要检查通过后交付。

回复链接实际成果，简述表达方式、实际复用、组装摩擦、验证方法与剩余限制。区分程序检查、实际观察与用户评价，不用静态终态截图冒充动态观看，也不另建报告、状态文档或测试流水。
```

## 按任务需要补充的条款

只加入本次需要的部分；具体参数、知识内容与权限并入底稿相应章节。

| 情况 | 应补充什么 |
| --- | --- |
| 新 Agent 冷启动 | 交代当前工程位置、有效入口、已有成果和本次范围；旧任务不自动成为新授权 |
| 复用同一制作 Agent | 说明新任务与上一作品的关系、保留哪些成果、输出到哪里；不强制重新通读同一批文档 |
| 参数联动 | 指出可改变的量、需观察的关系和领域范围；数值、说明与图形读取一致状态，连续操作不积累迟到变化 |
| 过程或规则演示 | 指出关键事件、触发条件与理解目标，让作者划分有意义的停点；不把示例时刻数量规定为固定点击数 |
| 明确测试公共聚焦 | 写清要验证实际到达、内容启动、可承接后交接及最终收束；单独画一个框不等同于覆盖公共协调；接口细节查当前 API |
| 局部调整已有作品 | 给出具体问题与需保持的行为，修改和复核围绕影响范围，不重新设计整页或重复整套验证 |
| 限定权限或特殊试验 | 写明对象、动作、适用阶段和结束条件，避免被后续任务机械继承 |

已有演示可供参考时，说明需要借鉴的具体表达或接口。参考某个局部不代表整页布局、主题、数据与时长全部适用。
