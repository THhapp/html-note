# 阅读与演示共识

本文件是 Skill 自带的阅读与演示共识，供仓库内外的制作任务直接使用；不依赖项目专项文档，也不替代具体接口契约。实际 API、实现能力和限制按查询 CLI 或目标库当前文档核对；设计原则不代表所有组件或场景都已经获得体验认可。K 编号供组件清单引用。

## K01 建设的是全面的预制代码组件库

库供人和 Agent 查找、配置和组合；主体是成品组件与必要资源。不是只提供演示样片、批注层或多套主题，也不要求先写一份完整课程笔记。

## K02 MD、HTML 与生成指导的分工

MD 保留完整知识组织；HTML 能在一个有边界的问题内独立讲清目的、规则和结果。具体笔记的选择指导在 MD 侧简述与提示词中，库只提供必要用法和边界。

## K03 演示聚焦和字幕位置

演示是视觉中心；解释、控制围绕演示组织。字幕贴近可视化下方，位置稳定；图内保留必要对象标签和变化线索。需要分别辨认的主要变化有先后承接，避免多个远处分区同时争抢注意；同一关系中的配合动作和辅助状态可同步，不机械串行每个微动作。

## K04 稳定停点和读者推进

以有独立理解价值的稳定状态划分步进；一次推进讲清一件事，可包含配合动作。必要过渡帮助追踪，不能自动跨过多个理解停点。完成后保留结果与解释，支持前后步和回看。

## K05 字幕和图形允许先后阅读

同一停点字幕稳定，图形与解释成组停留；不要求读者同时追赶密集动画和新字幕。没有采纳固定一句话、取消所有微动画或每个像素动作都点一次的统一规则。

## K06 对象身份、当前关注与本步变化

身份保持可辨认，关注指出现在看哪里，本步变化指出相对前态改变了什么。关注较克制、变化更突出；同一对象兼具两者时合成提示，不机械叠两圈。对象运动、对齐窗口、范围强调或稳定位置已能引导观察时，不必再叠公共 Focus 框。判断依据是主要变化是否容易跟踪、依据与结果是否对应，以及视线是否需要无谓寻找；文字可见性与阅读顺序仍遵循 K09、K17。

## K07 提示含义稳定，形状适配内容

相同提示在同篇 HTML 内意义相近，跨演示可延续读图习惯；不要求所有图形、颜色、形状和布局完全一致。

## K08 窗口完整度与可辨认性共同权衡

尽量让演示、字幕和基本控制一起可见，减少频繁上下翻找；不能为了塞进窗口把图形和文字缩到难读。可依内容调整区域和局部滚动，演示中避免无意义跳动。

## K09 必要说明进入正常阅读路径

重要说明的位置、字号、明暗应匹配理解价值；例子范围说明紧贴例子。必要信息不能只在悬停、角落淡小字或折叠后找到；辅助快捷键等可以克制。

## K10 非硬性设计值不冻结

尺寸、步数、句数、动作数、页面比例和动画时间按内容适配；Tokens 是可配置的默认候选。测试窗口可以确定，但不能伪装成通用设计标准。

## K11 继承已有 UX，不重新进行语义论证

沿 UX → Tokens → 组件 → 交互实现推进。共享阅读目标由本文件说明，组件承担可复用表达，宿主负责内容与装配；按实际使用补齐缺口。

## K12 图形承担解释，动作服从理解

变化应呈现对象如何移动、传递、插入、拆合，前后能对应；动效流畅不等于更快。保留有解释价值的动作和停稳线索，不用装饰运动填满画面。

## K13 教学性交互暂不扩展

组件与笔记表达服务于知识展示、演示和回顾。输入控件供宿主配置和控制，不据此扩展成测验、评分或闯关平台。

## K14 页面反馈与组件规范分清适用范围

具体页面的配色、容器和装饰按内容与实际观感选择。组件可有必要容器与局部色彩，不把一个页面的反馈扩成全库禁用暖色、浅底、圆角或阴影的规则。

## K15 已有资产的能力边界

已有组件的能力范围以对应模块文档为准；总体评价不自动覆盖全部参数或未展示场景。

## K16 组合与接口边界

组件管理内部空间，宿主或布局组件安排外部组合；具体例外按实际接口处理。新组件沿用 NoteUI、NoteViz、NoteBlocks，NoteExpr 与 SeqInsert 保留各自公开接口。共享设计值提供可配置默认，不冻结所有场景的具体数值。

## K17 文字职责与阅读顺序

先确定本步的理解目标和主要阅读顺序，再组织布局。对象名称、数值、单位和必要短标注紧贴对应图形；结果读数与状态记录集中呈现；当前步骤发生什么、为什么变化主要由稳定字幕解释；字段组成、推导等扩展内容放在正常知识正文。图内必要注释可以保留，但不规定统一句数、字数、标注数量或页面比例。布局后检查是否需要跨多处拼接解释、是否重复讲述同一道理、当前必要条件是否直接可见、移入正文的内容是否仍不影响本步理解。不要用缩小字号、角落小字、悬停或折叠隐藏解决解释拥挤。

## K18 目标说明与已发生事实

阶段名、当前模式、目标参数和预期结果可以随目标提交或提前展示，但名称要明确是“目标/预期”。
“已收到”“已发出”“已完成”等事实必须与领域事件或实际展示进度一致，不能在对象尚未到达时先显示完成值。
是否需要 Focus 巡视与何时可以更新数值分别判断；不要求所有计数单独分组、动画或逐处巡视。
