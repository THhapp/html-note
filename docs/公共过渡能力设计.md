# 公共层设计与取舍

> 资料定位：解释 NoteDemo 公共层的设计理由、执行契约与维护边界。**现行 API、参数、默认值和用法以[公共编排层](公共编排层.md)为准**；本文不重复维护接口清单。组件 API 见各模块文档，阅读目标见[设计共识](设计共识.md)。

本文关注注意承接、内容时序与自定义图形接入为何这样组织，以及这些选择的代价；具体 API、默认值和边界以[公共编排层](公共编排层.md)为准。

## 1. 要解决的问题

HTML 学习笔记需要一个可复用的浏览器端运行层：作者提供知识数据、停点、字幕和过渡意图，公共层负责推进、回退、重看、字幕、标记、取消、减少动效和完成边界。

边界：

- 运行层不生成知识内容，不推断教学因果，不做可视化编辑器、分支剧情或任意时间轴。
- 组件实例在会话期间常驻；Frame 只保存可恢复的数据与提示；Adapter 负责组件接入。
- 旧 `actions/parallel` 命令路径与 `scene` 完整目标过渡并存，各有用途，不能因为新示例采用 scene 就把 actions 当作死代码。
- 成品运行不需要 Agent、模型、网络或运行时构建。

## 2. 设计约束

来自[设计共识](设计共识.md)的硬约束：

- 演示是视觉中心；字幕在演示下方且位置稳定；必要解释在正常阅读路径。
- 默认静止，由读者推进；一次推进讲清一件事，可包含配合动作；完成后保留可理解的结果。
- 对象身份、前后状态和变化过程可追踪；同一停点内字幕稳定。
- 不统一冻结步数、动作数、时长、尺寸或页面比例。
- 公共问题修在可复用实现；宿主负责内容与布局；不动辄新增主题、遮罩或全库统一关动效。

## 3. 分层与数据流

| 层 | 职责 | 不负责 |
| --- | --- | --- |
| Definition | 定义校验、冻结、规范化、比较、编译 | 播放、DOM、计时 |
| Controller | 会话状态、唯一 runId、Abort、导航 API、错误恢复、订阅 | 具体动作与呈现 |
| Runner | 旧 `actions/parallel` 的执行、取消、读回核对 | 教学顺序 |
| Scene | 完整目标画面的同步事务、after 依赖、ready/finished、attention 协调 | 知识因果、第二套时间轴 |
| Adapter | 视图规范化、组件挂载/借用、动作、目标查询、prepareChange/effects/readView | 跨 Binding 调度 |
| EffectScope | WAAPI 句柄、源视觉保持、ghost、cue 差分、清理 | 第二套会话状态 |
| Presentation | 默认舞台、字幕、控件、标记呈现、settle、attention 焦点 port | 知识内容 |

一次推进的数据流：

```text
next()/replay()/go()
  → controller 建立本次运行（runId / Abort）
  → 字幕切到目标 Frame，按钮进入执行态
  → runner（actions）或 scene（目标事务）
  → Adapter/组件提交目标 model，公共层读回核对
  → 按 ready/finished 启动依赖、呈现标记与字幕收尾
  → presentation.settle() 转稳定测量
  → 原子提交 settledFrameId，恢复 idle 与按钮
```

取消、失败和迟到回调都沿同一条运行边界处理；旧运行的 Promise 不能改变新一轮的位置、字幕或标记。

## 4. 同步目标事务与源视觉保持

scene 的核心是“一次提交完整目标，再受控地把视觉从源带到目标”：

1. `prepareChange` 在提交前冻结源内容、源样式、必要几何和 cue；准备可清理资源。
2. 所有异步准备完成后进入同步提交区：提交全部目标 model，读回真实状态并与目标 Frame 核对。
3. 在同一任务内测量目标几何、建立局部 ghost/反向位移、创建并暂停本次全部效果；事务中不插入 `await`、额外 `setTimeout` 或表演性 rAF。
4. 未启动的效果必须保持源视觉；不能用“把目标 model 晚点写入”来掩盖瞬切。
5. 全部成员 finished、标记与字幕收束后，释放临时 fill/ghost，让组件目标样式自然接住终态，再提交稳定停点。
6. 正常完成不做通用 `commitStyles` 回灌；取消先使运行失效并清理，再恢复来源 Frame。

这套顺序保证：模型、视觉、按钮状态三者不会互相抢写；失败不会被动画完成掩盖；取消不会留下迟到提交。

**局部效果结束后的稳态交接**：`ready/finished` 只说明任务完成，不自动保证画面被正确接住。Adapter 用 `EffectSpec.handoff:'hold'` 标记“正常完成后要保持末帧”的目标内容效果；公共 scene 只对该 spec 使用 `fill:'both'`，等整步收束取消句柄后由目标基础样式接住，取消/失败则先恢复来源。退出副本、提示脉冲等不该保持末帧的效果不声明 handoff，也不使用全局 `commitStyles`。`cleanup()` 仍只释放临时资源，不承担“第一次正确显示目标内容”。

**来源对象保留到观察结束**：目标 commit 可能把来源对象压成不可见（例如旧层的 active 状态被摘掉），而 attention 还要观察它。`PreparedChange.sourceElements()` 在 commit 前声明这些来源元素；公共 scene 捕获其可见状态，commit 后临时恢复，并在该 Binding 第一个内容轨道启动（来源开始被替换）时释放。作者声明真实对象，公共层只恢复 `opacity/visibility/display`，不克隆、不重建、不猜知识含义。

这两项共同把“未启动保持来源、运行中属性归属、局部结束接住目标、ready 后交接、finished/cleanup 收束”连成闭环；动画句柄本身不承担稳态兜底。

## 5. ready / finished / after

三个时点必须分清：

- **start**：本次运行允许该成员启动本地效果，不代表目标值已经可辨。
- **ready**：该成员的关键内容真实完成，后续依赖可以承接。
- **finished**：该成员全部效果与清理完成，本次运行才能收束。

规则：

- `after` 只引用同一 scene 的成员，等待其 ready；无 after 的成员同窗启动；没有效果的成员立即 ready，不占空等。
- layout 位移、内容入场、同 ID 值替换、显式 cue 轨道可以承担 ready；旧值 ghost、退出副本、非必要强调和脉冲通常只计 finished。
- reveal 保留自身语义：没有 after 时用 `at:'start'` 或 `objects-settled`；显式 after 优先且不能同时给 at。
- cut 在同步事务中立即显示目标，不能声明 after；需要承接视觉时用 update/reveal。
- 字幕和外部标记不属于任一 Binding 的 ready，但参与本次运行的最终收束。
- 不用固定秒数或百分比假装“已经可辨”；需要同窗就省略 after，需要完整内容就写 after。
- attention 的观察停留属于 Focus 的阅读节奏，不属于 Binding 的 ready：观察型目标从真实到达起默认停留 `stepDuration`；触发内容的目标先等该组效果真实 ready，默认 ready 后不再追加停留（显式 `holdDuration` 才追加）；最后落点不倒计时。这样不会把“内容动画时长 + 固定观察时长”双重相加，也不把“代码已启动”当成“读者已经看到响应”。

## 6. Timing 契约

有效 timing 的优先级固定为：

```text
公共默认 → Adapter.sceneTimingDefaults（稀疏） → scene.timing → 该参与者 timing
```

- 0 是有效值；稀疏输入在定义阶段冻结并校验，未知键、负数/非有限数、浏览器不接受的 easing 直接报错。
- `duration` 只是布局位移时长，不等于全部动画；`enterDuration`/`exitDuration`/`valueSwap*`/`cueDuration`/`mark*`/`reveal*` 各有明确消费方。字段含义与默认值见[公共编排层](公共编排层.md#2-definition-形状)的 timing 表。
- 声明 `scene.attention` 的 scene 会在 Adapter 默认之后、scene/member timing 之前套用一套较慢的公共识别节奏；普通 scene 保持原默认，不改变既有认可流程。
- timing 是作者可调的节奏输入，不是笔记设计的统一硬标准；适配器只消费自己真正实现的效果，不虚构动画。

## 7. 元素与属性归属

| 载体 | 拥有者 |
| --- | --- |
| layout 载体的 transform | scene FLIP |
| contentCarrier 的 opacity/transform | 内容入场/退出 |
| valueEl 的 opacity/transform | 新值交换 |
| 同 carrier 下的旧值副本 | 旧值离场 |
| 组件 cue 的连续样式/专用视觉层 | cue 差分 |
| 外部 Focus/Range/Link 根 | Presentation 受控标记 |

同一元素同一属性只能有一个写入者；离散样式（display、outline-style 等）不能混进颜色渐变，组件要提供能接住终点的稳定目标样式。

## 8. 注意交接（scene.attention）

attention 是作者显式声明的阅读注意路径，不是内容推断：

- `targets` 按作者给出的顺序列出 `{binding, query, groups?, holdDuration?, range?}`；公共层不根据数据变化自动猜教学重点。
- **会话焦点**：默认舞台每个 presenter 懒创建一个 `NoteExpr.Focus`，跨 attention 场景复用。首次进入在起点软出现；正常下一步从弱化位置恢复并迁移；本步收束后在最后落点快速弱化为虚线/低强调并静止（不闪烁、不呼吸、不倒计时）；取消、回退、重看、重来、跳转按导航策略隐藏或重启，teardown 销毁。会话焦点不属于全页共享状态。
- **运动**：框迁移用对称加减速，从静止加速、后半段以同大小减速度停下；归一化进度 p(u)=2u²（前半）与 1−2(1−u)²（后半），T=2√(D/a)。D 取对应角点最大位移并覆盖尺寸变化，位置与宽高共用同一进度；加速度集中配置、按相邻/跨区/范围变化实际观看校准，不设近中远档，也不对所有迁移固定时长。目标本身在动时连续跟随，不每帧重启迁移；到达后活动期逐帧跟随，weak 静止期停止逐帧、只按布局事件重测。
- **到达与交接**：`whenArrived()` 是实际几何完成，不是计时器。到达后才放行该目标对应的内容组；内容 ready 与观察停留都满足后才迁移；最后落点不再加观察倒计时。观察型目标从到达起默认 `stepDuration`；内容型目标默认 ready 后 0 额外停留，显式 `holdDuration` 才追加。
- **看哪里与放行什么分开**：`groups` 省略=整 Binding 默认门控（未分组 Adapter）；`[]`=只观察；非空=放行命名效果组。声明了 `PreparedChange.groups()` 的 Adapter 可让同一 Binding 先观察不同依据、再由不同目标放行不同局部组。一个组最多被一个目标门控；未知组、重复门控、漏归属与不完整覆盖定位拒绝。组内图形/文字/提示/局部副本的完整覆盖由 Adapter 负责，公共层只校验归属。
- **观察范围**：`range` 用 `local`（相对主目标矩形的局部区域）或 `union`（主目标与引用目标的并集）表达事件附近范围，不把屏幕坐标存成长期目标；公共层负责坐标换算与跟随，Adapter 只解释 query。SVG 包围盒准确不等于观察范围合适，作者仍要给出合理区域。
- **联合依赖**：attention 顺序与 after/reveal 隐式依赖共同构成 waits-for 图；定义期能判定的循环在 prepare 拒绝，需要 Adapter 组信息的在 prepare 后、目标提交前拒绝，并给出具体循环路径。attention 不改变模型提交与 ready/finished 的因果定义。
- 减少动效时不建/不留会话焦点、不迁移、不增加等待；非正常导航会先隐藏旧焦点，旧运行回调不能恢复新运行样式。`NoteDemo.create` 自备 presentation 时需要实现同名 port 语义，否则运行期报错。

### 8.1 自定义图形接入的分工

- 图形组件保留稳定对象身份：底座、历史层、文字节点不整图重建；一次停点只追加本次证据层，旧层保留，不用新层叠画覆盖历史标记。
- `prepareChange` 捕获来源视觉与必要几何；`commit` 同步提交完整目标，并在绘制前把延后内容预置到来源视觉；`effects` 用命名组把图形、前沿、文字、提示与局部副本完整归组，未获放行时保持来源视觉。
- 连续数值属性（SVG 的 x/width/cx 等）用 `type:'progress'` spec 的 `update(progress)`；公共 scene 提供唯一 rAF 调度、取消与 finished，作者不复制播放器或另建计时器。
- 作者可用 `NoteDemo.effects` 的 `captureContent` / `createGhost` / `planValueSwap` / `captureStyles` / `planCueChanges` / `rectOf` 等窄工具；不需要 `NoteDemoInternals`。
- 示例 `examples/propagation` 只验证通用能力；物理常量、坐标、图层数量和页面比例属于示例，不进入核心。

## 9. 引擎与依赖取舍

- 运行后端只有一套：现有 `NoteCore.motion` + WAAPI + 内部 EffectScope；不引入第三方动画运行时，不向笔记作者暴露引擎选择。
- 试过 Anime 4.5.0 与 Motion 14.7.1 的最小真实样片：前者会强制接管非 target 后代的内联样式，与 D01 内层载体冲突；后者公开 stop/cancel 不结算 finished，取消后留下内联 transform/opacity。两者都没有满足受控分层、真实取消与资源清理门槛，因此不进入依赖。
- 值替换 ghost、连续 cue 差分、数值进度句柄等局部能力由 demo effects 工具提供；progress 与 WAAPI 句柄共用启动/取消/finished/清理关系，各 Adapter 保留自己的波形与清理职责。
- 借鉴成熟实现的机制（keyed 对象身份、同步目标事务、明确的属性归属、WAAPI 完成/取消语义）但不复制其运行时；外部许可处理见[第三方说明](../THIRD_PARTY_NOTICES.md)。

## 10. 错误、取消与减少动效

- 不吞错：定义错误在创建阶段抛出并带 Frame/Binding/Action 定位；运行期失败进入 error 状态并尝试恢复最近稳定停点，恢复失败如实保留状态。
- 不把失败动画包装成正常完成：效果创建/启动失败终止本次运行并清理，不启动下游依赖。
- 取消：先使运行失效，再取消句柄、移除 ghost/fill/标记，由 controller 恢复来源 Frame；迟到的 finished/cancel 回调不能提交新 Frame。
- 默认舞台“上一步”映射 `replayPreviousStep()`：上一停点有入边时从该步初态重播，允许焦点跳变；`session.prev()` 仍是直接恢复上一停点，供自定义宿主使用。会话焦点的弱化/隐藏是呈现状态，不计入 ready/finished，也不延长完成边界；旧运行不得改写新运行的焦点样式。
- 减少动效：直接落到正确目标，不创建 ghost、不迁移焦点、不制造最低置灰时长；字幕、标记和按钮状态仍一致。
- 资源归属：组件只清理自己拥有的资源；borrowed 实例不被销毁；layout.cleanup 在正常销毁和取得返回值后的挂载失败中恰好调用一次。

## 11. 已知边界与非目标

- Frame 为线性停点；不实现分支、自动串播、暂停/恢复、编辑器、JSON 解释器或 Agent 检索服务。
- 内置 Adapter 覆盖 matrix、sequence、sequence-edit、sequence-insert、dom、expression；其他图形用本地自定义 Adapter 接入。场景过渡只做窄 HTML 布局：布局载体只位移，不覆盖 SVG 内部 transform，不做任意时间轴。
- sequence 的离场对象 v1 不生成 ghost；需要删除证据时用目标停点状态/标签表达。
- 默认舞台仍携带 blocks 及其传递依赖，未做按组件裁剪；这是明示限制。
- 效果组与观察范围是 opt-in 能力：内置 Adapter 尚未拆细效果组；同一组内图形/文字/提示/局部副本的完整覆盖由 Adapter 负责，公共层只校验归属、未知组与重复门控。attention 的 range provider 用实时矩形，与受控 Frame 标记提交期间的冻结几何不同。
- 会话焦点在组件重建后经约 150ms 去抖重新解析；weak 目标被移除后短暂保留旧几何再转 idle；reduced 下不创建/不保留会话焦点。
- 完整限制清单只在[公共编排层](公共编排层.md#9-已知限制)维护，本文不复制一份以避免两处漂移。
