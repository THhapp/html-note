# 公共层开源实现代码对比

> 资料定位：研究资料，比较公开实现的源码、发布入口、完成/取消、许可与接入代价；不是现行 API。现行接口见[公共编排层](公共编排层.md)。

本工程采用窄 FLIP + WAAPI；本文保留各实现的源码证据与复用边界，不表示需要重新选择引擎。

## 1. 先给出工程判断

1. **布局过渡与相对时间线，优先直接验证 Anime.js 4.5.0 和 Motion 14.7.1。** 两者的发布物都有原生 DOM 布局 API，不必从零重写复杂 FLIP，也不要求把整库改成 React/Vue。
2. **GSAP Flip 是有实际技术价值的第三候选。** 显式 ID、嵌套坐标、全局矩阵、批量捕获和时间线很完整；采用时须保留自定义许可边界，不能标成 MIT。
3. **代码变更演示可单独采用当前 Shiki Magic Move 的独立 renderer。** 通用位、字节、图节点仍用业务 key，不照搬文本 diff 当身份。
4. **公共层继续拥有 Frame、导航、步骤结果与取消。** 引擎负责几何与补间，不能用其 then/finished/revert 直接替换现有契约。
5. **OpenMAIC、visual-explainer 是实际教材/Agent 产物链的参考。** 有可取用的小型 runtime、编译器和离线装配代码，但没有发现一套可原样移入、同时解决本项目全部需求的工作台。
6. **Motion Canvas、Remotion 是另一种完整执行模型的对照。** 不因其偏视频就忽略：前者确有手动停点；后者提供帧驱动定位。整套采用会更换宿主和渲染体系，当前收益不足以抵消改造。

以上是工程判断，不代表用户已选定依赖或认可任何新动效。

## 3. Anime.js：发布版已经有布局事务

入口：[AutoLayout 实现](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/src/layout/layout.js#L948)；[分发清单](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/package.json#L1)。

### 调用链与对象处理

createLayout(root) 建立受控容器，update(callback) 依次执行：

~~~text
record 旧布局和样式
→ 同步 callback 修改 DOM
→ animate 测目标布局、按 data-layout-id 配对
→ 分类继续存在 / 进入 / 离开 / 替换
→ 临时定位、反向变换与属性补间
→ 统一 timeline
→ 清理临时样式并保留目标 transform
~~~

[稳定 ID 与节点建立](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/src/layout/layout.js#L280)允许显式 data-layout-id；适合映射已有模型 ID。相同值不必当成同一对象，相同对象改值也不应换 ID。

[记录新布局和配对](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/src/layout/layout.js#L1172)已包含进入、离开、重排和替换分支。[WAAPI 纳入同一时间线](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/src/layout/layout.js#L1571)将 transform 动画交给 WAAPI，再由 timeline.sync 驱动；其他样式变化与它共享父完成边界。不是每个元素自己完整结束后才轮到另一个。

[完成整理](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/src/layout/layout.js#L1107)恢复临时定位与内联样式，下一帧才恢复 CSS transition，避免收尾又触发一次过渡。这是“按钮恢复后还有尾巴”的直接实现参考。

### 接入限制

- [update 的实际实现](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/src/layout/layout.js#L1600)不 await callback 的返回值。若 Adapter 是异步渲染，必须先准备数据，再同步提交 DOM；不能把 async update 塞进去便认为新几何已就绪。
- LayoutSnapshot 遍历跳过 SVG。Anime 有独立 SVG 动画能力，但这不代表 createLayout 会自动处理图内节点的布局。
- 引擎临时控制 position、尺寸、min/max、margin 等。适合独立对象容器；与组件自有布局/transform 的冲突必须用代表场景验证。
- record 会取消旧布局过渡；保留中途视觉、回源 Frame、跳到目标 Frame，是公共层需要明确执行的不同操作。
- 完整布局源码约 56 KB 字符，不建议手抄成自己的长期 fork。优先依赖公开 API。

### 相对时间与 Promise

时间线的位置语法有明确差别：Anime 的 < 是前一子动画结尾，<< 才是前一起点；GSAP/Motion 的 < 通常指前一起点。公共层若给出统一相对时机，必须转译，不能直接转发字符串。

[Timer 的取消与等待](https://github.com/juliangarnier/anime/blob/2c9cf8ea00329f6768c7d7902252ed977d75ce42/src/timer/timer.js#L450)暴露两个接入问题：

- Timer.cancel 设置取消状态并暂停，不 resolve 正常完成等待。
- Timer.then 写单个 _resolve，第二次注册覆盖前一次。

发布源码方法级探针确认了这两条控制路径。NoteDemo 应只监听一次底层完成，向外提供自己的共享 Promise，并在取消时自行结算。此结论限定 Timer，不泛化成所有 Anime WAAPI 包装的取消都相同。

同目标同属性还有覆盖机制：新 tween 可能截断旧 tween，乃至取消父句柄。因此引擎能处理属性冲突，也不代表布局、强调、注释可以随意同时写同一 transform。

### 复用判断

MIT；无必需运行依赖；three 是可选 peer。发布版含经典 UMD，min 文件 118,043 字节，是原文件大小而非 gzip。主入口和 animejs/layout 子路径都导出 createLayout。

**当前最省宿主改造的候选。** 先验证布局事务和时间线，不移植其整个内部结构，不采用默认时长作为本项目标准。

## 4. Motion：vanilla animateLayout 已实际发布

入口：[animateLayout](https://github.com/motiondivision/motion/blob/9ba8846b6819172cb829e65a9f46433a4de377ab/packages/motion-dom/src/layout/animate-layout.ts#L19)；[builder 批次](https://github.com/motiondivision/motion/blob/9ba8846b6819172cb829e65a9f46433a4de377ab/packages/motion-dom/src/layout/LayoutAnimationBuilder.ts#L227)。

14.7.1 已通过 registry gitHead、发布 tag 和实际 npm tarball 入口交叉核对，包含公开 animateLayout / LayoutAnimationBuilder。不是从 React layout prop 推测原生能力，也不是未发布 main 功能。

### 跨组件批量提交

同一同步 tick 建立的 builder 合并处理：

~~~text
发现全部目标，按文档顺序挂 projection node
→ 全部 willUpdate 捕获旧位置
→ 运行全部 updateDom（支持等待 Promise）
→ 先处理所有新增共享 ID，再处理删除
→ root.didUpdate 生成布局投影
→ 收集 currentAnimation，形成 GroupAnimation
~~~

顺序的重要性在于：A 组件写布局之前，B 组件的旧位置已经捕获；同 ID 的新成员建立之前，不提前丢掉旧成员快照。

内部 projection 批量 resetTransform、读取布局、通知变化，再同步刷新，避免目标位置先闪一帧。这里包含父子缩放、滚动和共享节点交接，已经是大型引擎，**优先公开依赖，不建议摘抄内部 projection**。

data-layout 跟随同 DOM 节点；data-layout-id 支持共享对象匹配。但普通无对应项的进入/退出，并不自动变成完整入离场设计，应显式配置。

### ready 不是视觉结束

[builder.then](https://github.com/motiondivision/motion/blob/9ba8846b6819172cb829e65a9f46433a4de377ab/packages/motion-dom/src/layout/LayoutAnimationBuilder.ts#L336)等待的是 readyPromise；finalize 只把已产生的动画组交出来。因此底层使用要区分：

~~~js
const group = await animateLayout(stage, commitTarget, options);
// 动画组已就绪
await group.finished;
// 正常视觉完成；取消还要走公共层自己的结算路径
~~~

### 完成、取消与 scope

[正常完成与 cancel](https://github.com/motiondivision/motion/blob/9ba8846b6819172cb829e65a9f46433a4de377ab/packages/motion-dom/src/animation/NativeAnimation.ts#L98)自然完成先写最终样式、撤掉 WAAPI，再 notifyFinished。这能防止清掉 fill 后回闪。

但 cancel/stop 不走相同的 notifyFinished；layout 所用 JSAnimation 也有这个区别。[finished 的实际结算](https://github.com/motiondivision/motion/blob/9ba8846b6819172cb829e65a9f46433a4de377ab/packages/motion-dom/src/animation/utils/WithPromise.ts#L14)只在 notifyFinished 时 resolve，GroupAnimation 又对所有子项 Promise.all。因此直接 cancel 后等待 finished 可能永久挂起。

scope.cancel 还会恢复登记过的原 inline style，stop 则保留当前位置。这些都不等于恢复组件模型。应由 NoteDemo 先取消视觉，再按导航意图恢复对应 Frame。

系统减少动效方面，布局 VisualElement 默认读系统偏好，projection 会关闭布局过渡；不能据此认定所有普通颜色、透明度和自定义动作也自动关闭，仍需统一翻译 NoteDemo 策略。

### 时间线与分发

[sequence 编译器](https://github.com/motiondivision/motion/blob/9ba8846b6819172cb829e65a9f46433a4de377ab/packages/framer-motion/src/animation/sequence/create.ts#L45)把 subject/property/label/相对位置编译成属性时间轴。可以重叠，仍保留依赖；不必把整段动作压成全并行。

MIT。motion-dom 声明的直接运行依赖是 motion-utils；motion 总入口还经 framer-motion/dom 重导出，但原生路线不要求 React。精确本地 bundle 大小在本次核对没有构建测量，不能用包下载大小代替。

**与 Anime 同列优先候选。** 对跨容器、复杂父子布局更值得比较；代价是更重的 projection 与两阶段完成适配。

## 5. GSAP Flip：成熟批量布局能力，许可单独看

入口：[Flip](https://github.com/greensock/GSAP/blob/13e2b790546426a1a2e0e9b409f3f8dc6d6611f2/src/Flip.js#L185)；[FlipBatch](https://github.com/greensock/GSAP/blob/13e2b790546426a1a2e0e9b409f3f8dc6d6611f2/src/Flip.js#L793)；[坐标矩阵](https://github.com/greensock/GSAP/blob/13e2b790546426a1a2e0e9b409f3f8dc6d6611f2/src/utils/matrix.js#L286)。

### 实际实现值得看什么

- data-flip-id 决定逻辑身份。
- FlipState / ElementState 保存矩形、矩阵、样式等；compare 区分 changed/unchanged/enter/leave。
- from/to/fromTo 从前后状态生成过渡；enter/leave 另行处理。
- 嵌套对象和绝对定位有专门分支；global matrix 解决祖先 transform、SVG、滚动坐标等。
- FlipBatch 将 getState / loadState / setState / animate 分开：先读齐全部旧态，等待资源准备，再写状态和动画，避免各模块互相污染测量。
- 属性可用不同持续时间与缓动，布局和局部强调不必同速结束。

GSAP 的相对位置解析提供 label、<、>、+= 等，但 < 表示前一起点，不同于 Anime。不要让 Agent 学三套供应商语法；由公共层编译一次即可。

### 生命周期与许可

[Animation.then](https://github.com/greensock/GSAP/blob/13e2b790546426a1a2e0e9b409f3f8dc6d6611f2/src/gsap-core.js#L1420)已经串接旧 resolver，多个 then 可以同时得到完成。这一点与本次 Anime Timer 不同。[kill 中断路径](https://github.com/greensock/GSAP/blob/13e2b790546426a1a2e0e9b409f3f8dc6d6611f2/src/gsap-core.js#L646)不 resolve 正常完成 Promise；方法级探针验证 kill 触发 interrupt、等待仍 pending。

Flip.revert 还有专用覆盖，会推进以清除临时样式，不等同于所有动画对象“回到源快照”。接入时不能把 cancel、kill、revert、complete 混用。

GSAP 使用自定义 Standard No Charge License，允许常见网站与应用用途；对竞争性可视化无代码动画搭建器有特定限制，官方 FAQ 也明确谈到 AI 生成 GSAP 代码。**Agent 使用本身不是一概禁止，但未来若扩展为可视化编辑器，需要按实际功能重新核对。** [官方许可](https://gsap.com/community/standard-license/)

这是技术强候选；本工程未选为默认，不把自定义许可源码当 MIT 随意拆走。

## 6. AutoAnimate 与 Svelte：同样叫 FLIP，身份和控制粒度不同

### AutoAnimate：DOM Element 是身份

[WeakMap 缓存](https://github.com/formkit/auto-animate/blob/b6a6feebf75c198dd85f280c549bc0303f9e7aa8/src/index.ts#L49)用真实 Element 作 key。只要原节点被复用，列表重排很省事；重新创建节点，即便 data-key 相同也不自动认成同一对象。

MutationObserver 只观察 parent 的 childList；不统一解释文本、属性和深层语义变化。remain 计算位移与尺寸，add 做进入，remove 暂存原位置并绝对定位，最后移除。

[公开 controller](https://github.com/formkit/auto-animate/blob/b6a6feebf75c198dd85f280c549bc0303f9e7aa8/src/index.ts#L883)只有 enable/disable/isEnabled/destroy，没有“这一轮所有动作真正结束”的 Promise。默认进入还有先透明一段的安排，直接套在舞台可能重新带入用户不喜欢的等待。

MIT，无必需运行依赖。**可用于不参与步骤完成边界的普通列表增强；不是当前主执行器的省事替代。** 退出被 cancel 时的清理值得后续单测，但本次核对没有浏览器复现，不能宣布为已确认 bug。

### Svelte：key、几何与调度各有职责

[flip 几何](https://github.com/sveltejs/svelte/blob/23bb146306ff02cc5041bca0c5de9f8bd086e4a3/packages/svelte/src/animate/index.js#L13)输入前后 DOMRect，计算 transform-origin、祖先缩放、CSS zoom、位移和尺寸比，并保留原 transform。它是小型几何函数，不自动匹配对象或管理播放器。

keyed each 先按业务 key 找对象，更新前统一 measure；重排后再统一 apply。退出对象用 fix/unfix 临时固定，避免污染其他对象布局。

crossfade 的 send/receive 用逻辑 key 的两张 Map，延迟解析到同批两端都登记后再配对。这适合同一逻辑对象从一个容器换到另一容器，DOM 本身已替换的情形。

animation manager 在中断时释放 effect 和完成回调；反向从当前进度接续。**值得移植的是几何、配对及 measure/apply/fix 分工，不是整个 each/effect runtime。**

MIT。纯几何探针验证 flip 与 crossfade 的起终坐标；没有验证视觉流畅度。完整 Svelte 框架引入不作为当前首选。

## 7. Reveal.js：前后页配对，比逐对象命令更接近 PPT 体验

[AutoAnimate.run](https://github.com/hakimel/reveal.js/blob/e240e175232fa2de660a02bc0d7bf5f655b159bb/js/controllers/autoanimate.js#L24)做 reset → 配对 → 测量 → 一次生成 CSS → 应用样式 → running；不要求把移动、缩放、改色分成多个 await。

[默认配对](https://github.com/hakimel/reveal.js/blob/e240e175232fa2de660a02bc0d7bf5f655b159bb/js/controllers/autoanimate.js#L418)先匹配显式 data-id，再尝试文本、媒体、代码。可定制 matcher。对本项目必须以模型 key 为主：重复 7D 的“值相同”不代表“是同一枚字节”。

具体保护值得移植：

- 文本默认不 scale，改字体相关属性；代码块宽高变化与逐行匹配分开。
- Fragment 自己控制 opacity，AutoAnimate 就让出 opacity，避免系统争夺属性。
- 同 fragment-index 的元素属于一次点击；回退按索引重算 visibility，不逐个撤销历史 class 操作。

[getState/setState](https://github.com/hakimel/reveal.js/blob/e240e175232fa2de660a02bc0d7bf5f655b159bb/js/reveal.js#L2283)只保存页位置、Fragment、暂停、概览，不是任意组件模型。AutoAnimate.run 也没有整体 finished Promise。

本次核对用真实匹配函数和假节点执行：显式 ID 能保持 7E→5E 的身份；内容匹配会把原有 7D 错配给新插入的同值 7D。结果支持稳定 key 的具体实现选择，非浏览器验收。

MIT。**局部采用 matcher、文字保护与属性归属。** 完整 Reveal 可成为真正 deck 的宿主，但会带入自己的页模型、CSS 和导航，属于另一架构选择。

## 8. Slidev：每次点击重算完整目标，而非反放动作历史

[useClicks](https://github.com/slidevjs/slidev/blob/a42aff28dd75f26eb5abbf3d616ea022c3d08924/packages/client/composables/useClicks.ts#L31)规范绝对、相对和范围点击；v-after 的 +0 表示同一次点击，不表示“等前一动画完成”。

[v-motion 目标合成](https://github.com/slidevjs/slidev/blob/a42aff28dd75f26eb5abbf3d616ea022c3d08924/packages/client/modules/v-motion.ts#L58)按当前页面/点击位置重新合成 initial、enter 和全部已激活的变体，然后一次 apply；打印则 set。

可直接借用的实现模式是：

~~~text
目标样式 = 初始样式 + 进入状态 + 当前索引之前所有有效变体
回退 / 跳转 → 重算目标，不回放逐个逆动作
~~~

但这是视觉 variant，不是组件的业务数据快照。现有 Frame 保持数据恢复职责，不能用 style 合并替掉。

代码演示采用构建时 Shiki 高亮、keyed tokens、压缩序列化，运行时仅选择停点。运行时用 cancelTick 让旧 nextTick 失效，重测时排除离场 token，避免过期异步写入和 ghost 干扰几何。

MIT。完整应用依赖 Vue/Router/Vite 等，静态构建生成资源和 SPA 路由辅助文件，不直接保证 file:// 单 HTML。**取目标重算和预编译分工，不为一个能力更换全宿主。**

## 9. Shiki Magic Move：可直接利用的代码变化渲染器

当前实现位于 shikijs/shiki 的 packages/magic-move；旧 shikijs/shiki-magic-move 仓库已归档。不要拿旧包/旧路径当后续维护入口。

[独立 renderer](https://github.com/shikijs/shiki/blob/f7d0167873fd676fe4e190bc9b53832fba9ee01d/packages/magic-move/src/renderer.ts#L155)只有类型导入，包公开 @shikijs/magic-move/renderer，可脱离 Vue 使用。

### 值得逐步移植的完整流程

~~~text
结算上一轮保存的手动句柄
→ key 复用 DOM，测旧坐标
→ 构造完整新 children，分类 move / enter / leave
→ 离开节点保留旧坐标，脱离文档流
→ 一次 replaceChildren
→ 测新坐标，写反向 transform
→ 准备进入、离开、容器尺寸和样式变化
→ 一次强制 reflow
→ 执行 postReflow 回调，启动全部相关变化
→ 此时才 getAnimations，聚合真实 finished
→ 清除离场节点、临时样式与 class
~~~

中途刻意不 await，避免半套 DOM 被其他更新插入。相对 delay 由 duration×ratio+stagger 得到，移动、进入、退出、容器可交叠。

### 能直接用与不能直接用

- **代码前后态：可直接打包独立 renderer。** 高亮和 diff 构建时完成，浏览器只带 keyed token 数据与 renderer。
- **位、字节、通用节点：局部借几何流水线。** 不能把所有对象硬变成代码 span。
- syncTokenKeys 依赖文本 diff，增强匹配按词内容，适合代码；宿主对象的稳定身份仍须显式给。
- 有 Promise，但没有公开 cancel/destroy/AbortSignal。新 render 会结算旧手动句柄，replace 没有完全相同的清理链。
- 手动 resolve 与自然完成清理可能重入；内部大多幂等，不能当成通用“只结算一次”的合同。
- 宿主还要处理减少动效及旧 token 样式缺省时的清除。

MIT。core 依赖 diff-match-patch-es、ohash；renderer 可单独打包，不必带完整高亮器或 Vue。

## 10. Motion Canvas：完整串行之外，已有“错开启动”

[all](https://github.com/motion-canvas/motion-canvas/blob/7b91435c301d530351dcf5ebb91dd139c002e405/packages/core/src/flow/all.ts#L1)同时启动再 join；[chain](https://github.com/motion-canvas/motion-canvas/blob/7b91435c301d530351dcf5ebb91dd139c002e405/packages/core/src/flow/chain.ts#L1)逐任务完整等待；[sequence](https://github.com/motion-canvas/motion-canvas/blob/7b91435c301d530351dcf5ebb91dd139c002e405/packages/core/src/flow/sequence.ts#L1)按间隔启动，前一任务没结束也可开下一任务，最后统一 join。

这给现有 runner 的具体补充是第三种组合能力，而不是继续在串行和全并行之间摇摆。其 sequence 最后一次启动后也等待一个间隔；短任务时可能形成尾部空等，不宜无条件照搬。

[统一逻辑时钟](https://github.com/motion-canvas/motion-canvas/blob/7b91435c301d530351dcf5ebb91dd139c002e405/packages/core/src/flow/scheduling.ts#L48)保留逻辑时间与实际帧时间的余量，避免多个 timeout 的舍入误差叠加。Thread 具有父子归属，父取消会使子任务失效，退出时调用 generator.return 并清理任务。

它确有 beginSlide 手动停点。PlaybackManager 回到旧停点时 reset 场景，再确定性重放到目标，**不同于 Frame 直接恢复**。Node.applyState 为属性生成任务后 all，一次批量恢复，并非逐属性串行。

core/player 是 MIT，ffmpeg 包为 GPLv3；不能把整仓库统称 MIT。当前只参考 core 调度，不引入 FFmpeg。完整接入将引入自己的 Canvas/scene/signal 工程；公开时间线已能满足大部分重叠需求，无须先复制整个 generator 引擎。

## 12. Remotion：帧驱动模型的实质与边界

这是源码可读的完整比较对象，采用自定义 Remotion License，不当成 MIT 类代码直接移植。

[Sequence](https://github.com/remotion-dev/remotion/blob/cadb7d84b4ed887e274b16b0abc1f6f67dc93357/packages/core/src/Sequence.tsx#L1)建立嵌套局部时间域；[useCurrentFrame](https://github.com/remotion-dev/remotion/blob/cadb7d84b4ed887e274b16b0abc1f6f67dc93357/packages/core/src/use-current-frame.ts#L30)按全局帧、上下文偏移与 playback rate 求局部帧。视图由 frame 求出，而非把一串 DOM 操作依次 await。

Series 累加 duration/offset，正偏移可留空，负偏移可重叠；TransitionSeries 将前后场景重叠。seek 到某时刻即可重算画面，适合精确定位与导出。

其价值在于说明另一条可行路线：**完整场景是时间函数**。但当前组件有真实 DOM、命令式实例和业务 Frame，把它们变成 React 帧函数改造范围很大。NoteDemo 为短动画停点并不需要先变视频渲染系统。

### 发现的真实不兼容点

相关 runner.js 的 onAbort 调用 cancelStarted 后，再 waitStarted，等所有 effect.finished 结算；这依赖现有组件“取消也结算”的合同。

Anime Timer、Motion 的部分动画句柄、GSAP kill 的控制路径不满足这个前提。如果原样塞进 Adapter，**现有公共层可能等待一个再也不结算的 Promise，阻住后续导航**。这是源码推得的集成风险，尚未在本地接入复现。

正确方向是：保持现有公共句柄合同，由窄适配器拥有自己的 Promise；底层完成、取消、异常和清理分别接入，最多结算一次。取消先使迟到回调失效，停止底层，按现有导航规则恢复 Frame；不要靠任意 setTimeout 假装已经完成。

另一个差别是异步提交：Motion builder 可等待 updateDom 的 Promise，Anime update 是同步 callback。选引擎前先核对实际 Adapter 更新能否同步提交目标 DOM。
