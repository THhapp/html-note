# 预览与示例

本文件说明组件库的实际入口：完整预览外壳、按 ID 打开的最小宿主、不加载预览壳的组合示例，以及公共编排层的独立示例、自包含离线预览与完整候选包。当前清单为 101 条、17 个分发模块。这些入口都使用普通 `<script>` 与相对路径，可直接 `file://` 双击打开；不需要本地服务、网络、`fetch` 或 ES module。

构建、预览生成、静态核对与打包的命令及产物规则统一见[构建与分发](构建与分发.md)（命令在第 1 节，产物在第 3 节）；本页只说明入口、加载顺序与检查方式，不重复命令清单。

## 2. 完整预览 `gallery/index.html`

### 2.1 清单与状态

- 组件条目、类别、公开名、中文名、用途、输入、可替换项、代表状态、用法、源文件、分发文件、文档、示例、限制、技术状态、核验记录、用户评价、评价范围与共识编号全部来自 `window.NOTE_LIBRARY_REGISTRY.entries`。
- 外壳不维护第二份组件清单。新增组件只需构建时合并 manifest 并提供 demo。
- 顶部构建信息显示条目计数、构建时间以及（若 registry 记录）`expected` / `missing`。构建不完整时显示警告，但只展示真实存在的条目。
- 技术状态与用户评价分开显示：
  - 技术状态：`planned` / `implemented` / `verified` / `blocked`。
  - 用户评价：`not-reviewed` / `positive-with-scope` / `rejected`。
  - `verified` 只表示技术核验，不等于用户认可；新增组件显示“候选 · 未评价”。
- 各条目的“用户评价范围”独立可见；技术状态不扩大评价范围。

### 2.2 查找与切换

- 输入框即时过滤 ID、公开名、中文名和类别；多个空格分隔的词按 AND 匹配。`/` 聚焦检索框，`Esc` 清空。
- 类别 chips 由 registry 动态生成并显示计数；与检索组合使用；无结果显示明确空态和“清除筛选”。
- 默认选中 registry 的第一条。点击列表、上一项/下一项或调用 API 都可以切换。
- 深链使用 hash：`gallery/index.html#L01`。浏览器前进/后退通过 `hashchange` 恢复对应条目。
- 切换条目时先调用上一条 demo 的 `destroy`（或返回的函数），再清空演示宿主；外壳另做一次兜底清理：只移除本次挂载后新增的 `.hnv-floating`、`.hnv-floating__backdrop`、`.nui-toast-region`、`.nui-toast`、`.nx-focus`、`.nx-range`、`.nx-link` 等 body 层，并恢复被临时改写的 `body.style.overflow / paddingRight`。挂载前已存在的节点不动。
- demo 抛错时在详情显示错误并 `console.error`，外壳与列表仍可使用。
- 不自动播放：外壳不会点击 demo 控件、不会自动切换步骤或重放动画；演示内的“重看/重置”由该 demo 负责。需要重新挂载时可点“重载演示”。

### 2.3 详情内容

每个条目默认可见：用途；实际运行区；代表状态；可替换内容与接口参数；最小用法（可复制）；支持范围与限制；维护源码、分发文件、模块文档、独立示例、预览记录，以及技术状态/用户评价范围/核验记录；共识编号收在可选的 `<details>` 中，关键限制不被放进折叠区。

复制按钮调用公开的 `NoteCore.copy`。复制失败时展开只读、可手动选择的文本，不静默失败。`运行独立示例` 与源文件路径均在新标签打开。

### 2.4 自动化审计接口

```js
window.NoteGallery.select(id)  // 同步返回 boolean；成功则挂载该条 demo
window.NoteGallery.current()   // 当前 ID 或 null
window.NoteGallery.list()      // registry 中全部 ID（不是筛选结果）
window.NoteGallery.ready()     // Promise；在当前 demo 挂载后的下一帧后 resolve
```

`select` 与页面的 hash 路由共用同一套切换逻辑；审计接口不是用户功能的前置条件。加载失败、registry 缺失或 demo 缺失时，`ready()` 也会 resolve，不无限等待。

### 2.5 响应式与可访问性

- 宽屏：左侧类别/列表可独立滚动，右侧详情；1440×900 与 1024×768 首屏可读到标题、用途和演示区入口。
- ≤900px：单列，列表在顶部（有独立最大高度），详情在下；390px 无页面横向溢出。宽表或密集图形由组件/演示局部滚动。
- 列表项是真实链接，当前项有 `aria-current`；筛选框有标签；类别 chips 使用 `aria-pressed`；焦点有可见焦点环；空态、复制结果与构建警告有 live/status 语义。
- 减少动效时组件按各自策略直落终态；外壳自身的跳转链接只有可关闭的短过渡，并尊重 `prefers-reduced-motion`。

## 3. 最小宿主 `examples/run.html`

- 地址：`examples/run.html?id=L01`；缺省 `id` 为 `L01`。
- 不加载 `gallery/gallery.js` 或 `gallery/gallery.css`，页面样式独立在 `examples/example.css`。
- 加载全量分发代码、registry 与全部共享 demo 文件；只挂载选中的那个 ID，其余 demo 不执行。共享 demo 不算 gallery 外壳。
- 顶部原生 `<select>` 按类别分组列出 registry 条目；切换时销毁上一个演示，并用 `history.replaceState` 更新 `?id=`（`file://` 限制时保持页内切换）。
- 显示演示、用途、代表状态、可替换内容、用法与复制、限制、源文件/分发文件/文档、技术状态与用户评价范围，并提供返回 gallery 的链接。
- ID 不存在、registry 缺失或 demo 缺失时显示明确说明，不白屏，不伪造组件。
- 复制走 `NoteCore.copy`，失败展开手动文本；演示切换或 `pagehide` 时销毁并做与 gallery 相同的 body 层兜底清理。

## 4. 组合示例 `examples/composed.html`

组合示例不加载 gallery 外壳、`gallery.js/gallery.css` 或 demo 注册脚本。它用与组件浏览不同的示例内容“缓存键替换与校验”，直接调用公开 API：

- NoteUI：Container、Panel、Stack、Inline、Badge、Notice、DataObject、Table、Tabs。
- NoteExpr：Focus、Range、Link，标注页面内真实对象。
- NoteViz：Sequence、Chart（柱状图）。
- NoteBlocks：DemoStage（主舞台与固定字幕）与 RuleCompare（校验规则与就近说明）。

页面上的四个停点由宿主自己的按钮和停点 chips 驱动，不复用 gallery 控件：

1. 收集请求片段，版本仍为 v1。
2. 只替换版本段 v1 → v2，其他片段保持原值。
3. 校验字符集、长度（22 ≤ 64）与版本前缀，三项通过。
4. 按本地静态数据落到 3 号槽，显示命中。

实现要点：

- 每一步使用同一份状态快照更新 Sequence、DataObject、Table、Chart、RuleCompare、状态徽标和 DemoStage 字幕；字幕与图形停点一致。
- 默认静止，没有自动步进、自动播放或定时器；用户点击“下一步/上一步/重看本步/从头开始”或停点才变化。
- “重看本步”会重放当前停点（减少动效时直接落定），不会跳步。
- NoteExpr 的 Range 标签在“保持不变”的片段行下方有独立预留空间；1440/1024/390 宽度下不与正文重叠。切换停点时隐藏不用的 Range/Link，Focus 迁移到当前对象；页签切换后刷新叠加层坐标。
- 标记层是视觉层；相同信息在字幕、DataObject、表格/规则结果与状态徽标中可读。
- `pagehide` 或 `NoteComposed.cleanup()` 会销毁所有实例、隐藏并销毁 NoteExpr 叠加层，并清理残留的 `.hnv-floating`/`.nx-*` body 层。
- 页面提供 `window.NoteComposed = { go, next, prev, replay, reset, current, ready, cleanup }` 供自检使用，不作为用户功能前置。
- 示例数据是本地静态数据；不访问网络，不执行输入内容，不代表真实缓存、哈希或命中率。

组合示例不是完整课程笔记，也不属于 101 项清单之外的组件；它只证明这些组件可以脱离 gallery 外壳实际协作。

## 5. 公共编排层示例与离线预览

### 5.1 scene 开发宿主 `examples/demo-scene/index.html`

- 直载 `src/` 经典脚本（core、expr、viz、demo-runtime、sequence/dom adapters、presentation），不加载 gallery 外壳；页面用独立 section 展示三个 scene 样例。每个 section 只保留标题、画面、字幕和操作；实现说明与自检读数收进默认折叠的“开发自检”，不进入演示阅读路径。
- 默认舞台为字幕预留本会话全部 Frame 在当前宽度下的最高阅读高度，画布在会话内只增长不回缩；三个样例推进前、运行中、停稳后的字幕和按钮位置保持一致。字幕正文左侧显示“字幕”身份标签。
- 宿主用一个浅色画布承载演示对象；画布右侧是本步结果读数（有“结果 · 接收端”标签和独立数值排版），没有结果声明的样例则不画读数。字幕换句时整句有一次轻淡入/上移，取消、回退、重看和减少动效不留下迟到动画。
- `scene-bytes`：线路 D01 用 sequence adapter 的 layout 参与 scene，接收端 dom 用 reveal at objects-settled；前 41 7E 7D 42 → 后 41 7D 5E 7D 5D 42；p1/p2 改值保持身份，e1/e2 插入，目标 Frame 两条 range 括线说明 7E/7D 的转义关系；字幕只讲知识，结果只保留一行接收端字节。
- `scene-other-bytes`：同一接入换一组非 PPP 数据 90 7E 80 41 → 90 7D 5E 7D 80 41，不声明 result，说明 reveal 是可选能力，也不是右侧栏固定的理由。
- `scene-custom`：最小自定义 Adapter 声明 `sceneModes ['cut','reveal']`，沿用 restore 作为同步提交；一步内一个容器 cut、另一个 reveal，验证扩展契约无需改核心；两个面板标题为“说明/结论”。
- 默认静止；场景代码在 `examples/demo-scene/scenarios.js`，开发页与单文件预览共用。
- 单文件预览模板是 `examples/demo-scene/standalone.html`，生成 `dist/公共编排层-整合预览.html`；命令与生成规则见[构建与分发](构建与分发.md)。

### 5.2 作者装配与聚焦 `examples/authoring/index.html`

- 普通作者入口：页面只加载 `dist/note-library.css|js`、`data.js`、`boot.js`，不列维护源脚本；开发页与 `dist/作者装配与聚焦-预览.html` 由同一个模板内联生成。
- 两个 section 共用 `NoteDemoRecipes.focusWorkbench`：矩阵乘法用两个稳定来源板和过程区；逐项读数用单行 sequence、当前读数和结果，结构不同但 recipe 相同。
- 矩阵的注意顺序由数据声明：A 当前单元 → B 当前单元 → 当前乘积项 → 最终累计 → 结果；默认舞台只迁移一个连续 Focus 框，不再让 A/B 两个单元同时叠直接关注，也不新增“关注”标签。矩阵行列、已完成项和结果保持稳定参照；最终和为 `4 + 1 + 12 = 17`，结果 `17`。
- 减少动效时焦点不迁移、不增加等待；回退/重看/重来/中途取消与普通 scene 共用清理。内容数据、视图、scene 参与者、after 与注意顺序仍由作者给出，配方只负责区域骨架、slot 收集和 layout.cleanup。
- 单文件预览由 `examples/authoring/index.html` 作为模板生成到 `dist/作者装配与聚焦-预览.html`；命令见[构建与分发](构建与分发.md)。

### 5.3 公共层复用验证：矩阵乘法 C₁₂ `examples/reuse-matrix-product/index.html`

- 一个不同结构的独立入口：只计算 A(2×3) × B(3×2) 的 C₁₂，展示 A 第 1 行与 B 第 2 列的配对、三项乘积、逐项累计和最终 C₁₂ = 17。
- 内容入口是 `content.js`：矩阵数据、配对、字幕和 Frame/Transition 定义；`host.js` 只负责画布槽位与 NoteDemo.mount；`reuse.css` 是宿主排版。没有新播放器、计时器或另一套运行语义。
- 矩阵使用 matrix Adapter 的 scene `update`（默认模式）：当前配对单元的关注从旧单元过渡到新单元，行列持续参照不重播；Matrix 元状态文字在 NoteDemo 新挂载下默认关闭，当前配对只靠视觉轮廓/底色和可访问描述；乘积项使用 D01 sequence 的固定三项和既有值替换；累计和使用 NoteUI.Expression 的稳定项 id，f2 从 4 扩展为 4 + 1 = 5，f4 再加入 + 12 并更新 total；C₁₂ 结果使用 dom reveal。
- scene 只保留 terms → sum → result 的真实内容承接：matrixA/matrixB 与 terms 同窗，sum 等 terms 内容可辨，result 等 sum；相对不变的累计和在重复边上不再列入 reveal，也不再让整段矩阵 cue 阻塞乘积。
- 自包含预览模板为 `examples/reuse-matrix-product/standalone.html`，输出 `dist/公共层复用验证-矩阵乘法.html`；此页保留上一版公共承接的旧对照，不再是作者聚焦入口。

### 5.4 旧 actions 独立宿主 `examples/demo-runtime/index.html`

- 加载 `dist/note-library.css|js`，不加载 gallery 外壳；页面用场景切换展示公共编排层旧 actions 路径。
- 场景（每个容器带 `data-demo-scenario` 与 `data-demo-readout`）：
  - `matrix`：静态矩阵 + DOM 文本，直接恢复、跳转、字幕与单元标记；
  - `sequence-edit`：M01 删除/交换，真实过渡、真实字幕，可在动作中打断；
  - `sequence-insert`：R10 插入/还原，逻辑引用在重建 DOM 后仍能标记；
  - `linked`：同一步中 sequence-edit 与自定义 Adapter 两类 Binding 配合，全部走 NoteDemo 公共层；
  - `custom`：最小自定义 Adapter 的完整用法。
- 默认静止：加载后不自动调用 `next`，不使用 `setInterval` 自动播放；由默认舞台按钮推进。
- 场景代码集中在 `examples/demo-runtime/scenarios.js`，独立页与单文件预览共用同一份。

### 5.5 自包含离线预览

单文件预览由 `scripts/build-demo-preview.mjs` 生成：默认读取 `examples/demo-scene/standalone.html`，把本地 stylesheet/script 引用内联为单文件，输出到 `dist/公共编排层-整合预览.html`；支持显式模板与输出参数。构建脚本会检查无残留 `<script src>`、无 stylesheet link、无外部 URL、CSS 无本地/外部 `url()`。生成的页面可以复制到任意位置直接 `file://` 打开。旧的 `examples/demo-runtime/standalone.html` 仍可用显式参数生成独立预览。命令与参数见[构建与分发](构建与分发.md)。

### 5.6 完整候选包

`scripts/package.ps1` 从现行工程生成 ZIP：包含运行资源、源码、必要用法、示例与许可；默认输出 `dist/公共编排层-整合候选.zip`。排除 node_modules、浏览器 profile/cache、缓存、临时日志、`tests/.cache` 与测试夹具截图。清单与排除规则见[构建与分发](构建与分发.md)与脚本本身。

## 6. 新增组件演示的接入契约

各模块负责人只需提供 `gallery/demos/<module>.js`（公共编排层的 I07 demo 为 `gallery/demos/demo-runtime.js`）：

```js
(function () {
  'use strict';
  var demo = window.NoteGalleryDemos = window.NoteGalleryDemos || {};
  demo['L01'] = function (host) {
    // 只调用公开 API，向 host 追加演示与控制。
    // 默认静止；提供换内容/状态与重看/重置入口。
    // 覆盖与本项相关的代表状态，不机械填满状态矩阵。
    return { destroy: function () { /* 释放计时器、动画、浮层 */ } };
  };
})();
```

要求：

- 真实挂载组件，不用静态截图或“看着像”的另写 DOM。
- 对宿主传入的 `host` 追加内容，不清空其它节点。
- 至少一个控件可换数据或状态；演示内说明默认可读。
- `destroy` 清理自己创建的监听、定时器、动画、body 浮层并幂等。
- 不自动串播；动效由用户操作触发。

外壳不把 demo 当作组件源码的替代品；组件源码与分发代码仍由构建从 `src/` 生成。

## 7. 离线与文件依赖

- 所有运行依赖均为本地相对路径；没有 CDN、网络字体、运行时构建服务、`fetch` JSON 或动态 import。
- `gallery/index.html`、`examples/run.html` 与 4 个直载页按固定顺序加载脚本，避免 ES module 在 `file://` 下的限制。
- 分发代码的来源、版本、第三方许可与模块拆分见[构建与分发](构建与分发.md)与 `THIRD_PARTY_NOTICES.md`。

## 8. 自检与已知限制

### 8.1 检查入口

- 静态核对：`node scripts/check.mjs`（文件、依赖顺序、离线性、registry 一致性、文档锚点）；`node tests/checks/source-loaders-check.mjs`（纯静态，检查 examples 与 tests 的 HTML 夹具是否按 manifest 顺序加载了必要的 `src/` 脚本、是否引用已不存在的源文件）。模块拆分后先跑 source-loaders-check，再跑依赖浏览器的检查。
- 浏览器检查：`node tests/demo/core-check.mjs`、`node tests/demo/adapters-check.mjs`、`node tests/demo/ui-check.mjs`、`node tests/demo/integration-check.mjs` 与 `node tests/checks/public-transition-check.mjs`；它们直接加载 `src/` 经典脚本，源码清单由 manifest 推导。
- 补充核验：`tests/checks` 下的单模块脚本与 `tests/checks/audit.mjs` 可按受影响模块或页面单独运行；它们与构建产物无关，失败不代表离线包不可用，但应在对应模块改动后重跑。
- 生成物规则：截图、结果 JSON、日志与临时构建副本统一写入 `tests/.cache`（打包排除）；`tests/checks` 只保留脚本与输入夹具。实际验收记录应写真实命令、构建状态、Edge 版本/视口与未跑项；部分构建的检查结果不等同全库通过。

### 8.2 已知限制

- 未覆盖：Firefox/Safari、触屏手势、屏幕阅读器实测、打印输出、RTL。旧 NoteExpr 的 body 叠加层仍不保证跟随 transform 祖先、iframe 或嵌套滚动容器。
- 浏览器只测试本机 Edge（Chromium）；`file://` 下若浏览器限制历史或剪贴板，页面提供页内切换与手动复制回退。
- 单文件预览会把静态非页内链接中和为页内 `#`；运行时构造的本地路径（如文档/源码下载链接）在单文件中可能失效。构建与预览不内联运行时 `fetch`、ES module 或局部 `@import`。
