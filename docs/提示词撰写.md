# HTML 笔记制作提示词

本页用于把知识需求交给制作 Agent：MD 侧保留简要意图，执行提示词补齐本次上下文，组件库提供现行实现与用法。按本次任务组合必要内容，不把历史提示词逐轮叠加成一份越来越长的指令。

阅读与视觉原则统一维护在[设计共识](设计共识.md)，实际入口见[取用与组合](取用与组合.md)，运行接口见[公共编排层](公共编排层.md)。本页负责提示词组织和可复制底稿，不另维护一份组件 API 或动画参数表。

## 1. 哪些内容写在哪里

| 内容 | 放置与职责 |
| --- | --- |
| MD 侧演示预留 | 说明对应位置、要解释的问题、对象或过程、希望读者理解什么；已有展示意图与简化边界可直接保留 |
| 本次执行提示词 | 明确演示主题、源材料位置、库入口、输出范围、交付形式及本次授权；附必要的知识或试用要求 |
| 稳定设计原则 | 引用设计共识；提示词保留当前制作最重要的要求，不全文复制讨论和历次整改 |
| 接口与实现说明 | 按采用的组件查现行文档、registry 和可运行示例，不要求用户编写 Binding、Frame 或动画配置 |

这是输入内容的分工，不要求创建额外的规格、配置或状态文件。已有 Vxx 预留足以交代目标时直接采用，只补会影响理解或执行的缺项。

例如，“用分段长度条和两层括号区分数据字段与整帧，并允许改变数据长度观察填充”已经给出对象、关系和观察目标；制作 Agent 负责核对知识、选择组件与完成装配。只写“做得好看一些”则缺少可判断的表达目标。

## 2. 每次撰写先核对的内容

1. **范围与知识。** 确定本次解释的问题、必要前提和最终应能理解的关系；需要使用的数据、规则、单位、适用条件和简化不能含糊。HTML 在该范围内独立可读，MD 继续保留完整知识组织。
2. **任务上下文。** 填实源文件、对应标题或预留、库入口、制作位置、允许改动范围和交付形式。这些通常由派发任务的一方补齐，不转成用户必须逐项填写的技术表格。
3. **表达与取用。** 按内容选择静态图解、参数联动或可控步骤。现有组件优先按适配性复用，需要时允许局部宿主绘制；多停点协调使用公共层，不让所有内容迁就同一种配方。
4. **验证与结束。** 根据实际采用的知识模型、操作和风险选择必要检查，明确实际交付。局部修改复核影响范围，不默认追加精密测量、批量截图或全库回归。

演示主题单独成节，与执行范围、表达要求等处于同级，不藏在路径清单的一条简短备注里。可以直接粘贴现有 MD 预留，不必先把自然语言转换成接口配置。

## 3. 通用制作底稿

派发时将占位项替换为实际内容，删除无关条款。需要的知识纠错、试用目标或特殊权限并入对应位置，不在末尾不断追加补丁。

```text
你负责制作指定知识的 HTML 可视化。以本次内容和操作范围为准，交付可阅读、可回顾的成果。

一、本次演示主题

<粘贴对应 MD 预留或简要需求：要解释的问题、表达对象或过程、理解目标及必要边界。已有明确的展示意图一并保留。>

二、执行上下文与范围

- 源 MD：<实际文件路径>
- 对应位置：<标题、预留编号或明确范围>
- 组件库：<实际可用目录>
- 制作与输出位置：<实际目录和必要文件名>
- 允许改动范围：<源 MD、参考资料、组件库和输出目录分别怎样处理>
- 交付形式：<例如独立离线 HTML，并保留必要作者源文件和重新生成方式>
- 本次专属要求：<仅在需要时填写，例如固定参数的阶段试用、明确要覆盖的公共能力、或与既有作品比较的范围>

先理解本次材料中相关内容，补读必要上下文。核对知识、单位、规则和适用条件；示意、省略和比例简化清楚说明。开始观看所需的对象与记号应容易识别，无须复制整章 MD。

三、表达与阅读要求

沿用组件库的 docs/设计共识.md，优先保证：

- 演示是视觉中心。简短前提、主要图解和回顾说明沿自然阅读路径组织；当前理解所需信息集中，减少来回寻找。
- 步骤演示的解说紧贴画面下方并保持稳定。同一理解停点内不按计时连续替换多句，换句有轻提示；读者可先看图再读说明，也可反过来。对象名称、数值、单位与必要短标注紧贴图形，结果读数与状态记录集中呈现，本步变化及意义由字幕讲清；字段组成、推导等扩展内容放在正常知识正文。先确定本步理解目标和主要阅读顺序，避免同一解释分散到路径、帧下、记录和字幕多处。
- 步进按有独立理解价值的稳定状态划分，一次推进可包含多个配合动作。完成后停住，保留必要依据和结果；提供与实际过程相适应的回退或重看能力。类 PPT 描述的是演示区，不要求整页幻灯片化。接受步进后执行态立即清楚可见，运行中阻止重复推进，必要变化收束后恢复。
- 图形表达操作与关系，前后对象可追踪。当前关注与本步变化形成主次，相关变化可以配合，独立区域避免同时争抢注意；不是每次更新都需要额外高亮或焦点框。
- 使用公共聚焦时，正常连续推进承接上一停点的观察位置；必要依据看清后再落到变化部分，内容与焦点按公共机制交接。字幕换句不要求焦点巡视；回退、重看和重来可按对应步骤初态重新开始。
- 读数按语义更新：阶段、模式、目标参数可以随目标提交；"已收到/已发出/已完成"等事实必须随领域事件或实际展示进度更新；预期值可以提前显示，但名称要明确是目标/预期。是否需要 Focus 巡视与何时更新分别判断，不强制所有计数分组、动画或逐处巡视。
- 过程中的重要变化来得及辨认，停稳后仍能理解。用合理承接、缓动和必要强调组织节奏，不以统一加速、统一放慢或末尾空等代替判断。
- 画面、解说和基本控制便于一起查看，推进不推挤操作区。必要文字正常可读，不藏在角落小字、悬停或必须展开的区域；也不为塞入窗口把图缩到看不清。
- 用对齐、留白、比例和视觉层级形成完成度。提示含义在本篇内自洽，具体图形随知识适配；不固定所有作品的步骤数、句数、颜色、时长或页面比例。

组织文字前先确定本步的理解目标和主要阅读顺序，不要求页面固定设置四个区域。对象名称、数值、单位和必要短标注紧贴对应图形；结果读数与状态记录集中呈现；本步发生什么、为什么变化主要由稳定字幕解释；字段组成、推导等扩展内容放在正常知识正文。图内必要注释可以保留，不规定统一句数、字数、标注数量或页面比例。布局后检查：是否需要在多个位置拼接本步解释，是否重复讲述同一道理，当前必要条件是否仍能直接看到，移入正文的内容是否确实不影响本步理解。不要用缩小字号、角落小字、悬停或折叠隐藏解决解释拥挤。

静态图解和参数联动按各自观察目标组织，不为凑齐步骤、字幕、控制或焦点而增加无意义结构。交互默认服务于观察、推进和回顾，不自行增加测验、评分或闯关内容。

四、实现与取用

如果已有有效上下文，直接沿用；缺什么再补读什么。定位实际库目录后，已知能力用查询 CLI 的 show 取当前接法，未知能力先 search；需要了解资料范围时用 info，完整参数与示例沿 read 继续读取。资料不足或存在具体疑点时，再查取用文档、API 或源码，不要求先通读组件目录和公共层手册。

复用公共组件、布局和运行能力，并按本次内容编写必要宿主图形。调用真实接口，不凭名称猜参数或强行把不适配的组件当作另一种图形。

需要多停点、回退和动作协调时使用现有 NoteDemo，内容、对象身份、必要因果与注意顺序由作者明确表达。使用 attention 等能力前核对当前接口和边界；不复制另一套播放器或用硬编码等待模拟公共完成机制。

领域模型决定知识状态与计算。注意编排和视觉过渡不改变模型中的时间、因果或并行关系。无合适组件时，在本次允许范围内做必要的局部实现，并说明真实缺口，不静默省略重要表达或擅自扩大共享库开发。

五、必要核对与交付

核对知识模型和代表状态，以实际速度观察需要动态理解的过程，并检查实际采用的关键操作。对具体疑点再补针对性探针，局部修改后只复核相关影响。

确认最终交付文件能在约定方式下打开、必要资源完整、关键操作正常。离线交付使用随成果提供或内嵌的资源；有动效时，减少动效仍应呈现正确且可理解的状态。

不默认做逐对象像素断言、全数值遍历、全视口截图或组件库完整回归。共享实现有改动时按实际影响扩大验证；必要检查通过后交付。

回复链接实际成果，简述表达方式、实际复用、组装摩擦、验证方法与剩余限制。区分程序检查、实际观察与用户评价，不用静态终态截图冒充动态观看，也不另建报告、状态文档或测试流水。
```

## 4. 按任务需要补充的条款

只加入本次需要的部分；具体参数、知识内容与权限并入底稿相应章节。

| 情况 | 应补充什么 |
| --- | --- |
| 新 Agent 冷启动 | 交代当前工程位置、有效入口、已有成果和本次范围；旧任务不自动成为新授权 |
| 复用同一制作 Agent | 说明新任务与上一作品的关系、保留哪些成果、输出到哪里；不强制重新通读同一批文档 |
| 参数联动 | 指出可改变的量、需观察的关系和领域范围；数值、说明与图形读取一致状态，连续操作不积累迟到变化 |
| 过程或规则演示 | 指出关键事件、触发条件与理解目标，让作者划分有意义的停点；不把示例时刻数量规定为固定点击数 |
| 明确测试公共聚焦 | 写清要验证实际到达、内容启动、可承接后交接及最终收束；单独画一个框不等同于覆盖公共协调；接口细节查当前 API |
| 局部调整已有作品 | 给出具体问题与需保持的行为，修改和复核围绕影响范围，不重新设计整页或重复整套验证 |
| 限定权限或特殊试验 | 写明对象、动作、适用阶段和结束条件，避免被后续任务机械继承 |

已有演示可供参考时，说明需要借鉴的具体表达或接口。参考某个局部不代表整页布局、主题、数据与时长全部适用。

## 5. 维护分寸

新反馈先判断影响范围：属于知识模型、某个作品、组件接口、公共运行还是通用阅读原则。修改对应维护位置，不把每次故障都追加为所有提示词的固定禁令。

更新本页时保持一份现行底稿。当前接口只链接 API，设计原则只链接共识；确有差异时同步修正主要说明，避免多个文档分别维护同一套数值与契约。本页不决定制作任务的固定文件结构、样式或控制器。

## 6. Skill 与制作资料的分工

[html-note-authoring](../skills/html-note-authoring/SKILL.md) 承接本页通用底稿和设计共识中的有效文字，不能只剩“查询组件—编写代码—测试”的工具流程。本页继续作为制作要求的维护源。

| 内容 | 放置方式 | 当前维护来源 |
| --- | --- | --- |
| 任务触发、按任务分流、查询时机及结束条件 | `SKILL.md` 主体，连接 `scripts/query.mjs` 的实际 `info/search/show/read` | 本页任务核对与取用要求、取用与组合 |
| 最重要的阅读和演示共识 | `SKILL.md` 中保留简明而完整的要求，指导实现时持续适用 | 本页“表达与阅读要求”、设计共识 |
| 完整制作底稿和按任务补充条款 | 作为 Skill 的参考正文，按任务读取；不能只提供一个脱离使用说明的链接 | 本页通用底稿与补充条款 |
| 各组件及公共层的 API、示例 | 通过 CLI 或文档入口按需取得 | 现行模块文档、公共编排层、源清单及代码 |
| 某次任务的源文件、演示主题、输出位置及权限 | 保留在本次任务中，不固化进通用 Skill | 本次请求与 MD 预留 |

需要保留的共识包括：HTML 在有边界的问题内独立可读；演示为视觉中心；字幕贴近画面下方且位置稳定；有意义的停点与读者推进；对象身份、当前关注和本步变化可分辨；连续推进承接视线；必要信息不藏在角落；节奏服务理解；非硬性尺寸、步数和时长不冻结；验证按实际问题收口。它们是制作要求，不因一次查询未返回相关资料就失效。

工程内使用可直接引用同仓现行正文，并在 `SKILL.md` 中保留关键要求；若将 Skill 独立分发，所依赖的参考正文应随包提供并可追溯到本页，避免安装后只剩不可访问的路径。分发副本从现行维护源整理，接口和共识不各自另写一份独立手册。

新任务不强制重读全部参考；已有有效上下文继续使用。查询 CLI 已可用：`node scripts/query.mjs info` 看库与资料范围，`search <用途/名称>` 找候选，`show <ID/名称>` 取开工包，`read <条目> api|source|demo` 深入；实际命令见[查询 CLI](查询CLI.md)。[查询语料](查询语料.md#corpus-usage)是 CLI 的检索元数据，不是另一套 API。`scripts/query.mjs` 只定位库并转调入口；`scripts/sync-references.mjs` 从本页及设计共识同步参考正文，避免手工维护多份要求。


## 7. 验证与观察

验证范围由本次任务和实际风险决定，不默认遍历全部停点、全部视口或跑整库浏览器矩阵。先核对知识与代表状态，再在实际速度下观察需要动态理解的过程；只有具体疑点才加探针。

### 何时只检查状态，何时必须真实推进

- 静态交付、只改文案或布局且没有动画/焦点变化时，检查页面能打开、目标状态正确、没有页面错误即可。
- 要证明动画、焦点到达、内容放行、取消恢复或连续承接时，必须通过 `next()`/`replay()` 真实推进并观察过程。`go()` 只是直接恢复停点，不能用来证明动画或 attention 正确。
- 静态终态截图不能冒充动态观看；时序疑点用页面内采样（phase、progress、可见值、焦点/组启动先后）而不是反复截静态图。
- 验证完成只说明已观察的范围；不把“打开成功”“没有报错”自动写成作品验收通过，也不代替用户评价。

### 本地观察入口

工程提供 `scripts/inspect-note.mjs`：一次调用、执行后退出、无常驻服务；默认无头打开给定本地 HTML，收集页面错误、控制台错误和外部请求，按需截图或执行作品专属 probe，并在正常结束或失败时释放自己创建的浏览器资源。

```powershell
node scripts/inspect-note.mjs "D:/path/to/成品.html" --json
node scripts/inspect-note.mjs "D:/path/to/成品.html" --screenshot "D:/path/out.png" --width 860 --height 1000
node scripts/inspect-note.mjs "D:/path/to/成品.html" --probe "D:/path/probe.mjs" --json
node scripts/inspect-note.mjs "D:/path/to/成品.html" --frame <frameId> --session "window.__inspectSession" --json
```

- `--frame <frameId>` 用公开 `session.go(frameId)` 恢复停点并确认实际落点后才执行截图/probe；未知 Frame、空参数或会话缺失会明确失败，不退回初始态冒充定位成功。它只证明静态停点，动画/焦点/组放行仍用 `next()/replay()`。

- probe 导出 `default async ({ page }) => ...`，复用同一个已打开页面；需要连续推进、采样或读取 DOM 时都在 probe 内完成，不另起浏览器。
- `--help` 是实现参数的最终事实来源；默认不生成截图、报告或日志，输出文件只在调用方明确指定时写出。
- 输出区分工具执行事实、页面观察事实和 probe 结果；不要把三者合成一个“通过”。
- 这里要区分“浏览器组件模块依赖”和“Node 工具运行条件”：页面需要 dist 模块或整库；观察工具需要工程现有 `playwright-core` 与本机浏览器，不自动安装、下载或轮换通道。
- 公共 scene 在提交前统一接管参与的 Binding 容器，暂停受控内容原有的 CSS transition；作者不另写 `setSceneActive` 或示例私有暂停层。要证明接管有效，可在最小输入上注入一条 CSS transition，检查提交帧的真实计算透明度而不是只看 data 属性。
- probe 期间新产生的页面/控制台错误必须在 probe 结束后重新汇总；probe 失败时也要保留已经收集的观察事实。
- 恢复/取消的接管不能只检查状态字段：恢复写入后先确认受控状态下的真实计算样式已经落位，再释放；用带 CSS transition 的最小元素检查 `go()` 不会留下 CSSTransition。

### Skill 中的收口

制作时按需查询现行 API 和最小示例，不复制完整接口手册。已有有效上下文继续使用；局部修改只复核影响范围。回复时链接实际成果，说明真实复用、实际观察、剩余限制与未完成项，不另建按轮次维护的报告、状态副本或批量测试材料。
