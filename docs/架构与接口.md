# 架构与接口

当前 note 根目录是单一组件库项目：组件、公共运行层和工具都在 `src`；历史候选组和旧笔记在 `archive`，不参与构建。本文件说明源码布局、分层职责、数据流与公开接口边界；具体参数在模块 API 文档中维护。

## 维护源与生成物

| 范围 | 维护位置 | 产物或消费方 |
| --- | --- | --- |
| 共享基础 | `src/core` | `NoteCore`；全部模块先加载 |
| UI 与基础控件 | `src/ui` | `NoteUI.*` |
| 对象与范围标记 | `src/expr` | `NoteExpr.Focus / Range / Link` |
| 图形、变化机制、图表 | `src/viz` | `NoteViz.*`、`SeqInsert` |
| 组合块 | `src/blocks` | `NoteBlocks.*` |
| 公共演示编排 | `src/demo` | `NoteDemo.create / mount`（demo-runtime、demo-ui） |
| 能力元数据 | `src/manifests` | 用途、接口、依赖、适用范围与预览内容 |
| 技术核验状态 | `src/status.json` | registry；构建不自行推断已验证或已认可 |
| 本地第三方资源 | `vendor` 与许可 | 内容渲染、图标 |
| 展示与独立用法 | `gallery`、`examples` | 多文件浏览页与单文件预览 |
| 运行产物 | `dist` | 笔记宿主按模块或整库加载 |

## 模块与内部拆分

当前 20 个分发模块，加载顺序与依赖以[构建与分发](构建与分发.md)为准：

```text
core → legacy → ui-layout → ui-content → ui-actions → ui-navigation →
ui-forms-basic → ui-forms-advanced → ui-overlay → ui-feedback → ui-extended →
viz-objects → viz-flow → viz-mechanisms → viz-chart →
blocks-base → demo-stage → blocks → demo-runtime → demo-ui
```

模块内部的源码拆分不增加模块数，但加载顺序必须按 manifest：

- `ui-content`：`content.js|css` → `table.js|css`（C06）→ `expression.js|css`（C13）。
- `ui-forms-advanced`：`forms-advanced-internal.js` → `slider.js|css`（F10）→ `forms-advanced.js` → `forms-advanced-pickers.js` → `forms-advanced-inputs.js`。
- `viz-flow`：`flow-core.js`（公共 helper 与 Propagation）→ `flow-stage.js` → `flow-packet.js` → `flow-segment.js` → `flow-device.js` → `flow.js` 入口。
- `blocks-base`（`shared.js`，内部 helper）→ `demo-stage`（B01）→ `blocks`（B02–B10）；`demo-ui` 只依赖 `demo-stage`、`demo-runtime` 及其传递依赖，不再带入完整 `blocks`。

模块内文件顺序、CSS 顺序与 demo 归属均由 `src/manifests/*.json` 声明；文档和测试不另维护源码总表。

`scripts/build.mjs` 读取上述源文件，按 manifest 声明顺序生成运行包、根 `registry.json` 与内嵌预览；`scripts/check.mjs` 核对文件、顺序与静态一致性；`scripts/package.ps1` 负责整理打包。模块内文件的真实清单与顺序以对应 manifest 为唯一依据，文档和测试不再各自维护一份源码列表。

## 分层与数据流

```text
manifest / status / vendor
        │
        ▼
src/core → src/ui, src/expr, src/viz, src/blocks ──► NoteUI / NoteExpr / NoteViz / NoteBlocks
        └──────────────► src/demo ──► NoteDemo.create / mount
                              │
             definition（校验/冻结/比较） → controller（会话/运行/取消）
                              ├─► runner（旧 actions/parallel）
                              └─► scene（同步目标事务/after/attention）
                                        │
                                   Adapter + 组件
                                        │
                              presentation（默认舞台/字幕/标记）
```

- Definition 只保存可恢复的数据与提示；运行层不修改传入的 definition。
- Controller 持有唯一运行、取消与错误恢复；旧运行的回调不能提交新状态。
- Runner 与 Scene 是两条过渡路径：前者执行组件命令，后者在同步事务中提交完整目标并受控呈现。两条路径共用取消、读回核对和完成边界。
- Adapter 负责组件接入（视图规范化、挂载/借用、动作、目标查询、scene 准备与效果、真实读回），不拥有另一套会话状态；自定义图形可用 `PreparedChange.groups()` 把局部效果归组，由 attention 观察目标分别放行。
- Presentation 只负责默认舞台、字幕、控件、标记与 settle；自备 slots 的宿主可使用 `NoteDemo.create` 而不加载默认舞台。
- `src/demo/effects.js` 等内部工具集中 WAAPI 句柄、源视觉保持、局部副本与数值进度；其中 `captureContent`/`createGhost`/`planValueSwap`/`captureStyles`/`planCueChanges`/`rectOf` 经 `NoteDemo.effects` 窄包装给作者，其余仍属私有实现。

## 公开接口

- 动态组件通常用 `mount(host, options)`，返回 `{ el, update, destroy, ... }`；值型按实际 API 提供 `getValue`，图形按需提供 `getTarget`。
- 公共编排层用 `NoteDemo.create({ definition, slots, adapters })` 或默认舞台 `NoteDemo.mount(host, { definition, layout, adapters })`；会话提供 `next/prev/go/replay/replayPreviousStep/reset/getState/subscribe/destroy`，Frame 只保存数据与提示，组件实例常驻。默认舞台“上一步”按 `replayPreviousStep` 从上一停点入边初态重播，`prev()` 仍是直接恢复。详见[公共编排层](公共编排层.md)。
- 静态排版/布局可以直接使用语义 HTML 与作用域类，不强制全部由 JS 创建。
- `NoteExpr` 使用 mount 后的 show/hide/refresh/destroy；`SeqInsert` 保留 insert/restore/replay/setData，选项为 `keepState`。
- 字符串默认作为文本；可传 DOM 时，以对应文档约定的迁入/清理规则为准。
- `destroy` 只清理组件自己拥有的资源；宿主传入的实例由宿主负责生命周期。
- 完整快照重绘（B02 StepPlayer）和常驻动作机制是两种组织方式，选择与边界见[取用与组合](取用与组合.md#优先选合适的入口)。

公共编排层通过 Adapter 复用既有组件，不复制组件实现，也不要求旧页面改写；原公开 `NoteUI`、`NoteViz`、`NoteBlocks`、`NoteExpr`、`SeqInsert` 接口保持。

## 测试与分发边界

工程检查在 `tests`：公共层行为检查使用本机 Edge 与 `tests/tools` 中已有的 playwright-core；源码/构建静态核对在 `tests/checks`；可复现消费测试在 `tests/consumer`。具体入口与运行方式以[构建与分发](构建与分发.md)和测试目录说明为准。

分发保留实际运行资源与许可。单文件预览不代表源码包，按模块分发也不等于逐组件自动裁剪；目录、能力计数和用户评价各自维护，不用变体、预览或归档增加组件数量。
