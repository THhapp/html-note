# 公共编排层 NoteDemo

公共演示编排层用于在浏览器端把「停点、动作、字幕、标记、操作控件」组织成一次可复用的演示。组件实例在会话期间常驻，Frame 是可恢复的结果，Transition 是可选过渡；成品运行不需要 Agent、模型或任何服务。

- 公开入口：`NoteDemo.create`（核心，自备插槽）与 `NoteDemo.mount`（可选默认舞台 B01）。
- 分发模块：`demo-runtime`（核心与内置 Adapter，硬依赖 core）与 `demo-ui`（默认舞台与呈现，依赖 demo-runtime 以及现有 blocks 及其传递依赖）。
- 新增条目：I07 NoteDemo（单一公共能力；六个内置 Adapter、子模块、示例与预览不重复计数）。

本文件说明实际可用的 API、可运行用法、依赖、受控状态、取消语义和已知限制。设计理由、执行契约与边界见[公共过渡能力设计](公共过渡能力设计.md)，组装入口见[取用与组合](取用与组合.md)。

## 1. 加载方式

### 整库

```html
<link rel="stylesheet" href="./dist/note-library.css">
<script src="./dist/note-library.js"></script>
```

整库中已按确定顺序装入 core、legacy、ui-*、viz-*、blocks、demo-runtime、demo-ui，因此 `NoteDemo.create` 与 `NoteDemo.mount` 都可用。

### 按模块

```html
<link rel="stylesheet" href="./dist/modules/core.css">
<script src="./dist/modules/core.js"></script>
<link rel="stylesheet" href="./dist/modules/legacy.css">
<script src="./dist/modules/legacy.js"></script>
<link rel="stylesheet" href="./dist/modules/ui-layout.css">
<script src="./dist/modules/ui-layout.js"></script>
<script src="./dist/modules/demo-runtime.js"></script>
<!-- 需要默认舞台时再加载：demo-ui 与它依赖的 blocks 及其传递依赖 -->
<link rel="stylesheet" href="./dist/modules/blocks.css">
<script src="./dist/modules/blocks.js"></script>
<link rel="stylesheet" href="./dist/modules/demo-ui.css">
<script src="./dist/modules/demo-ui.js"></script>
```

- `demo-runtime` 文件顶层不要求所有可选组件存在：Adapter 只在真正 mount/adopt 时核对对应组件是否已加载，缺失时抛出带定位的错误。
- `demo-ui` 依赖现有 blocks 模块（B01 DemoStage）及其传递依赖；旧 blocks 不按组件拆成多个入口，也不复制第二份 B01，因此 UI 入口仍较粗，这是明示限制。
- 只用核心的宿主可以只加载 `core`、`legacy`、`demo-runtime` 与所选组件，自备 slots；不需要默认舞台。

## 2. Definition 形状

```js
var definition = {
  initialFrameId: 'start',              // 可省略，缺省为首 Frame
  bindings: {
    seq: {
      adapter: 'sequence-edit',         // 必填：内置名称或 adapters 映射里的自定义名称
      slot: 'main',                     // 必填：宿主提供的插槽名
      options: { label: '示意序列' },    // 可选：稳定配置（标签、dense、固定序列数据等）
      // instance: component, ownership: 'borrowed'   // 可选：借用外部实例
    },
    note: { adapter: 'dom', slot: 'note' }
  },
  frames: [
    {
      id: 'start',
      caption: '先看初始序列。',
      views: {
        seq: { items: [{ id: 'a', label: 'A' }, { id: 'b', label: 'B' }], focus: [], changed: [] },
        note: { text: '初始说明。' }
      },
      marks: []
    },
    {
      id: 'removed',
      caption: '删除 B，后面的对象前移，结果保留。',
      views: {
        seq: { items: [{ id: 'a', label: 'A' }], focus: ['a'], changed: ['a'] },
        note: { text: '现在只剩 A。' }
      },
      marks: [{ kind: 'focus', target: { binding: 'seq', query: { id: 'a' } }, mode: 'box' }]
    }
  ],
  transitions: [
    {
      from: 'start',
      to: 'removed',
      actions: [{ binding: 'seq', type: 'remove', params: { id: 'b' } }],
      marks: [] // 可选；仅在本次过渡期间显示
    }
  ]
};
```

规则：

- Frame ID、Binding ID、逻辑对象 ID 非空且稳定。frames 为有序线性停点；Transition 只能连接相邻前进 Frame，同一 from/to 不重复。
- 每个 Frame 的 `views` 必须覆盖定义中全部 Binding，不从前一 Frame 隐式继承字段；未知 Binding 报错。缺省数组表示清空，不表示保留旧值。
- Frame 只保存数据与提示，不保存 Element、函数、像素坐标、Promise 或组件私有撤销历史。运行层不会修改传入的 definition 数据。
- `actions` 按序执行；支持显式 `{ parallel: [action, ...] }` 组合，同一 parallel 组不能重复写同一个 Binding。当前按 Binding 保守判冲突；同一对象的复杂并行动作应由一个机制动作内部完成。
- 不固定动作数或时长；一个停点可以包含几个配合的小动作。无 Transition 或 Transition 无动作时，前进直接恢复目标 Frame。
- 必需能力、有效引用、动作名称/参数与目标类型在定义准备阶段检查；不会把动画静默降级为静态替换。
- 定义错误在 `create/mount` 时直接抛出（`Error`，message 带 Frame/Binding/Action 定位；`error.issues` 可含多条）。

### scene 过渡：完整目标画面的连续过渡

Transition 二选一：旧 `actions/parallel`（组件命令）或 `scene`（完整目标画面的受控视觉过渡）。scene 用于同一组对象在一步内共同完成让位、入场、值变化、关系提示和结果揭示，不需要为每个组件写一段临时布局动画。

```js
transitions: [{
  from: 'raw', to: 'stuffed',
  scene: {
    bindings: [
      { binding: 'wire', mode: 'layout' },
      { binding: 'result', mode: 'reveal', at: 'objects-settled' }
    ],
    timing: { duration: 340, markDelay: 120 } // 可省略：默认值由公共层提供
  }
}]
```

四种参与者模式：

| mode | 含义 | 要求 |
| --- | --- | --- |
| `layout` | 稳定对象的整组布局过渡；内容进入/值变化由 Adapter 的 effects 配合 | Adapter 声明 sceneModes 含 layout，handle 提供 `prepareChange` 与 `readView`；必须有布局目标 |
| `update` | 主体不移动时的受控内容/关注替换；不会自动对主体做 FLIP | Adapter 声明 update，handle 提供 `prepareChange`、`readView` 和 `effects`；不要求 targets |
| `cut` | 本次同步提交，不单独播放该 Binding 的过渡；可作参照/静态结构更新 | Adapter 声明 cut（restore-only Adapter 用 `restore` 包装）；cut 在提交时已显示目标，不能声明 after，需要承接视觉请用 update/reveal |
| `reveal` | 目标根节点同步提交并在同一绘制前隐藏，保留布局占位；到时机后整块淡入 | 声明 reveal；没有 after 时可用 `at:'start'` 或 `at:'objects-settled'` |

- Adapter 可声明 `defaultSceneMode`。参与者省略 `mode` 时使用该默认值；没有默认值的旧自定义 Adapter 必须显式写 mode，公共层不猜 cut。当前内置默认：sequence=layout，matrix=update，dom=update，expression=layout。
- update 与 layout 一样在提交后真实读回并核对；缺少 `effects()` 的 update 会报错，不能静默降级为 cut。

- `bindings` 必须非空、Binding 唯一、来源与目标 Frame 都有对应视图；scene 与 actions/parallel 互斥。
- 关系提示写在**目标 Frame 的 marks** 中；scene 过渡自身不接受 `marks`（避免运行提示与稳定停点两套绘制）。标记在目标 DOM 提交后按目标布局测量，随本步收束并保留到停稳。
- Frame.marks 可带可选 `id`。scene 内同 id 同类型且几何不变的标记会复用同一实例，不重复淡入；新增/删除及不兼容变化走受控进入/退出。旧无 id 标记保留原有逐帧行为，不按文字猜测身份。
- `NoteDemo.mount` 会自动提供默认舞台与标记呈现；`NoteDemo.create` 自备宿主时，公共层不自动渲染 Frame/Transition 标记。若定义包含 scene 目标 Frame 标记或 `scene.attention`，create 必须传入同一 presentation port 语义，否则创建/运行期报错；非 scene 的外部标记由宿主按会话状态与 `bindings.getTarget` 自行呈现。
- `scene.attention` 是作者显式给出的注意交接：`{ targets:[{binding,query,holdDuration?}], stepDuration? }`。默认 `stepDuration:560`，目标可单独覆盖观察停留 `holdDuration`；`holdDuration` 只表达观察节奏，不用于补偿时序。默认舞台用一个连续 `NoteExpr.Focus` 框按 targets 顺序迁移；首次出现使用 focus 的软出现（轻微上浮/缩放，320ms）再进入迁移，框层是公共舞台的局部柔光描边，不添加文字标签、不默认遮罩/变灰/滚动。焦点框属于本次运行，取消/回退/重看/销毁统一清理；`prefers-reduced-motion` 下不迁移也不增加等待。attention 目标可以引用不参与本次变化的稳定 Binding；运行层不从内容推断教学重点。`NoteDemo.create` 自备 presentation 时也要实现同名 port 语义，否则运行期报错。
- attention 的内容启动不再按累计时长推算：`NoteExpr.Focus` 的 `show()`/迁移提供 `whenArrived()` 实际完成句柄，`hide()` 提供 `whenHidden()`；默认舞台在真实到达后通知 scene 启动该目标对应的内容成员，scene 以成员的 ready 实际完成作为“可承接”依据，焦点只有在作者观察停留与内容 ready 都满足后才迁移/离开。纯参照目标没有内容成员时只按作者停留自然停留；不再使用固定百分比、统一秒数或单独 settle/exit 计时。
- attention 目标的协调粒度是**Binding 级内容启动**：同一个参与内容变化的 Binding 在一次 attention 中只允许一个目标（重复目标会明确报错）；`cut` 仍在同步提交时显示目标，不能作为 attention 内容门控目标；稳定参照 Binding 可以重复访问，但不会因此重启内容。焦点显示期间会持续按目标真实 rect 跟随，目标移动或改尺寸时框随之更新。
- 参与者可声明 `after`（Binding ID 或 ID 数组）。它只引用同一 scene 的参与者，等待所引用 Binding 的 **ready**（目标内容/关注已经可辨）；after 与旧 `at` 二选一，不能自连、重复或形成循环。无 after/at 的成员同窗开始。
- 旧 `reveal at:'objects-settled'` 的等待条件现在展开为“其他非 reveal 成员 ready”，不再是固定 sleep；带 after 的 reveal 不再隐含附加 objects-settled，公共层会检查它与隐式依赖组合后的循环。
- ready 是“后续表达可以承接”，finished 是“本参与者全部效果和清理结束”。效果 spec 可声明 `gate:'ready'|'finish'`；默认内容效果进入 ready，旧 `role:'mark'` 默认 finish。ready 效果也属于 finished。没有效果的成员立即 ready，不占空等。
- after 延迟只延迟视觉启动：目标 model/cues 和布局已在同一次提交中写入；未启动的值交换/关注/布局保持源视觉。attention 不替代 after；它只决定焦点框的注意顺序，不改变模型提交、ready/finished 或因果依赖。
- 允许的 `timing`（数字毫秒，负数/未知键报错）：`duration`（布局）、`stagger`（入场/值替换错开）、`enterDuration`、`exitDuration`、`valueSwapDelay`、`valueSwapDuration`、`valueFlashDuration`、`cueDuration`（关注/变化持续 cue 的交接）、`markDelay`、`markDuration`、`revealDelay`、`revealDuration`、`easing`（CSS easing 字符串）。默认值依次为 600 / 40 / 420 / 220 / 160 / 420 / 560 / 520 / 200 / 420 / 0 / 260 / `cubic-bezier(.3,0,.15,1)`。
- 有效 timing 的优先级为：公共默认 → Adapter 静态 `sceneTimingDefaults` 稀疏默认（若声明）→ **scene.attention 存在时的公共 attention 内容节奏** → scene.timing → 该参与者 `timing`。后写覆盖前写，0 是有效值；编译时冻结稀疏输入，未知键、负数/非有限数或浏览器不接受的 easing 在定义阶段报错。`effects(ctx).timing` 仍是合并后的全量最终值。
- Adapter 可声明静态 `sceneTimingDefaults`（同一 timing 键表的稀疏对象）。内置 Adapter 的差异默认：Matrix `enterDuration:180, valueSwapDelay:80, valueSwapDuration:320`；Expression `enterDuration:360, exitDuration:320, valueSwapDelay:0, valueSwapDuration:420`；DOM `valueSwapDelay:0, valueSwapDuration:420`；Sequence 保留其认可波形。布局/reveal 也读取该成员最终 timing；Frame 外部标记没有成员归属：普通 scene 读取公共默认 + scene.timing，声明 `scene.attention` 的过渡还会使用 attention 内容节奏（scene.timing 显式覆盖的部分除外）。
- 声明了 `scene.attention` 的过渡会使用公共 attention 内容节奏：`duration:760, stagger:70, enterDuration:560, exitDuration:320, valueSwapDelay:0, valueSwapDuration:560, valueFlashDuration:720, cueDuration:680, markDelay:260, markDuration:600, revealDelay:100, revealDuration:420, easing:cubic-bezier(.22,.7,.25,1)`。它位于 Adapter 默认之后、scene/member timing 之前，用来给注意交接留出识别时间；普通 scene（没有 attention）继续使用原公共默认，不改既有认可流程。焦点真实到达某个 Binding 的目标时，公共 scene 才启动该 Binding 的 layout/update/reveal 效果；此前目标内容保持源视觉/隐藏，而不是在别处已经开始变化。
- 值替换的模型提交与视觉阶段分开：commit 时目标 Frame 已生效；`valueSwapDelay`（默认 160ms）是旧值可见阶段结束、新值开始显现的相对起点，`valueSwapDuration`（默认 420ms）是旧值退场/新值显现的持续时间。默认用旧值 ghost 叠层把“旧值 → 新值”做成可辨认的视觉交换，ghost 仅视觉且 `aria-hidden`，不推迟模型、不参与布局；`valueFlashDuration` 的强调在替换后保持约一半时间再退场。减少动效时不创建 ghost，直接显示目标值。
- 布局、入场、值替换按对象顺序使用 `stagger` 轻微错开；缓动默认 `cubic-bezier(.3,0,.15,1)`，避免大部分运动集中在开头。
- update/layout 的模型和 cues 必须能从组件真实状态读回；公共层不会用 `restore` 再盖一次正确目标来掩盖错误。
- 无动作、同目标、减少动效不人为制造执行窗口：直接提交目标，揭示与标记静态到位；按钮按新停点更新。
- 运行语义：phase 为 `running` 时，组件真实 model 可能已是目标，但 `settledFrameId` 仍是来源，直到布局、内层、揭示与标记全部收束才提交 `idle`。layout 参与者提交后必须读回真实状态并与目标 Frame 核对，不符即失败，不调用 restore 掩盖。

## 3. 会话 API

```js
var session = NoteDemo.create({ definition: definition, slots: { main: mainEl } });
// 或：
var session = NoteDemo.mount(host, {
  definition: definition,
  layout: function (container) {
    var root = document.createElement('div');
    var main = document.createElement('div');
    root.appendChild(main);
    container.appendChild(root);
    return { root: root, slots: { main: main } };  // 也可只返回 Element（作为 main 插槽）
  },
  adapters: { custom: myAdapter },   // 可选：与内置名称合并
  initialFrameId: 'removed',         // 可选：覆盖 definition.initialFrameId
  title: '演示标题',                  // 可选：默认舞台标题
  label: '演示可访问名称',             // 可选：默认舞台 aria-label
  labels: { prev: '上一步', next: '下一步', replay: '重看', reset: '重来' }, // 可选；labels.progress 可传函数或带 {current}/{total}/{frameId} 的字符串
  captionReserve: true,              // 可选，默认 true；控制默认舞台是否为全部 Frame 的字幕预留阅读高度
  captionLabel: '字幕'               // 可选，默认“字幕”；字幕身份标签，空字符串则不显示
});
// mount 返回的 session 额外带 el（舞台根节点）与包装后的 destroy（同时清理舞台）。

```

`create` 在所有 Binding 完成初始 Frame 恢复后返回；创建失败会清理本次已创建的 owned 实例与监听，外部 slot 与 borrowed 实例不被销毁。

| 方法 | 返回值 | 说明 |
| --- | --- | --- |
| `next()` | `Promise<Result>` | 推进到下一个 Frame；有 scene 或动作则执行过渡，无过渡直接恢复；末 Frame 为 noop(end)；运行中为 noop(busy)，不排队。 |
| `prev()` | `Promise<Result>` | 回退一个 Frame（直接恢复，不反向播放过渡）；运行中取消本次运行并回到其来源 Frame；首 Frame 为 noop(start)。 |
| `go(frameId)` | `Promise<Result>` | 直接恢复指定 Frame，不暗播中间步骤；运行中先取消旧运行。未知 Frame 返回 failed 并发布 error 状态，可再次导航恢复。 |
| `replay()` | `Promise<Result>` | 从当前 Frame 的前一 Frame 重演入边（scene 与 actions 同一入口）；无 transition/无过渡内容时直接恢复当前 Frame；首 Frame 为 noop(start)；运行中重演正在执行的同一入边。 |
| `reset()` | `Promise<Result>` | 取消运行并恢复配置的初始点（即使已在初始点也做一次幂等恢复）。 |
| `getState()` | 状态对象 | 见下。 |
| `subscribe(fn)` | 解除订阅函数 | 订阅后立即回调一次当前状态；程序调用与按钮调用共用同一状态发布。 |
| `destroy()` | `undefined` | 同步、幂等；先使运行失效（进行中的 Promise 结算为 cancelled），再销毁本次 owned 实例、标记、控件与舞台；borrowed 实例不被销毁。 |

Result：

```js
{ status: 'completed' | 'cancelled' | 'noop' | 'failed', frameId, reason?, error? }
```

- `completed`：导航结算到 `frameId` 对应的停点。
- `cancelled`：本次运行被后续导航/销毁取消；`frameId` 为取消后恢复到的来源 Frame。
- `noop`：无需动作，`reason` 为 `busy`（运行中 next）、`start`（首帧 prev/replay）、`end`（末帧 next）或 `disposed`（销毁后调用）。
- `failed`：动作异常、模型不符或目标无法恢复；`error` 至少含 `message`，可能含 `binding`、`action`。

公共状态（每次发布为新的只读副本）：

```js
{
  phase: 'idle' | 'running' | 'error' | 'disposed',
  settledFrameId: 'start',   // 最近一个真正完成的停点
  targetFrameId: null,       // 仅运行中存在
  replaying: false,          // 重看运行中为 true
  error: null                // 或 { binding?, action?, message }
}
```

## 4. 一次推进的次序（实现与验收依据）

1. 校验目标与动作能力，建立唯一 runId 与 AbortController；公开状态进入 `running`，记录 `targetFrameId`，字幕一次切到目标 Frame 并在整个动作期间保持稳定；默认舞台立即把“下一步”置为统一灰色不可用态。
2. 在常驻 Binding 上执行本次动作计划（串行或显式并行）。可以配合的动作在定义中显式并行，让同一步保持连续变化；运行期间标记每帧重新解析逻辑目标；Transition 未声明 marks 时暂时隐藏 Frame 标记。
3. 等待全部动作完成（包括位移、离场副本与内部清理）。取消会释放动画、副本、计时器与等待，`finished` 只结算一次。
4. 对参与动作的 Binding 从组件真实状态读回规范化 model，与目标 Frame 比较；一致后只应用目标 cues，必要时读回 cues 核对。模型不一致报错，**不会**调用 restore(目标) 掩盖错误动作。
5. 不参与本次动作的静态 Binding 完整恢复目标 Frame。
6. 必要时等待本步仍需要收束的提示（例如 R10 停稳后托盘文字的短暂淡入）；稳定标记与结果在恢复“下一步”可用之前落位，**不让读者在按钮恢复后又看到新一轮关键提示动效**。
7. 原子提交新的已停稳位置，应用稳定标记，最后更新按钮状态并发布 `idle` 状态。

### scene 的执行次序

scene Transition 沿用同一控制器/取消/错误语义，内部按以下次序执行：

1. 建立本次 run token 与 AbortController，公开状态进入 `running`，字幕切到目标 Frame 并保持稳定；默认舞台立即把“下一步”置为灰色不可用。
2. 先恢复不参与 scene 的静态 Binding，再准备全部 layout/update 参与者（`prepareChange` 可异步准备资源，但不改活 DOM、不启动动画）。
3. 收齐旧对象/旧位置、旧内容/关注；隐藏/停用旧标记。
4. 在同一同步事务内提交全部目标 model/cues，并在同一次绘制前测量目标、读回核对、隐藏需要延后揭示的目标容器、准备受控标记和全部效果（暂停在起点）。
5. layout/update 参与者真实读回并与目标 Frame 核对；不符立即失败并统一清理。
6. 布局载体只写反向位移（translate）；内容/关注由 Adapter effects 使用内层和真实目标；独立载体不争写同一属性。
7. 按 after/隐式 objects-settled 依赖启动效果：没有依赖的同窗开始；被依赖的成员 ready 后才启动后续。ready 效果结束后依赖方可承接，finished 等待全部效果与清理。
8. attention 焦点框在目标提交后开始，按作者序列迁移；它与内容 effect 共用本次运行的取消/错误/完成边界，但不延长或篡改 ready/finished 的因果定义。
9. 全部成员 finished、标记与 attention 序列 finished 后写稳定终态；字幕轻提示在写稳定终态前关闭，不延长完成边界。随后清临时 transform/属性/隐藏状态，`presentation.settle()` 转稳定测量，最后发布 `idle`。取消时先使 run 失效、取消全部句柄并清临时资源，恢复来源 Frame；正常完成也会释放临时 fill，迟到的 finished 不提交新 Frame。

## 5. Adapter 接入

内置 Adapter 由库维护；普通笔记只选择名称即可。自定义画面通过本地 Adapter 扩展，核心里不写任何专属知识绘图。

```js
var myAdapter = {
  name: 'badge',
  normalizeView: function (input, options) {
    var source = input || {};
    return {
      model: { label: String(source.label || ''), active: !!source.active },
      cues: { active: !!source.active }
    };
  },
  validateAction: function (action, options) {
    if (action.type !== 'activate') throw new Error('badge 只支持 activate');
  },
  mount: function (host, options) {
    var root = document.createElement('div');
    host.appendChild(root);
    var active = false;
    return {
      restore: function (view) { /* 直接落到 view.model，不播动画 */ },
      readView: function () { return { model: { label: root.textContent, active: active }, cues: { active: active } }; },
      applyCues: function (cues) { /* 只改提示 */ },
      perform: function (action, ctx) {
        var resolveFinished;
        var finished = new Promise(function (resolve) { resolveFinished = resolve; });
        root.setAttribute('data-active', 'true');
        setTimeout(function () { resolveFinished({ status: 'completed' }); }, 180);
        return { finished: finished, cancel: function () { resolveFinished({ status: 'cancelled' }); } };
      },
      target: function (query) { return query && query.part === 'root' ? root : null; },
      destroy: function () { root.remove(); }
    };
  }
};
```

接口约定：

- `normalizeView(input, options) -> { model, cues }`：填默认值并产生只读副本；`cues` 是 Frame 控制的提示（focus/changed 等），不能混进 model。
- `validateAction(action, options)`：定义准备阶段核对动作名称、参数与目标类型。
- `mount(host, options) -> BindingHandle` / `adopt?(instance, options)`：`host` 是公共层在插槽内建立的独立子容器；Adapter 在其中挂载组件。
- `restore(view)`：直接恢复完整目标（model+cues），不播动画、幂等；保留仍存在对象的身份。
- `readView()`：参与动作的 Binding 必须有，且必须来自组件实际状态，不能缓存“刚传入的目标”。
- `settleVisual?()`：可选。若组件在本步动作结束后还有必须随本步收束的提示（例如停稳文字淡入），返回 Promise 告诉公共层等它完成再恢复下一步可用；仅编排使用，不影响组件独立用法。
- `applyCues(cues)`：只更新 Frame 控制的提示，不改 model、不重挂载、不重写 items。
- `perform(action, { signal, motion, sourceView, targetView }) -> { finished, cancel }`：一次动作可以有多段位移与离场对象；`finished` 覆盖整体动画与临时资源收尾；`cancel()` 后 `finished` 也必须结算。
- `target(query)`：按逻辑身份返回当前 DOM 元素；组件重建 DOM 后必须重新解析，不能返回旧引用。
- `destroy()`：owned 时释放实例；borrowed 时只解除本次管理，不销毁外部实例。
- 标记目标能力（target）与动作能力（perform）在 `create/mount` 挂载后检查，缺失会在创建阶段给出定位错误。
- `sceneModes?`：Adapter 声明支持的 scene 模式数组（`layout` / `update` / `cut` / `reveal`）。定义准备阶段核对；未声明的模式不能被 scene 使用。
- `defaultSceneMode?`：作者省略参与者 mode 时采用的已声明模式。内置 sequence=layout、matrix/dom=update、expression=layout；无默认值的旧自定义 Adapter 仍要求作者显式写 mode。
- `sceneTimingDefaults?`：可选稀疏 timing 默认，只在 scene 参与者解析最终 timing 时合并；必须使用允许的 timing 键，0 有效，未知键/非法值在定义阶段报错。它不是作者配置层，也不替代 scene.timing。
- `prepareChange?(ctx) -> PreparedChange`：layout 与 update 参与者需要。ctx 为 `{bindingId, sourceFrameId, targetFrameId, sourceView, targetView, signal, motion}`；只允许准备资源/捕获引用，不能改活 DOM。同步返回或返回 Promise 均可。
- `PreparedChange`：`commit()`（同步提交完整目标，不自行启动播放器）、`targets() -> [{id, layoutEl, contentEl?, valueEl?}]`（layout 必需；提交前后都可取得真实载体）、`effects(ctx) -> EffectSpec[]`（update/layout 的内容与提示效果；spec = `{el, keyframes, options:{duration,delay,easing,fill?}, cleanupEl?, role?, gate?}`；`gate:'ready'|'finish'` 标记可承接/最终收尾；旧 `role:'mark'` 默认 finish）、`cleanup()`（幂等清理本次临时资源）、`facts?()`（可选诊断：entered/exited/valueChanged）。
- cut/reveal 模式可由公共层用 `restore(view)` 包装为同步 commit，不需要 Adapter 新增 prepareChange；layout 不允许这种无信息包装。
- 读回能力：layout 与 update 参与者必须提供 `readView()`，提交后公共层会用真实状态与目标 Frame 的 model/cues 核对；cut/reveal 有 readView 时同样核对。update 不使用 Adapter 缓存目标伪称读回。

### 5.1 内置 Adapter 的视图与目标

| 名称 | 组件 | Frame 视图 | 动作 | target query |
| --- | --- | --- | --- | --- |
| `matrix` | NoteViz.Matrix（D02） | `{ rows, columns, values, focus?, changed?, caption? }` | 无 | `{ row:'r1', col:'c2' }`；sceneModes `['cut','update']`，默认 update；Adapter mount 未指定 stateText 时默认 false |
| `dom` | 内置纯文本占位 | `{ text:string }` | 无 | `{ part:'root' }` / `{ part:'value' }`；sceneModes `['cut','update','reveal']`，默认 update |
| `expression` | NoteUI.Expression（C13） | `{ parts:[{id,text|tex}], focus?, changed?, label? }` | 无 | `{ id:'p1' }` / `{ id:'p1', part:'unit'|'content'|'value' }`；sceneModes `['layout','cut']`，默认 layout |
| `sequence-edit` | NoteViz.SequenceEdit（M01） | `{ items:[{id,label}], focus?, changed? }` | `remove({id})`、`swap({a,b})` | `{ id:'a' }` |
| `sequence-insert` | SeqInsert（R10） | `{ inserted:boolean }`，整组数据在 `options` 固定 | `insert`、`restore`（params 为空对象） | `{ kind:'source', key:'a' }`、`{ kind:'inserted' }`、`{ kind:'pending' }` |
| `sequence` | NoteViz.Sequence（D01） | `{ items:[{id,value,label?}], groups?:[{label,ids}], focus?, changed? }` | 无：只用于 scene（layout/cut/reveal） | `{ id:'p1' }`、`{ id:'p1', part:'unit'|'cell'|'value'|'label'|'mark' }`、`{ part:'root' }` |

- matrix 的 cues 规范为 `{ focus:{rows:[id],cols:[id],cells:[{row,col}]}, changed:{...}, caption:string }`；caption 是矩阵自身说明，与公共字幕分开。matrix Adapter 可作 scene 的 **cut/update** 参与者：固定行列身份下 update 支持单元值、关注和内容变化的受控过渡；不承诺行列增删/重排/转置，仍不支持动作，也不声明 layout/reveal。Matrix 组件新增 `stateText`：独立组件默认 true；NoteDemo Adapter 新挂载默认 false，显式 options.stateText 优先，借用实例保持原显示。关闭时只收敛行头/单元“关注/变化”文字，保留 data-mark、真实可访问状态描述与视觉轮廓；开启时旧标签以局部副本退场、目标标签进入，不让旧文字在 commit 瞬间消失。
- dom 的 update 只针对单个文本读数：root 内部建立稳定 valueSlot，旧值副本与 valueSlot 为兄弟并在 root 内局部定位；模型读回来自 valueSlot，不把 ghost 计入，也不改宿主父容器的 position。不解析长文或算式结构。
- expression 按稳定 part.id 保留 unit → contentCarrier → valueSlot；未变项的 DOM 与 NoteUI.Math 实例复用。同 ID 换值的旧副本放在 contentCarrier 内跟随 unit；补 focus/changed 的 cue-only 差分，不变 cue 不重播。
- sequence-edit / sequence-insert 的 focus/changed 是逻辑 ID 集合；规范化后去重并按稳定顺序排序。集合按集合比较，数组数据按序比较；不直接拿组件原始 getState 与 Frame JSON 深比。
- sequence-insert 固定 Binding 数据，不做跨 Frame 换序列；换整组数据使用新定义/新会话。`total`/`moved` 不是当前可见数量或已发生移动，不作为读回依据。
- sequence-insert 每次 render 会重建卡片，`target` 每次调用重新取得当前元素；插入前的“已插入”目标返回 null，需要提前标记的 Frame 应把该引用声明为 `optional` 或用 Transition 标记。
- sequence（D01 scene 接入）：要求显式非空唯一字符串 ID；`groups` 只接受 `{label,ids}`（拒绝 start/count/from/to），focus/changed 必须是存在 ID；display value 与 label 统一转字符串。scene 期间 Adapter 给组件根加 `data-note-scene="true"` 暂停受控节点原有 CSS transition，由公共层效果接管；exit 事实会报告，但 v1 不创建离场 ghost（需要保留删除证据时用删除状态/标签表达）。D01 新增 `getState()`、`getMotionTargets()`、`setSceneActive(on)` 三个公开查询/受控方法，见[图形与数据对象](viz-objects.md)。
- sequence Adapter 的 NoteDemo 默认组合为 `stable:true, summary:false, stateText:false`：稳定占位标签/状态行，隐藏重复的可见摘要与“变化”文字，但保留对象标签、视觉 cues 与 aria 描述。宿主可在 Binding.options 中用同名布尔项覆盖；D01 独立使用仍默认 `summary:true, stateText:true, stable:false`。
- expression（C13）scene 接入：默认 layout，项级 FLIP 与内容 ghost 由 Adapter effects 提供；组件只做稳定 id 项、text/tex、cues 与查询，不解析公式语义。

#### scene 执行后端

默认只维护一个内部后端：对 layout 载体做 translate-only 的 FLIP（旧 rect → 目标布局），内层进入/值替换用 WAAPI spec，由同一次运行的内部 EffectScope 管理真实句柄、暂停起点、依赖启动、ready/finished 与清理；值替换的旧值 ghost 由 sequence Adapter 在 effects 中创建并登记清理，取消或正常完成都会移除；matrix/dom/expression 各自提供同一个 PreparedChange/effects 契约。减少动效直接落终态，不创建 ghost。布局与几何方法来自已有 NoteCore.motion 的 WAAPI 封装和 Svelte 小型几何经验。

设计阶段曾以 Anime 4.5.0 与 Motion 14.7.1 做最小真实样片：Anime 的 createLayout 会遍历并强制接管非 target 后代的内联样式（观察到的 inner 被改为 absolute/width/color/background），与 D01 内层载体冲突；Motion 的公开 stop/cancel 不结算 finished 且取消后留下内联 transform/opacity 与投影状态，无法用公开 API 保证清理干净。两者均未通过受控分层/资源清理门槛，因此不引入运行时依赖，也不向笔记作者暴露引擎选择；vendor 中不新增第三方动画库。

## 6. 默认舞台与呈现（demo-ui）

`NoteDemo.mount(host, options)` 使用现有 B01 `NoteBlocks.DemoStage` 作为默认舞台：

- 画面放在舞台中部；字幕紧邻画面下方、控件在其下方，三者都在同一演示卡内。默认舞台给字幕一个独立的阅读身份：左侧显示可配置的“字幕”标签，右侧是完整句子；长句正常换行，不裁切、不缩字。字幕不是结果区，也不承担状态读数。默认舞台按当前宽度测量本会话**全部 Frame 字幕**的高度并为字幕阅读区预留最高者，预留不低于 B01 CSS 的阅读下限，测量时按“字幕身份标签可见”的最窄布局计算，避免首帧空字幕后在窄屏换长字幕时跳动；画布的 `min-height` 在会话内只增长不回缩。因此常规推进前、运行中、停稳后，字幕和操作位置保持稳定。窗口宽度变化后会重新测量并排布。
- 字幕换句提示由 Presentation 统一处理：目标 Frame 提交后，整句以一次 200ms 的轻淡入/上移进入（首屏、取消、回退、错误、减少动效不播），内容不变不重复；若停稳时动画仍未结束，会在下次可用前关闭。它不逐字、不复制文本、不新增独立的硬等待。
- 默认舞台不创建结果区。结果是否存在、放在画面旁还是别处，由宿主 layout 决定；宿主可用独立标签和读数排版表明“结果”，不要把结果文字伪装成第二段字幕。样例只在字节填充场景使用窄读数“结果 · 接收端”，另一组数据不声明 result。
- 控件区在舞台底部形成统一操作带：主按钮“下一步”与“上一步”成组，重看/重来为次要操作，进度读数靠右；控件节点常驻，不因视觉更新重建。
- 开发说明（实现细节、参数、自检状态）不属于演示文字：样例把它们放进默认收起的“开发自检”区域；公共舞台只负责标题、画面、字幕和操作。
- 会话存在 Range/Link 关系标记时，默认舞台在画布上方预留一条标记走廊（`--note-demo-mark-gutter`，默认 26px），让括线标签出现在画面与标题之间，而不是压住标题或被裁切。该空间计入画布稳定高度，不随某一步是否出现标记而变化。
- 默认控件为“上一步 / 下一步 / 重看 / 重来”与一个进度读数（`第 n / m 步`，可用 `labels.progress` 改写）；首 Frame 在稳定状态禁用上一步/重看，末 Frame 禁用下一步。
- **执行中反馈**：本步被接受后，“下一步”立即呈组件库统一的中性灰禁用态，并在整个动作与必要收尾期间保持；鼠标、键盘与程序重复 next 都不会排队或累积步骤。默认舞台使用可聚焦的禁用语义（`aria-disabled` + 完整事件拦截）而不是把焦点移走：焦点留在“下一步”上仍可见，同时“上一步 / 重看 / 重来”在运行中保持可取消能力（包括从初始停点启动的第一次过渡）。
- 恢复可用时，本步主要结果、Frame 标记与必要提示已经落位；恢复可用后不再新启动关键提示动效。最后停点保持禁用，不误导继续推进。
- 一次动作期间字幕保持目标 Frame 的句子；取消后回到来源 Frame 的字幕；错误时保留已停稳 Frame 的字幕并显示 role=alert 的错误说明。
- Frame 标记只在稳定状态显示；默认舞台中的标记以会话范围即时落位（不播放独立组件的淡入/迁移表演）。Transition 声明 marks 时，动作期间显示 Transition 标记并暂时隐藏 Frame 标记，结束时换回目标 Frame 的标记。
- 运行期间每帧重新解析逻辑目标：同一 Element 只 refresh；组件重建 DOM 后重新 show，不会一直刷新已断开的旧引用；运行结束停止跟帧。
- 无动作、同目标与减少动效可以立即落到正确终态：不会出现人为最低置灰时长、灰色闪烁或额外等待；此时按钮直接按新停点更新。
- 必需标记目标缺失会报出具体 binding/query（进入 error 状态）；`optional:true` 的目标缺失时隐藏。
- scene 运行期由私有 presentation port 接管最终标记：目标 commit 后同步解析目标 Frame.marks、按目标布局建受控实例并先隐蔽；对象效果收束前后按相对时机显现，`settle()` 后转为稳定测量并保留到下一次渲染，运行期不再由 phase 订阅重复建标记或补播提示。稳定期页面的普通 window 滚动会平移受控标记、保持与目标元素锚定且不重算选边；resize/组件重建会撤掉平移并按真实目标重测。
- scene 的 reveal 容器在目标提交前隐藏，`objects-settled` 后淡入；`at:'start'` 则在提交后立即显现。减少动效时直接显示。布局 FLIP、Adapter effects 与该成员 reveal 读取同一份最终 timing。
- scene 效果创建/启动/意外取消失败会给 Frame/Binding/effect 定位并终止本次运行，清理 ghost/fill 后由 controller 恢复来源停点；下游依赖不会在失败后启动。无变化与减少动效不造最低等待。
- D01 的值替换默认先保留旧值叠层、让对象先移动，随后旧值上移淡出、新值从下方淡入，并用保持后淡出的背景强调；模型、目标 Frame 和统一取消语义不变。
- 稳定空间的边界：字幕按本会话全部 Frame 在**当前宽度**下的最高字数预留；画布（含关系标记走廊）按本会话已出现过的最高内容预留。若宿主内容在某一停点首次出现更高的内在高度，画布仍会在该步提交时增长一次；需要完全固定时，可在宿主 layout 内用内容自身的稳定槽位/占位，而不是给每个样例写固定像素高度。

`layout(container)` 是本地的 DOM 装配函数：在容器内创建本次画面并返回 `{ root, slots, cleanup? }`（每个 slot 必须是 Element）。自定义 layout 不再强制 `main`；每个 Binding 按 `binding.slot` 取得真实插槽，返回单个 Element 的旧用法仍映射为 `main`。

`NoteDemo.collectSlots(root, required)` 只按 `[data-demo-slot]` 收集，重复/缺失报名称；不猜区域。可选 `layout.cleanup` 在正常销毁和取得返回值后的挂载失败中恰好调用一次。layout 回调在返回前失败时，公共层没有 cleanup 可拿，内部资源由 layout 自行释放；配方已在 slot 收集失败时自行清理。

### 标记形状

```js
{ kind: 'focus', target: { binding, query, optional? }, mode: 'box' | 'underline', text? }
{ kind: 'range', targets: [ref, ...], text, side?, orientation? }
{ kind: 'link', from: ref, to: ref, label, arrow? }
```

- `Focus.text` 表示目标中的文本子串（下划线），不是框旁字幕；`mode:'box'` 框住目标本身。
- `ref = { binding, query, optional? }`；query 由 Adapter 解释，不强制所有组件使用一种伪统一对象 ID。
- 缺失必需目标报具体 binding/query；optional 目标可隐藏。销毁只清理当前会话的标记实例。

## 7. 取消、错误与生命周期

- 同一会话同一时刻只允许一个有效运行；`runId` 区分旧回调，`AbortController` 传递取消。旧 Promise 迟到不能改变位置、字幕或标记。
- 运行中 `next` 不排队；`prev/go/reset` 会取消旧运行；`replay` 重演正在执行的同一入边。取消会结束所有等待。
- 动作异常或模型不符时：取消同行动作 → 尝试完整恢复最近已停稳 Frame。恢复成功进入 error 状态并返回 failed（settledFrameId 保持不变）；恢复失败保留 error，不假称画面一致。新 `go/reset/prev/next` 可再次尝试恢复，不做自动重试平台。
- 减少动效（`prefers-reduced-motion: reduce`）：保持目标 Frame、字幕与标记一致，省去视觉过渡；无动作、已在目标、减少动效都可 `completed`，取消为 `cancelled`。
- borrowed 实例：运行期间由公共层管理其受控视图，宿主不同时写同一视图；不覆盖原回调、不调用外部 destroy；销毁后的画面归属由宿主自行负责。
- `destroy` 同步、幂等；不产生仍会提交的异步尾巴，也不会销毁 borrowed 实例。

## 9. 已知限制

- frames 为线性停点；不实现分支剧情、自动串播、暂停/恢复、可视化编辑器、JSON 解释器、Agent 检索服务或全库 Adapter。
- 内置 Adapter 覆盖 matrix、sequence、sequence-edit、sequence-insert、dom、expression；其他图形用本地自定义 Adapter，核对接口后接入。D02–D06 没有全部迁移到 scene：D02 已支持 cut/update，但不支持 layout/reveal 与行列重排；D03–D06 仍按各自接入能力为准，不宣称所有图形都已具备整组过渡。
- 默认舞台 UI 入口仍携带现有 blocks 及其传递依赖，未做按组件裁剪；这是明示限制。
- 默认舞台中的 Focus/Range/Link 使用会话范围的即时落位，独立使用这些组件时仍保留原有淡入/迁移；若自定义舞台需要动画标记，可在本地呈现层自行实现。
- 依赖核心能力读取真实 model 的动作，若组件本身没有可靠的读回与完整动作句柄，需要先在对应组件补齐小接口，而不是在 Adapter 里假装读回或按固定时长等待。
- scene 只实现窄 HTML 布局过渡：布局载体只做位移（不通过 scale 处理尺寸变化），不覆盖 SVG 内部 transform；不提供任意时间轴/客户自定义 DSL；不推断跨 Binding 的对象身份（同 ID 在不同 Binding 中默认独立）。
- sequence scene 的离场对象 v1 不生成 ghost 动画；需要保留删除证据时用目标停点的删除状态/标签表达。样例②的 80 是“保持原值但让位”的教学数据，不是标准 PPP 语义。
- 受控标记的稳定期滚动跟随以 window 普通滚动为锚点；嵌套滚动容器、缩放或字体二次加载导致的重排依赖 resize/稳定观察器，不保证逐帧跟随。
- 稳定舞台依赖对字幕全部 Frame 的测量和 D01 等组件提供的稳定占位；任意自定义内容若在同一演示的不同停点有大幅不同的内在高度，首次出现更高画面时仍可能重新排布。默认舞台不裁切内容、不缩小文字，也不把控件固定到视口来掩盖内容增长。
- D01 的 `stable` 会为标签/状态行保留固定空间，因此对象盒比自然排布更高；这是可关闭的显示选择（`stable:false`），不是全库统一样式。
- 技术 `verified` 只代表工程核验，不代表用户审美认可；I07 的 userReview 为 not-reviewed。
