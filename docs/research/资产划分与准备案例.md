本轮查阅了项目文档、GitHub 仓库说明、作者方法文章、论文项目页和论坛讨论。目标是借鉴资产怎样划分、展示和选择，不是决定安装这些工具。

## 1. Storybook：组件实现与可观察状态放在一起

来源：[Writing stories](https://storybook.js.org/docs/writing-stories/index)、[Manifests](https://storybook.js.org/docs/ai/manifests)。

> **案例事实**
>
> Story 表示给定参数下组件的一个可渲染状态；示例文件与组件实现相邻，同一组件可以有多个状态。官方还提供描述名称、接口和用法的结构化清单，帮助 Agent 理解组件；AI 清单能力目前仍处于预览期。

对我们的启发：资产应同时便于人看效果、Agent 找实现和识别可改内容。一个插入组件可用不同数据长度、插入位置展示适用情况。准备初期可以用简短说明做到，不据此要求安装 Storybook、使用 React 或建设 MCP 服务。

## 2. Manim 与 Reactive Manim：对象、动作和组合能力分开

来源：[Manim building blocks](https://docs.manim.community/en/stable/tutorials/building_blocks.html)、[Example gallery](https://docs.manim.community/en/stable/examples.html)、[Reactive Manim GitHub](https://github.com/philip-murray/reactive-manim)。

> **案例事实**
>
> Manim 将可显示对象、动画和场景区分为不同概念；图库把代码片段与对应的图像或视频效果放在一起。
>
> Reactive Manim 进一步提供分式、括号、矩阵等可组合的数学对象，以及状态变化到动画的实现示例。它展示了面向知识对象的复用，而不仅是普通按钮等 UI 元素。

对我们的启发：序列、标记、连线可作为对象；插入、删除、替换可作为动作；它们可以组成只讲一个机制的小演示。图库的展示方法值得借鉴，但视频动画工具的时间轴不直接等同于我们已确认的读者步进方式。本轮未安装运行，也不声称代码能直接搬入单文件 HTML。

## 3. Motion Canvas：实现、示例和播放器各有职责

来源：[GitHub 仓库与包划分](https://github.com/motion-canvas/motion-canvas)、[Scene hierarchy](https://github.com/motion-canvas/motion-canvas/blob/main/packages/docs/docs/getting-started/hierarchy.mdx)。

> **案例事实**
>
> 仓库将核心运行逻辑、二维图形、文档示例和浏览器播放器分包；场景内部以节点树组合图形对象。

对我们的启发：局部图形与动效实现、用于选型的预览、演示推进控制可以分别维护，避免每份笔记重复编写整个播放器。这里只借鉴职责划分，不照搬其大型仓库结构或默认制作流程。

## 4. Atomic Design：复用既要有小部件，也要有有意义的组合

来源：[Brad Frost：Atomic Design Methodology](https://atomicdesign.bradfrost.com/chapter-2/)。

> **案例事实**
>
> 该方法从基础元素逐层讨论功能组合、较大模块、模板和页面，强调各层结合使用，而不是单纯按文件类型收集材料。

对我们的启发：保留小对象和动作，同时积累“按条件定位并插入”“移除后恢复对齐”等小机制组合。用户已明确资产不能是完整笔记，因此我们的复用范围不直接延伸为整页课程模板，也不强制采用原方法的五层命名。

## 5. Style Tiles：先比较视觉样片，再扩展风格

来源：[Style Tiles 项目说明与例子](https://styletil.es/)、[作者方法文章的搜索索引](https://badassideas.com/style-tiles-as-a-web-design-process-tool/)。

> **案例事实**
>
> Style Tiles 使用字体、颜色和局部界面元素表达视觉方向，帮助讨论偏好，不必先做多份完整页面。项目说明提供样例与模板。
>
> 作者文章的完整页面本轮返回 403，因此以可读取的项目说明为主要依据，没有把搜索摘要当作全文阅读。

对我们的启发：使用同一组对象、说明文字与状态变化比较风格。我们可进一步加入一段可控动效，检验静态外观和动作结束后的阅读效果；这项动态扩展是本项目的推导，不是原方法本身的规定。

## 6. Idyll：内容组织与可复用行为分工

来源：[UIST 2018 论文项目页](https://idl.uw.edu/papers/idyll)。

> **案例事实**
>
> Idyll 为交互文章提供标记语言与结构化 JavaScript 组件接口，使文章样式、布局和读者触发事件能够通过组件组织。研究项目针对交互文章制作耗时、定制代码多的问题提出作者工具。

对我们的启发：知识内容、解释和停点由笔记组织承担，资产提供可复用的图形和行为。不能期待资产自动判断教学顺序；也不据此决定把现有 MD 改写为另一套文章语言。本轮未复现实验或验证节时幅度。

## 7. 论坛中的实际分歧

来源：[There should be a Manim Components Library](https://www.reddit.com/r/3Blue1Brown/comments/qre6ul/there_should_be_a_manim_components_libaray_like/)。

> **社区经验，非研究结论**
>
> 发帖者希望有可预览并附源码的 Scene/Mobject 分享库；回复者提出，动画组件过于通用时仍需写大量内容，过于具体时又可能迅速膨胀。
>
> 这是社区使用者的取舍讨论，不作为任何库已经有效或适合本项目的证明。

对我们的启发：基础部件与少量有知识意义的组合都值得保留。准备库先积累实际会用到、能解释用途的能力，不追求覆盖所有课程和动作。

## 本项目的候选组织方法

以下来自调研后的组织建议。其中第 1 项的小机制组合粒度已获用户认可；其余具体形式与技术方案仍需细化，不视为已经实施。

1. 以有意义的小机制作为预览与选择单位，内部复用对象和动作。例如只展示“满足条件后向序列插入一个元素”，无需附完整课程笔记。
2. 每项资产让人能看到效果，让 Agent 能找到实现、了解适用内容与可改参数；认可范围单独说明，不把动效认可扩大成配色或文字认可。
3. 比较风格时保持内容与动作一致，再比较文字层次、颜色、线条、重点提示和结束状态。静态风格与动作效果都在真实的小内容中判断。
4. 通用推进控制、图形对象、动作实现与知识内容分别承担职责；暂不决定框架或详细目录分类。
5. 继续交付单文件 HTML 时，可在制作阶段使用准备库，在成品中内嵌所需实现。具体封装后续讨论。

### TKCode.Arc：共享设计基础上的成品组件

> **具体参考与核对事实**
>
> [TKCode.Arc README](https://github.com/AIDotNet/TKCode.Arc/blob/main/README.md)说明这是基于 AtomUI 的 Avalonia 组件库，参考网页端 Arc。
>
> [Core](https://github.com/AIDotNet/TKCode.Arc/tree/main/src/TKCode.Arc.Core)包含 Theme、Motion、Primitives 等公共部分；实际主题源码组织了背景、文字、边框、强调和状态颜色，动效部分具有弹簧与过渡实现。组件目录覆盖按钮、卡片、导航、内容、图表和文字效果等类别。
>
> [Button 实现](https://github.com/AIDotNet/TKCode.Arc/blob/main/src/TKCode.Arc/Buttons/Button/Button.cs)公开了 Variant、Size、IsLoading 等属性，既有外观变体，也有状态和响应行为；它不是只提供一段孤立的按压动画。仓库另有 Gallery、Demos 和 Docs。

可借鉴的是一套已设计好的组件在公共视觉与动效基础上提供明确的属性、状态、变体和用法。TKCode.Arc 是桌面技术实现，不可直接当成 HTML 的 JS 组件使用；其组织与表达方式可以作为参考。

可借鉴的是“从目录找到合适成品 → 观察表现与用法 → 取得源码并调整内容”的使用方式。是否采用 React、安装分发工具或接入 MCP，尚未决定，不因参考此项目自动采用。

### 对本项目理解的修正

此前试作把工作较多集中于序列插入、关注、范围和关系等局部机制，并按独立批次交付。这些代码可以保留，且其已有正向评价继续有效；但它们只覆盖库中少量条目，不能据此认定已经达到用户所说的组件库形态。

基于两个指定参考，当前的修正理解是：为 HTML 笔记准备一套可供 Agent 选取、组合和调整的成品组件与设计资源，兼顾现成表现、可改内容、动效、必要状态与变体、共享基础以及统一的效果和用法入口。具体组件目录、技术栈和复用现有库的范围，仍需对齐，不直接把这段推导变成已批准的新开发范围。

此前“不围绕一个机制制作三套主题”的纠正，不排斥组件库拥有共同的配色、字体、间距、层次和动效基础，也不排斥有实际用途的组件变体。不能由此把组件资产一律收窄为极简批注工具。
