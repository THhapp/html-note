## 二、资产描述需要区分的用途

### 生成前：资产需求描述

告诉执行 Agent 这项资产解决什么表达问题、组件里有什么、变化如何发生、哪里需要停留，以及组件自身需要维持的行为与可辨认性。整页配色、页面容器和全页文字排布属于笔记组装层，不自动成为组件约束。

“流畅、精致、可复用”等词可表达倾向，但还需要可观察的结果。例如，不能只写“插入动画自然”，还要交代新增元素如何定位、旧元素怎样让位、结果停住后怎样辨认变化。

### 生成后：资产使用说明

根据实际实现说明入口、支持的数据、可修改参数、依赖、预览位置、已验证表现和用户认可范围。不能把生成目标直接写成已经支持的能力。

[shadcn registry item 规范](https://ui.shadcn.com/docs/registry/registry-item-json)区分名称、描述、文件和依赖等信息；此前的 [Storybook stories](https://storybook.js.org/docs/writing-stories/index)则提供参数化状态示例。可借鉴其可发现与可使用的信息组织，不要求安装对应框架或提前规定 JSON 清单。

两类信息可以在同一份资产说明中分区保存，无须为每轮新增状态文档。当前优先把生成前的需求写清楚。

## 三、一份描述怎样具体起来

以下是候选写法，不是所有资产都必须填满的固定表格。

- 说明用途与适用场景，便于 Agent 判断何时选它。
- 明确对象和关系，保留知识表达所需的语义。
- 描述关键状态、变化路径和停留结果，不能只列动作名称。
- 区分可替换内容与需要维持的行为。
- 对参考分别写明借鉴什么，避免复制整套颜色、布局或控制方式。
- 用可观察现象说明验收，减少“高级、好看、舒服”等难以独立执行的判断。
- 生成后补入实际入口与能力，继续区分设计要求、程序检查和用户体验认可。

## 四、资产需求描述草案：序列中的条件插入

这一节是供讨论的资产描述示例，不是已发给独立 Agent 的开工任务书。

### 简短检索描述

序列中的条件插入：展示选定位置与插入前后的对象关系，支持稳定步进和回看。用于数组、字符串或数据流的局部讲解。以上为生成目标，实际适用范围待实现后验证。

### 需要表达的机制

读者能看清为什么在这里发生插入，新增元素放在哪里，原有元素如何让位，以及操作完成后原序列的对应关系。只演示这件局部事情，不扩展为完整课程笔记。

### 对象与示例内容

画面包含一组原有元素、选定的位置或条件提示，以及待插入元素。可用 A、B、C 等简单字符说明；这些只是预览数据，不把固定字符、固定数据长度、PPP 或“五个 1”写死为所有用法。

### 变化与稳定状态

在插入前能够辨认选定位置或依据。由读者推进后，新元素进入目标位置，相关元素配合让位；结束后稳定停留，新增位置、原有对象及必要说明仍可核对。需要独立理解的中间状态可设置停点，不固定动作数量或时间。

回退恢复对应的插入前状态，重看能够复现本次变化，不能因反复操作而重复插入或让内容与字幕失配。

### 视觉与文字

当前关注和本步变化有主次，对象身份在前后保持可追踪。组件内的必要标记和文字与对象关系清楚、容易辨认。具体颜色、形状、线条与字体组合可随使用场景调整，不在本项需求中规定整页主题、页面底座或整页文字排布。

### 替换与比较

生成目标包括替换数据内容、目标位置、新元素文字及解释。描述替换能力时不预先规定代码接口，实际支持范围由实现与验证补齐。

多个视觉候选使用同一机制与相同数据。切换风格保持当前步骤，重看动作由用户触发，避免同时播放多个候选争抢注意。

### 参考借鉴点

AutoAnimate 用于参考插入和让位的连续性；Rough Notation 与 Manim 的范围标记用于参考关注位置及就近说明。各参考分别说明需要学习的能力；是否采用其现有视觉风格在样片中比较，不默认把参考的全部外观与交互打包采用。

### 可以观察的结果

不看过渡、先读文字再看图时，仍能找出新增元素、插入依据和操作结果；前后对象容易对应；回退与重看状态一致；切换风格后能继续比较同一结果；组件中的必要标记和文字能与对应对象关联。

## 五、与独立执行提示词的关系

资产描述解决“做什么、怎样表达”。完整执行提示词还需要明确实际输入、允许修改的目录、交付物、共享能力和验收范围。

如果采用独立总控与子 Agent，建议总控先统一状态、字幕、样式和预览切换的最小约定，再给各实现者分配独占文件与任务，避免每人各造一套播放器。该调度方式仍是任务书候选，本轮未调用或创建执行 Agent，也未开始实现。
