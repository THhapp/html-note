本页是作者开工路径：一次查询取得通用路径选择，按任务选静态组件、固定区域配方、跨区域协调或自定义连续画面，再正常速度观察并离线交付。详细 API、参数与生命周期以[公共编排层](公共编排层.md)为准；本页不复制整套接口。

## 作者开工：一次查询选对路径

先取开工包：

```powershell
node scripts/query.mjs show authoring:start --json
```

它返回通用的作者开工入口：取用指南、作者示例、最小连续画面宿主、实现源码、完整示例与本地核对入口；不绑定某个具体组件或 Table 做法。需要具体组件、配方或某条接法时，再按 `show` 返回的资源与条目补取，不必先通读全部资料。

开工顺序：

1. 执行 Agent 是作者：从源材料判断要理解的问题、知识重点、观察关系与表达方式；查询、配方和运行层不自动推断这些。
2. 运行上面的开工查询；只有缺具体能力时才 `search`/`show`/`read` 单条。
3. 选路径：静态组件、固定区域配方、跨区域协调或自定义画面（见下表）。
4. 先贯通最不确定的代表过程，优先做一个真实停点链，不先铺满页面。
5. 用正常速度 `next()`/`replay()` 观察依据、主要变化和结果的承接；有具体疑点再补 probe。
6. 需要离线交付时按“加载与离线交付”内联；保留作者源文件与重新生成方式。

| 本次要做 | 先取 | 继续 |
| --- | --- | --- |
| 单个静态组件/图形，无演示运行层 | `show <ID> --context independent` | 组件 API，直接 mount/update |
| 固定区域的多个停点 | 配方 `focusWorkbench` / `stagePacket` / `diagramTable` / `repeatStages` | [作者入口与配方](#作者入口与配方) |
| 跨区域协调：依据与结果分别在不同区域，需要先后承接 | 公共 attention + 实际组件条目 | [具体分支：跨区域承接](#具体分支跨区域承接) |
| 自绘画面、局部变化，希望少写 Adapter 胶水 | `public:continuous-adapter` | [自定义连续画面接入](#author-custom-scene) |
| 自备整个舞台 | `NoteDemo.create` | [公共编排层](公共编排层.md) |

配方和公共层的完整参数不在本页复制；以查询返回资源和[公共编排层](公共编排层.md)为准。

## 查询与本地观察

查询读维护源，不打开浏览器；观察打开真实页面并收集页面事实。

```powershell
node scripts/query.mjs info
node scripts/query.mjs search 路径选择
node scripts/query.mjs show authoring:start --json
node scripts/query.mjs show D01 --context independent --json
node scripts/query.mjs read authoring:start guide --json
node scripts/query.mjs show recipe:composition --json
node scripts/query.mjs load D01 --json
node scripts/query.mjs load recipe:composition --with C06 D08
```

- `search` 按 ID、名称、别名、用途和检索词匹配；零结果时的 suggestions 只来自真实拆词命中，不是热门推荐，也不代表库缺少能力。
- `show` 返回条目的上下文、依赖、资源和短用法；可用上下文以实际返回为准。作者开工用 `authoring` 上下文；`public:*` 接法按返回用 `public` 上下文（如 `public:attention`、`public:table-adapter`），不套用 authoring。
- `read <id> <资源键>` 读取条目声明的资源；`--offset`/`--limit` 分页，章节止于下一条同级或更高级标题。常见键：`api`/`source`/`example`/`fragment`/`full`/`minimal`/`guide`/`verify` 等，实际以条目声明为准。

本地观察：

```powershell
node scripts/inspect-note.mjs "examples/authoring/index.html" --json
node scripts/inspect-note.mjs "examples/authoring/index.html" --session "window.AuthoringDemoSessions.crossRegion" --probe "D:/path/probe.mjs" --json
node scripts/inspect-note.mjs "D:/path/成品.html" --selector ".nblk-demo-stage" --screenshot "D:/path/stage.png" --json
```

- `--frame <frameId>` 只调用公开 `session.go(frameId)` 恢复停点；它证明静态落点，不证明动画。过程用 probe 内 `next()/replay()` 真实推进；`inspect.step('go', 'frame-id')` 的第二个参数是实际字符串 Frame ID。
- `--selector <CSS选择器>` 可只截演示区域/元素；默认唯一匹配，多个用 `--selector-index`，不存在会明确报错。成品 HTML 相对 cwd，截图/probe/browser 用绝对路径；完整参数以 `--help` 为准。
- probe 导出 `default async ({ page, inspect }) => ...`，与页面同页；`inspect.sample()` 用于采样，截图只在显式调用时写文件。
- 输出区分工具执行事实、页面观察和 probe 结果；打开成功不等于作品验收通过。详细参数见[公共编排层 §8.2](公共编排层.md#author-inspect-note)。

## Focus 与可读内容：先有依据，再展开

有公共 Focus 时，按实际阅读顺序组织每个落点。

- 落点从第一眼就应有可读依据或变化内容。保留来源值、可读标签或相关证据；需要在放行时切换文本或恢复强调的，可以在 progress 的 `onStart` 同步交接，再动画局部提示。
- 同一次要理解的多个对象，用真实容器或 `unionRange` 一起框入。依据即使没变也可以入框；辅助状态可在框外同步。
- 需要先后阅读的区域各用自己的效果组，由首次要读它的落点放行。只观察已经可读的内容时用 `groups: []`。在 `commit` 保留来源视觉，主要变化由受控效果推进，并以 `gate:'ready'` 表达何时可承接。

[离线短例](../dist/Focus顺序短例-预览.html)依次呈现借阅请求、馆藏依据与两项登记结果、到期回执。中间一次框入三个相关对象，回执等自己的落点才更新并恢复正常强调。用真实 `next()` 在正常速度下看落点、停留和离开，再针对疑点读位置、文本或样式。[示例源码](../examples/attention-order/index.html)

## 加载与离线交付

~~~html
<link rel="stylesheet" href="./dist/note-library.css">
<script src="./dist/note-library.js"></script>
~~~

整库已经包含现有公开组件与 NoteDemo，作者入口只需整库加一份数据/启动文件。若要控制体积，加载 `dist/modules` 下目标模块及其声明依赖；闭包按查询结果的 `dependencies`/`regionDependencies`，同页不要重复加载整库和相同模块。

现有单文件内联器接受任意本地经典脚本 HTML 入口：

~~~text
node scripts/build-demo-preview.mjs --template <作者index.html> --output <独立HTML>
~~~

它只内联入口已经列出的资源，不计算未列出的依赖，也不生成知识内容。开发预览与离线文件应消费同一份资源入口；作者入口当前直接引用整库 JS/CSS，因此同模板生成的预览与开发页一致。旧示例的双入口是历史组织，不是作者必须遵守的要求。

## 作者入口与配方

[examples/authoring/index.html](../examples/authoring/index.html) 是普通作者入口：整库 + `data.js` + `boot.js`。现有实例按用途分为矩阵/读数（`focusWorkbench`）、普通 DOM 交接（自定义 Adapter）和跨区域承接（`diagramTable` + attention 行组）。数据在 [data.js](../examples/authoring/data.js)，启动在 [boot.js](../examples/authoring/boot.js)。

配方源码在 `src/demo/recipes.js`，都只返回 `NoteDemo.mount` 输入，不拥有播放器：

- `focusWorkbench(options)`：矩阵/单行读数类区域骨架、slot 收集与 layout.cleanup。带 `title` 或 `meta` 的 `process` 项会把标题和内容组织成独立区块。数据、视图、scene、after 与 attention 由作者给出。
- `stagePacket(options)`：阶段轨 + 报文流 + 读数/状态的主区纵向结构；至少提供 stage 或 packet，其他区域可省。
- `diagramTable(options)`：图形 + 状态表的主区网格结构；至少提供 diagram 或 table，页脚可放读数/状态。跨区域示例即此配方。
- `repeatStages(options)`：作者给 bindings/initial/items/expand，配方补稳定 Frame id、caption 回退并调用 `NoteDemo.compile`；不生成第二套 Frame/Transition。

`stagePacket`/`diagramTable` 可给 `density:'compact'`，只缩小配方外壳的 gap、padding、readout/head 间距，不改内容、字幕或动效。四个配方都不推断知识因果、不生成 scene.attention；变化 binding、观察顺序与说明由作者声明。自定义图形效果工具与交接边界见[公共编排层 §5.5](公共编排层.md#author-scene-adapter)和[传播示例](../examples/propagation/index.html)。

### 具体分支：跨区域承接

“依据 → 主要变化 → 结果”落在不同区域、需要先后承接时，用公共 attention 组织观察顺序；具体组件、布局与行组接法按条目当前返回：

- 先按通用路径选组件/配方与 scene 结构，再用 `scene.attention` 指向依据与结果；`public:attention` 给出目标、分组与 range 的当前契约。
- 表格新行可由独立 Binding 的 attention 行组放行；这只是具体分支，不是 Table 的通用接法，也不成为使用 attention 的前提。Table 的视图、目标与行组边界查 `public:table-adapter`。
- 任何 Binding 的视图变化都必须列入该步 `scene.bindings`；辅助状态如何提交（快照式 cut 或 update）与是否需要 Focus 巡视分别判断，不要求一律 cut、逐项巡视或数字动画。
- 对象运动、对齐窗口、范围变化等自然引导已能对应依据与结果时，不必再用公共 attention；局部高亮只是局部提示，不自动等同完整跨区域协调。知识重点与观察顺序由作者判断。
- 可运行示例见[作者入口](../examples/authoring/index.html)的“跨区域承接”示例与 [data.js](../examples/authoring/data.js)；机制细节见[公共编排层 §5.1](公共编排层.md#5-1-内置-adapter-的视图与目标)、[§5.3](公共编排层.md#author-attention)。

## 多列、泳道与状态卡

多列泳道、状态卡是内容结构，不是天然要新增一套公共组件。先用现有布局和内容组件表达；只有在多个作品出现同一稳定骨架时再抽配方：

- **多列泳道**：在窄容器里不要把固定五列继续压成每列几十像素。可让容器局部横向滚动（`NoteUI.Inline({wrap:false})` 或 `NoteUI.ScrollArea`，或宿主自己的 `overflow-x:auto`），或按阅读顺序改为纵向分组。默认舞台在 ≤760px 时会把字幕与控件吸底，但画面本身仍按作者 layout 重排/滚动；吸底不替作者解决列宽。
- **状态卡/读数**：先组合现有 `NoteUI.Metric`、`NoteUI.Badge`、`NoteUI.Table`、`NoteUI.Progress` 等；保留“静态摘要 / 随过程变化的事实 / 当前需要观察的主要变化”三种语义，不要把状态卡的全部更新都塞进同一个 focus 组，也不要让辅助摘要抢先显示完成事实。状态卡栏是纵向堆叠时可直接复用 layout 组件；像 V13 这样同时包含“交换表/查表结论/转发端口”的复合栏，仍应由作者场景适配器组织，不强行抽成公共组件。
- **配方边界**：`focusWorkbench` 提供依据—处理—读数区域；`stagePacket` 提供阶段/报文/读数；`diagramTable` 提供图形+表。泳道板没有进入公共配方——DeepSeek 试作的五列流程快照是内容特化，V13 的纵向状态栏也不是同一种布局；本轮不新增组件或配方，避免把单一作品结构固化为公共 API。
- **实测参考**：DeepSeek 试作在 390px 下五列各约 46px、卡片文字逐字换行，属作者固定列宽+缺少窄屏策略；应在内容层改为局部横向滚动或按列重排。V13 390px 的纵向状态栏可读，默认舞台吸底页脚让字幕和操作仍在视口内；V10 390px 的宽 SVG 由作者局部横向滚动，正文表溢出属作者页面样式，不是默认舞台尺寸。

## 槽位、布局与作者简写

- 自定义 layout 返回 `{ root, slots, cleanup? }` 时按 Binding 的真实插槽名取用；返回单个 Element 的旧用法仍映射为 `main`。
- `NoteDemo.collectSlots(root, required)` 只收集 `[data-demo-slot]`；重复或缺失直接报名称错误，不猜区域对应关系。
- `layout.cleanup` 在正常销毁和取得返回值后的挂载失败中恰好调用一次；layout 回调在返回前抛错时，内部资源要由该回调自行释放。
- `NoteDemo.compile({ bindings, initial, steps })` 按整个 Binding 替换视图生成完整 Frame/Transition，补齐 after 引用的稳定参与者，保留 reveal 与 scene.attention，不推断 actions，也不把未声明变化静默降级为 cut。
- `NoteDemo.timingFacts.watch(session)`/`collect()` 按需观察 focus 到达、效果启动、ready、finished；默认关闭、只在内存、不写文件。

## 主题、文字与窄屏覆盖

默认舞台和常用组件使用 `--hnv-*` tokens。宿主把覆盖写在演示容器或其祖先上，作用域只覆盖该子树；不要写全局 body 主题：

```html
<div data-demo-host style="--hnv-color-accent:#7a4bd6; --hnv-color-accent-soft:#f0ebff"></div>
```

`NoteDemo.mount` 的本地文字入口包括 `labels`（`prev/next/replay/reset/progress`，`progress` 可为字符串或函数）、`captionLabel`、`title`/`label`；布局入口包括 `maxWidth`、`minStageHeight` 与 `captionReserve`。默认 `.nblk-demo-stage__caption` 上限为 `72ch`（当前桌面字号约 620px），这是默认阅读宽度而不是强制统一字数；具体篇目可在自己的容器上用 CSS 覆盖字幕宽度。窄屏（≤760px）默认舞台的页脚（字幕+控件）吸底，长画面继续随页面滚动；这不是固定等待，也不替代 `session.getState().phase`。

覆盖后至少核对：主按钮/进度/字幕标签的实际文字与可访问名称、颜色是否来自覆盖的 token、默认字号/宽度是否仍可用。根部覆盖不自动修改 `NoteUI` 独立组件的局部样式；需要时在对应组件容器上声明。

## 依赖与加载

- 导航/开工条目只给出路径与资源，不声明运行依赖；按返回的 `guide`/`example`/`minimal`/`full`/`verify` 等继续。
- 配方骨架、具体区域组件和具体示例的依赖分开：`show` 在条目上返回 `dependencies` 与 `regionDependencies`，按实际返回的闭包加载；不同示例/配方不共享一套手写模块清单。
- 作者另选的组件要把该组件模块及其声明的依赖补上。整库加载与按模块加载使用同一套查询结果，同页不要重复加载整库和相同模块。
- 需要可复制清单时运行 `load`：`load D01` 组件默认独立/mount 上下文；`load recipe:composition --with C06 D08` 把配方骨架与实际 table/flow 区域组件合并；`load I07 --context mount` 只取公共运行/默认舞台闭包。输出路径相对库根，`--json` 给出 entries/context/modules/styles/scripts/wholeLibrary，便于脚本消费。导航入口本身不声明依赖，先用 `show authoring:start` 选具体条目；上下文不匹配时按报错列出的 key 重试。

## 公共层与作者的职责

使用 NoteDemo 时，公共层负责 Frame/Transition 编排、常驻组件、推进/回退/重看、默认舞台控件与字幕、受控视觉接管、attention 焦点与效果组门控、取消/错误生命周期与恢复；作者提供对象稳定 ID、知识数据、视图与恢复、字幕、focus/changed、必要 after、观察顺序、来源视觉与宿主布局。

知识重点、理解目标与观察关系由作者根据源材料判断；查询、配方和运行层不自动推断。公共层不猜知识因果、不从快照推断动作、不统一支持所有图形变形；attention 只接受明确列出的目标，局部高亮不自动等同完整协调。直接组合组件时，宿主自行管理子组件销毁、常驻实例、按钮焦点与布局资源；NoteDemo 管理 Binding 拥有的组件生命周期。详见[公共编排层](公共编排层.md)。

## 能力边界与维护

- 公共层现有能力以[公共编排层](公共编排层.md)为准；消费测试是可复现入口，不是第二套功能清单。
- `attention` 只接受明确列出的目标，不从内容变化自动推断教学重点；未声明的变化不自动降级为 cut。Table 行组等具体接法以对应条目当前返回为准，不作为通用 attention 前提。
- 维护源只在 `src`；`dist` 与根 `registry.json` 统一构建，不手改。

## 自定义连续画面接入

普通自定义画面优先用 `NoteDemo.sceneAdapter.define`：作者实例负责绘制/恢复、真实状态读回、目标查询与局部变化计划，helper 组织 Adapter 契约、提交顺序、减少动效与 timing。只有需要直接控制完整 Adapter 契约（`prepareChange`/`targets`/`sourceElements`/`facts` 等）时才用原生 BindingHandle；两者不是迁移关系。完整参数与差异见[公共编排层 §5.5](公共编排层.md#author-scene-adapter)，最小可运行宿主为 [minimal.html](../examples/continuous-scene/minimal.html)。

### 最小接法

整库加载后：

~~~html
<link rel="stylesheet" href="../../dist/note-library.css">
<script src="../../dist/note-library.js"></script>
~~~

```js
var definition = {
  initialFrameId: 'initial',
  bindings: { scene: { adapter: 'my-scene', slot: 'scene' } },
  frames: [
    { id: 'initial', caption: '初始状态', views: { scene: { value: 0 } } },
    { id: 'changed', caption: '一次局部变化', views: { scene: { value: 1 } } }
  ],
  transitions: [{
    from: 'initial', to: 'changed',
    scene: {
      bindings: [{ binding: 'scene', mode: 'update' }],
      attention: { targets: [{ binding: 'scene', query: { part: 'value' }, groups: ['value'] }] }
    }
  }]
};
var session = NoteDemo.mount(document.querySelector('[data-demo-host]'), {
  definition: definition,
  adapters: { 'my-scene': myAdapter },
  layout: function (container) { /* 建 data-demo-slot="scene"，返回 { root, slots } */ }
});
```

`sceneAdapter.define(spec)` 常用字段：`name` 与 adapter 名一致；`sceneModes` 常用 `['update']`，`defaultSceneMode` 必须在列表中；`sceneTimingDefaults` 可给稀疏 timing；`normalizeView(input, options)` 返回 model 或完整的 `{ model, cues }`；`mount(host, options)` 返回作者实例，至少提供 `restore(model, view)`、`readModel()`、`target(query)`、`planStep(input)`、`destroy()`。

作者实例与提交：`commit()` 必须同步提交完整目标；未放行组保持来源视觉，`effects` 只推进已放行组；`groups()` 声明本步真正变化的组，每个 EffectSpec 必须属于某个声明组；`cleanup()` 只释放本步临时资源，不承担最终显示；reduced 跳过 effects，`commit()` 直接呈现目标终态；`restore` 直接呈现完整停点，不依赖 effects。需要 `sourceElements()`/`handoff:'hold'` 时按完整契约使用，不伪造来源。

```powershell
node scripts/inspect-note.mjs "examples/continuous-scene/minimal.html" --frame changed --session "window.__inspectSession" --json
```
