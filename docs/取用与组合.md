## 文档与资料如何取用

| 当前要解决的问题 | 先取哪份资料 | 取得什么后继续 |
| --- | --- | --- |
| 这篇 HTML 要讲什么、交付什么 | 源 MD 预留和本次任务 | 问题、对象、理解目标、允许范围与交付形式 |
| 阅读和演示应该遵循什么 | [设计共识](设计共识.md) | 视觉聚焦、稳定字幕、停点与必要解释等已有要求；有效上下文可沿用 |
| 不知道已有资产叫什么 | 先跑 `node scripts/query.mjs search <用途/名称>`；未命中时看 suggestions 或 `node scripts/query.mjs info` | 用途、关键边界、相近能力区别及后续入口 |
| 已知具体组件，准备调用 | 对应模块 API、源清单和最小示例 | 当前调用上下文、必要参数、依赖与限制 |
| 需要多停点、内容过渡或聚焦协调 | 本页选入口，再取[公共层 API](公共编排层.md)中所需契约 | 知道公共层接管什么、作者仍需提供什么，取得对应接法 |
| 需要理解公共层为什么这样设计 | [架构与接口](架构与接口.md) 与[公共编排层](公共编排层.md)的设计说明 | 分层、时序和实现取舍；普通调用不必先通读设计资料 |
| 准备离线交付 | 本页加载说明和[构建与分发](构建与分发.md) | 资源入口、生成命令和实际输出 |

新接手时先用本页确定入口，已有有效上下文直接继续。语料用于定位和选择，模块 API 与公开契约负责准确调用；示例提供结构参考，源码用于接口不清、资料冲突或具体故障。发生冲突时核对对应维护源，不把旧任务中的目标当作现有支持范围。

查询入口是 `scripts/query.mjs`：默认读取脚本所属库，也可用 `--root <库目录>` 指定。组件身份、用途、限制和依赖来自 `src/manifests/*.json` 的条目及 `query` 元数据；配方、公共接法、工具和示例来自 `scripts/query/entries.mjs`。查询不读浏览器包、不启动服务，一次调用后退出。

```powershell
node scripts/query.mjs info
node scripts/query.mjs search 矩阵
node scripts/query.mjs search 设备端口连接 --json
node scripts/query.mjs show D01
node scripts/query.mjs show recipe:focusWorkbench --context recipe
node scripts/query.mjs read D01 api
node scripts/query.mjs read D01 source --limit 80
```

- `info`：库位置、组件/模块/资料条数、命令入口。
- `search`：ID、名称、别名、用途和检索词匹配；精确结果与零结果 `suggestions` 分开，suggestions 只来自实际拆词命中，不是热门推荐。
- `show`：取用包；默认上下文由入口决定，可用 `--context` 选择 `independent/scene/create/mount/recipe/public/authoring/tool`。可用上下文以实际返回为准。
- `read <id> <资源键>`：读取条目声明的资源，常见键有 `api`/`source`/`guide`/`example`/`fragment`/`full`/`minimal`/`control`；`--offset`/`--limit` 分页，`--file` 读明确文件。路径都从库根解析，章节读取止于下一条同级或更高级标题。

已有明确 ID 或公开名时直接 `show`，不必先 `info` 或 `search`。参数与环境边界以 `node scripts/query.mjs --help` 和实际 JSON 为准。

## 查询与本地观察

查询和观察是两个独立入口：查询读维护源，不打开浏览器；观察打开真实页面并收集页面事实。

```powershell
node scripts/inspect-note.mjs "<成品.html>" --json
node scripts/inspect-note.mjs "<成品.html>" --screenshot "D:/path/out.png" --width 860 --height 1000
node scripts/inspect-note.mjs "<成品.html>" --probe "D:/path/probe.mjs" --json
node scripts/inspect-note.mjs "<成品.html>" --frame <frameId> --session "window.__inspectSession" --json
```

- 页面需要驱动时暴露 `window.__inspectSession = session`，或用 `--session` 指定明确表达式。
- `--frame` 先用公开 `session.go(frameId)` 恢复指定停点并确认 `settledFrameId`/phase，再执行截图/probe；未知 Frame、空参数或会话缺失会明确失败，不退回初态冒充定位成功。
- `go()` 只证明停点恢复；动画、焦点到达、内容放行、取消和恢复过程用 probe 内 `next()/replay()` 真实推进。时序疑点用 `inspect.sample()` 采样，不靠多张静态图猜过程。
- probe 导出 `default async ({ page, inspect }) => ...`，与页面同页；`inspect` 提供 `state/read/evaluate/start/step/waitIdle/waitFor/sample/box/screenshot/observe`。只在显式调用 `screenshot(绝对路径)` 时写文件。
- 输出区分工具执行事实、页面观察和 probe 结果；打开成功不等于作品验收通过。长 JSON 重定向到 UTF-8 文件后解析，不用截断输出重跑整轮。

参数以 `--help` 和实际返回为准；完整公共层观察 API 见[公共编排层 §8.2](公共编排层.md#author-inspect-note)。

## 优先选合适的入口

| 目的 | 当前入口 | 职责 |
| --- | --- | --- |
| 查能力和独立调用 | `query.mjs`、registry、模块 API | 通用 UI、静态知识表达直接使用，不必经过演示运行层 |

## 作者入口与配方

[examples/authoring/index.html](../examples/authoring/index.html) 是普通作者入口的实例：只加载整库、一份数据与一份启动文件。数据在 `examples/authoring/data.js`，启动在 `boot.js`；不写播放器、不猜教学因果。

配方源码在 `src/demo/recipes.js`，最小用法：

~~~html
<script src='./dist/note-library.js'></script>
<script>
  var demo = NoteDemoRecipes.focusWorkbench({
    bindings: { /* Adapter 与 slot */ },
    initial: { id: 'start', caption: '…', views: { /* 每个 Binding 的完整视图 */ } },
    steps: [ { id: 'next', caption: '…', replace: { /* 按整个 Binding 替换 */ },
      scene: { bindings: [ /* … */ ], attention: { targets: [ /* 按注意顺序 */ ], stepDuration: 240 } } } ],
    sources: [ { slot: 'matrixA', title: '矩阵 A' } ],
    process: [ { slot: 'terms' } ],
    readout: { slot: 'sum', title: '逐项相加' },
    result: { slot: 'result', title: '结果' }
  });
  NoteDemo.mount(document.querySelector('[data-demo-host]'), demo);
</script>
~~~

`focusWorkbench` 只返回现有 `NoteDemo.mount` 输入，不拥有播放器。它负责区域骨架、slot 收集和 `layout.cleanup`；数据、视图、scene 参与者、after 和 attention 仍由作者给出。矩阵与单行读数两个例子共用这一配方，换内容时不应把它当成固定模板。

同一源码还提供三种区域/状态配方：

- `NoteDemoRecipes.stagePacket(options)`：阶段轨 + 报文流 + 读数/状态的主区纵向结构；至少提供 `stage` 或 `packet` 区域，其他区域可省。
- `NoteDemoRecipes.diagramTable(options)`：图形 + 状态表的主区网格结构；至少提供 `diagram` 或 `table` 区域，页脚可放读数/状态。
- `NoteDemoRecipes.repeatStages(options)`：作者给 `bindings/initial/items/expand`，配方补稳定 Frame id、caption 回退并调用 `NoteDemo.compile`；不生成第二套 Frame/Transition。

`stagePacket` / `diagramTable` 可选 `density:'compact'`：只缩小配方外壳的 gap、board/readout padding 与 head 间距，不改内容、字幕或动效；`flow-stage`/`flow-packet` 可另在 Binding.options 传 `density:'compact'` 收紧各自内部几何。`examples/flow-composition` 两段都使用 compact，并在 1366×768 / 1280×900 下按演示 section 起点对齐做同屏观察。

三者和 `focusWorkbench` 一样只返回 `NoteDemo.mount` 输入。完整中性实例见 [examples/flow-composition](../examples/flow-composition/index.html) 与 `dist/流程组合-预览.html`。

自定义图形接入时，demo-runtime 还提供 `NoteDemo.effects` 窄工具：`captureContent` / `createGhost` / `planValueSwap` / `captureStyles` / `planCueChanges` / `rectOf` / `unionRange`。`unionRange(refs)` 把移动对象和它的轨迹/标签等真实元素合成观察区域，返回 Definition 可用的 union range，不另建测量或动画。EffectSpec 支持 `type:'progress'` + `update(progress)` 驱动 SVG 数值属性（公共 scene 统一启动、取消、finished 与清理），作者不需要依赖 `NoteDemoInternals` 或自建 rAF。完整接入示例见 [examples/propagation](../examples/propagation/index.html) 与 `dist/传播过程与局部过渡-预览.html`。

局部动画结束和来源观察需要显式交接，否则很容易出现“动画结束回落隐藏、整步结束才重现”或“旧层一提交就消失”：

~~~js
// PreparedChange 内：commit 前声明本步仍要观察的来源对象；公共 scene 捕获并在 commit 后保持，
// 到该 Binding 第一个内容轨道启动时释放。
sourceElements: function () { return [sourceLabel]; },

effects: function (ctx) {
  return [{
    el: targetLabel,
    keyframes: [{ opacity: '0' }, { opacity: '1' }],
    options: { duration: ctx.timing.enterDuration, easing: ctx.timing.easing },
    group: 'reveal',
    gate: 'ready',
    handoff: 'hold'   // 正常完成后由公共 scene 保持末帧到收束；取消仍恢复来源
  }];
}
~~~

`sourceElements()` 只接受 commit 前后仍在 DOM 中的真实元素；公共层只恢复 `opacity/visibility/display`，父级整体隐藏不在保证范围。`handoff:'hold'` 只用于目标内容类 WAAPI 效果；退出副本、提示脉冲和 progress 的终态不要声明它。普通 DOM 交接见[作者入口](../examples/authoring/index.html)第三节；SVG 的 `handoff:'hold'` 与真实运动对象跟随见[传播示例](../examples/propagation/index.html)。来源保留用 `sourceElements()`，当前由普通 DOM 小例示范。

声明 `scene.attention` 的 scene 自动使用公共的较慢内容节奏（内容 enter 560 / cue 680 / reveal 420 等），普通 scene 仍使用原默认。默认舞台使用**会话级 Focus**：首次在起点软出现，按 targets 顺序迁移，最后停点快速弱化保留（虚线/低强调），正常“下一步”从弱化位置承接；取消、回退、重看、重来、跳转与销毁按导航策略隐藏或重启。Focus 的 `whenArrived()` 与 scene 的真实 ready 决定启动和承接，作者不要在 target 上另写观察计时。

target 可选字段：`groups`（省略=整 Binding 门控；`[]`=只观察不启动；非空=放行命名效果组）、`holdDuration`（0 有效；观察型目标从到达起默认 `stepDuration`，触发内容的目标默认 ready 后 0 额外停留，最后落点不倒计时）、`range`（`{kind:'local',dx,dy,width,height}`、相对形式 `{kind:'local',outset}`/`{kind:'local',inset}`，或 `{kind:'union',refs:[...]}`，把焦点框变成事件附近的合理观察区域）。local 的相对形式使用 CSS 像素、只能二选一且不能与绝对字段混用；union refs 可写 `optional:true`，缺失的可选成员跳过，必需成员或无效几何明确报错。断开/`display:none`/`visibility:hidden` 元素不算有效目标；`opacity:0` 但有真实矩形仍可用，SVG 一维线有效，零面积点必须显式范围。`table` 与四个 flow Adapter 已拆出细粒度效果组（`cell/row`、`stage/bypass`、`message/participant`、`segment/range`、`link/device`）；其他内置 Adapter 是否拆组以 Adapter 文档为准。自定义 Adapter 声明 `PreparedChange.groups()` 后，可用 `spec.group` 把图形、文字、提示与局部副本完整归入同一组，再由不同观察目标分别放行。

## 槽位、布局与作者简写

- 自定义 layout 返回 `{ root, slots, cleanup? }` 时，公共层不再强制 `main` 别名；每个 Binding 按自己的 `slot` 取得真实命名插槽。返回单个 Element 的旧用法仍映射为 `main`。
- `NoteDemo.collectSlots(root, required)` 只收集 `[data-demo-slot]`，重复或缺失直接报名称错误，不猜区域对应关系。配方使用它；自定义 layout 也可以直接使用。
- 已成功取得的 `layout.cleanup` 会在正常销毁和取得返回值后的挂载失败中恰好调用一次。layout 回调在返回前抛错时，公共层没有 cleanup 可调用，内部资源必须由该回调自行释放；配方在收集 slot 失败时会自行销毁已建布局组件。
- `NoteDemo.compile({bindings, initial, steps})` 是纯作者编译辅助：按整个 Binding 替换视图，生成每个完整 Frame 和相邻 Transition；差分使用 Adapter 规范化结果，补齐 after 引用的稳定参与者，保留 reveal 和 scene.attention，不推断 actions，也不把未声明变化静默降级为 cut。完整 Definition 仍是高级入口和可检查产物。

## 公共演示层已经管理什么

- Frame提供完整可恢复视图，Transition指定可选scene或actions。
- 普通推进保留组件实例；回退/go/reset 直接恢复明确停点，重看按入边重演；默认舞台“上一步”按 replayPreviousStep 从上一停点入边的初态重播（允许焦点跳变），`session.prev()` 仍保持直接恢复上一停点。
- scene同步提交完整目标，保持未启动源视觉，按真实句柄完成；相关变化可同窗，必要因果用 after，同一 Binding 的局部变化可用命名效果组分别放行。
- scene.attention 使用会话级焦点框，不新增文字标签、不默认遮罩或滚动；最后停点弱化保留，正常下一步承接；取消/回退/重看/跳转按导航策略隐藏或重启，减少动效时不迁移也不增加等待。观察可用 groups 区分“看哪里”和“放行什么”，用 range 表达事件附近范围。
- 默认舞台稳定下方字幕与控件，执行中下一步灰色不可用，取消和错误沿统一生命周期处理。
- Frame标记按逻辑TargetRef解析；scene内有稳定id的标记可复用，字幕与必要标记计入最终收束。
- 当前timing有公共/Adapter/scene/成员覆盖；值交换与cue由接入组件生成，不能假定全部105组件自动拥有scene能力。
- 自定义连续画面默认用 `NoteDemo.sceneAdapter.define(spec)` 复用 Adapter 生命周期胶水，最小接法见[自定义连续画面接入](#author-custom-scene)；原生 BindingHandle 与 helper 的恢复/效果入口不同，完整差异见[公共编排层](公共编排层.md#author-scene-adapter)。`NoteDemo.timingFacts.watch(session)`/`collect()` 按需观察 focus 到达、效果启动、ready、finished，默认关闭、只在内存、不写文件。

作者仍提供对象稳定ID、知识数据、字幕、focus/changed、保留证据、必要after、注意顺序及正常宿主布局。公共层不猜知识因果、不从快照自动推断M01动作、不统一支持所有图形的变形。attention 只接受明确列出的目标，不从内容变化自动推断教学重点。 自定义图形若需要按局部放行，Adapter 用 PreparedChange.groups() 声明组、EffectSpec.group 归属，并在 attention target 上写 groups；组内覆盖由 Adapter 自己保证。

自定义layout现在按 Binding 真实插槽名取用，可选 `cleanup` 已接入正常销毁和取得返回值后的挂载失败；旧单区布局仍可用 `main`。若 layout 在返回前失败，其内部资源仍需自行释放。

## 直接组件组合时的责任

| 事项 | 直接组合 | 使用NoteDemo |
| --- | --- | --- |
| 子组件销毁 | 宿主逐项处理，移除DOM不等于destroy | Binding拥有的组件随session销毁；借用实例保持原所有权 |

## 自定义连续画面接入

以下内容是项目内默认自定义画面的直接接法：先用 `NoteDemo.sceneAdapter.define` 把一张自己绘制的画面接入公共 scene，完成一次有意义的局部变化。完整参数、原生 Adapter 和进阶边界仍在[公共编排层](公共编排层.md#author-scene-adapter)；最小可运行宿主为 [minimal.html](../examples/continuous-scene/minimal.html)，更丰富的双组示例为 [index.html](../examples/continuous-scene/index.html)。

### 1. 什么时候用哪种入口

| 接法 | 适合 | 恢复入口 | 效果入口 |
| --- | --- | --- | --- |
| `sceneAdapter.define`（默认） | 普通自定义画面、局部变化、希望少写 Adapter 胶水 | 作者实例的 `restore(model, view)` | 计划的 `effects(timing, meta)`，`timing` 已是最终值 |
| 原生 BindingHandle | 需要直接控制 `prepareChange`、`targets`、`sourceElements`、`facts` 等完整契约 | `restore(view)` | `PreparedChange.effects(ctx)`，从 `ctx.timing` 取时序 |

两种入口都保留，不是迁移关系。先选默认 helper；只有需要直接控制完整 Adapter 契约时再读原生接法。不要把 helper 的 `restore(model, view)` 写成原生 `restore(view)`。

### 2. 先看可运行源

- 最小可运行宿主：[examples/continuous-scene/minimal.html](../examples/continuous-scene/minimal.html)
- 完整双组示例：[examples/continuous-scene/index.html](../examples/continuous-scene/index.html)
- 完整示例的 Adapter 消费片段：[examples/continuous-scene/adapter.js](../examples/continuous-scene/adapter.js)

最小宿主只用真实 `dist/note-library.css` / `dist/note-library.js` 和公开 helper，没有第二套播放器、私有暂停层或展示用外壳。它覆盖一次局部变化、`attention` 组放行、提交目标、来源视觉保留、恢复和减少动效；完整示例再增加两个分区与更丰富的观察节奏。文件职责以示例目录 README 为准。

需要看离线单文件时，用现有预览构建：

```powershell

```

### 3. 加载、Definition 与挂载

整库加载后，公共演示入口在 `NoteDemo`：

```html
<link rel="stylesheet" href="../../dist/note-library.css">
<script src="../../dist/note-library.js"></script>
```

一个最小 Definition 只需要作者能讲清的两三个停点：

```js
var definition = {
  initialFrameId: 'initial',
  bindings: { scene: { adapter: 'my-scene', slot: 'scene' } },
  frames: [
    { id: 'initial', caption: '初始状态', views: { scene: { value: 0 } } },
    { id: 'changed', caption: '一次局部变化', views: { scene: { value: 1 } } }
  ],
  transitions: [{
    from: 'initial', to: 'changed',
    scene: {
      bindings: [{ binding: 'scene', mode: 'update' }],
      timing: { enterDuration: 420, easing: 'linear' },
      attention: {
        targets: [{ binding: 'scene', query: { part: 'value' }, groups: ['value'] }]
      }
    }
  }]
};
```

`views.scene` 是作者领域视图；`normalizeView` 把它变成可序列化的 `{ model, cues }`。`attention` 的 `query` 是目标元素查询，`groups` 是焦点到达后要放行的效果组。挂载时把 Adapter 放进 `adapters`，用默认舞台：

```js
var session = NoteDemo.mount(document.querySelector('[data-demo-host]'), {
  definition: definition,
  adapters: { 'my-scene': myAdapter },
  layout: function (container) { /* 建 slot[data-demo-slot="scene"]，返回 { root, slots } */ },
  title: '示例标题'
});
window.__inspectSession = session; // 便于本地观察入口默认找到会话
```

自有舞台时用 `NoteDemo.create`，但默认舞台已负责画面容器、字幕、控制条和 Focus。最小示例只需要自己的`layout`把画面放进 slot。

### 4. 作者与公共层各负责什么

| 作者负责 | 公共层负责 |
| --- | --- |
| 领域 model、视图和正/反向规范化 | Definition/Frame/Transition 编排、定时与几何等待 |
| 绘制、恢复、当前真实状态读回 | Binding 生命周期、受控容器接管、CSS transition 暂停 |
| 目标元素查询、局部变化计划 | `attention` 焦点移动、效果组门控与取消 |
| 本步哪些组变化、来源视觉如何保持 | 运行中推进锁、ready/finished 结算、恢复/回放 |
| `progress` 的绘制与领域值换算 | 启动/取消/完成 EffectSpec、最终 timing 透传 |

作者不需要另写播放器、私有暂停层、第二套 rAF 或等待函数；也不要在 helper 之外伪装 Adapter 的读回。

### 5. 必要契约

`NoteDemo.sceneAdapter.define(spec)` 的常用字段：

- `name`：非空字符串，与 Definition 的 `adapter` 名一致。
- `sceneModes`：常用 `['update']`；需要 cut 等模式时按公共场景接口声明。`defaultSceneMode` 必须在列表中。
- `sceneTimingDefaults`：可选稀疏 timing，数字 ≥ 0，`easing` 非空字符串。
- `normalizeView(input, options)`：返回 model 对象或完整的 `{ model, cues }`，不能只返回一半。
- `mount(host, options)`：返回作者实例。

作者实例至少提供：

```js
{
  restore: function (model, view) { /* 直接呈现 view.model，不播动画、幂等、保留对象身份 */ },
  readModel: function () { /* 读真实实例状态，不返回缓存的目标 */ },
  target: function (query) { /* query -> 真实元素或 null */ },
  planStep: function (input) { /* 见下 */ },
  destroy: function () { /* 移除画面与监听 */ }
}
```

`mount` 返回的实例也可以选择 `readView()`、`cues()`、`applyCues()`、`settleVisual()`；只有确实需要时使用。scene 参与者应保证 `readModel` 能核对提交后的真实状态。

`planStep(input)` 的输入含：

```
{ bindingId, sourceFrameId, targetFrameId, sourceView, targetView,
  sourceModel, targetModel, motion, reduced, signal }
```

它可以同步返回计划，也可以返回 Promise。计划形状：

```js
{
  groups: function () { return ['value']; }, // 本次实际变化的组
  commit: function () { /* 必须同步提交完整目标 */ },
  targets: function () { return []; },        // 可选：布局载体
  effects: function (timing, meta) {          // 只在非 reduced 时调用
    return [NoteDemo.sceneAdapter.progress({
      group: 'value',
      duration: timing.enterDuration,
      easing: timing.easing,
      gate: 'ready',
      update: function (p) { /* 只画本组变化 */ }
    })];
  },
  sourceElements: function () { /* 可选：需要公共层保持/交接的来源元素 */ },
  cleanup: function () { /* 只释放本步临时资源；不承担最终显示 */ }
}
```

关键点：

- `commit()` 必须同步提交完整目标；只有 `planStep` 允许同步或异步。
- `effects(timing, meta)` 收到的 `timing` 已是 scene 合并后的最终值，0 合法；`meta` 含 binding、motion、attention、grouped、groups，可用于诊断/调整，不必自行重算默认。
- `groups()` 声明本次真正变化的效果组。`effects` 的每个 spec 必须属于某个已声明组；未声明组时 spec 不带 group。
- `sourceElements()` 用于公共层在提交前捕获来源视觉；没有需要交接的来源时不要伪造。
- `cleanup()` 只清理临时资源；不能等它来第一次显示目标内容。

### 6. 组、attention 与来源视觉

是否使用公共 Focus，按阅读需要决定。对象运动、对齐窗口或局部强调已经清楚指出本步变化时，不必额外叠框。主要变化仍应有主次和承接，解释不应散落在多处或藏成小字；完整阅读原则见[设计共识 K03、K06、K09、K17](设计共识.md)。

`attention.targets[].groups` 与 Adapter 的 `groups()` 按名字对应：

- 目标到达前，未放行组保持来源视觉；别的组的绘制不能提前覆盖它。
- 组内的图形、文字、提示和局部副本由 Adapter 自己完整覆盖；公共层校验归属，不推断领域。
- `groups:[]` 是只观察、不启动内容的合法接法，但不能拿来消除等待。
- 不需要 Focus 的辅助读数不必强行分组；它们什么时候能更新按“目标/阶段说明”与“已发生事实”区分，见[设计共识](设计共识.md#k18-目标说明与已发生事实)。

**部分过渡使用 attention**：可以只在需要引导的 transition 声明 `scene.attention`。省略它时，效果组不等待焦点到达，仍按原有 `after` 等依赖启动，并非无条件同时启动全部效果。默认舞台正常向前推进到无 attention 的停点时，上一目标仍有效则保留弱化线索，目标失效则清除；省略 attention 不等于显式清除旧框。回退、重看、重来、跳转和减少动效继续使用各自的导航处理。若需要混用，既判断本步是否需要新引导，也判断上一弱化线索是否仍有阅读意义。

**来源视觉**：`commit()` 提交目标模型后，本步未放行的组应继续显示来源值/来源视觉；已放行组由 `progress` 从来源推进到目标。不要在一次 commit 里把所有内容瞬间改成目标后再统一淡入，也不要用外层 opacity 遮罩假装局部变化。

**恢复与减少动效**：`restore(model, view)` 必须直接呈现该停点完整画面，不依赖稍后才执行的 effects。reduced 时 helper 跳过 `effects`，`commit()` 应直接呈现目标终态；不要等待不会出现的 progress。无论正常、恢复还是 reduced，最终 `readModel()` 都应等于目标停点的真实模型。

三条路径要分别处理：

| 入口 | 模型与可见画面 |
| --- | --- |
| 普通 update 过渡的 commit | 同步提交目标模型，同时在受控事务内建立各未启动组的来源视觉；组开始后才推进相应变化 |
| restore 恢复停点 | 模型和画面直接呈现该停点完整状态，不暗播中间步骤 |
| reduced 过渡的 commit | 模型和画面直接呈现目标终态，不依赖 effects 或其 update 回调 |

例如自定义画面已有 `paint(from, to, p)` 时，普通过渡可先呈现来源，再由 progress 绘制到目标；恢复与 reduced 则直接绘制目标。这里说明视觉职责，不要求每个 Adapter 都重画整个来源画面；需要构造目标布局或使用局部载体时沿用对应接法。关键是浏览器绘制时没有提前露出尚未启动的目标，而不是仅在变量里记下来源。

### 7. 读数与画面一致

阶段名、模式、目标参数可以随提交更新；“已收到/已发出/已完成”等事实必须随领域事件或实际展示进度更新；预期结果可以提前显示，但要明确是目标/预期。是否进入 Focus 与何时更新数值分别判断，不要求所有计数分组、动画或逐处巡视。

在最小示例中，辅助状态可以写“目标已提交/等待放行”；真正的“已显现/已完成”应在 progress 完成或终态恢复时更新，不能由 commit 提前写成完成。
