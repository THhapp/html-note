## 文档与语料如何使用

| 当前要解决的问题 | 先取哪份资料 | 取得什么后继续 |
| --- | --- | --- |
| 这篇 HTML 要讲什么、交付什么 | 源 MD 预留和本次任务；[提示词撰写](提示词撰写.md) | 问题、对象、理解目标、允许范围与交付形式 |
| 阅读和演示应该遵循什么 | [设计共识](设计共识.md) | 视觉聚焦、稳定字幕、停点与必要解释等已有要求；有效上下文可沿用 |
| 不知道已有资产叫什么 | 先跑 `node scripts/query.mjs search <用途/名称>`；未覆盖时查[完整组件目录](组件目录.md) | 用途、关键边界、相近能力区别及后续入口 |
| 已知具体组件，准备调用 | 对应模块 API、源清单和最小示例 | 当前调用上下文、必要参数、依赖与限制 |
| 需要多停点、内容过渡或聚焦协调 | 本页选入口，再取[公共层 API](公共编排层.md)中所需契约 | 知道公共层接管什么、作者仍需提供什么，取得对应接法 |
| 需要理解公共层为什么这样设计 | [公共过渡能力设计](公共过渡能力设计.md) | 分层、时序和实现取舍；普通调用不必先通读设计资料 |
| 准备离线交付 | 本页加载说明和[构建与分发](构建与分发.md) | 资源入口、生成命令和实际输出 |

新接手时先用本页确定入口，已有有效上下文直接继续。语料用于定位和选择，模块 API 与公开契约负责准确调用；示例提供结构参考，源码用于接口不清、资料冲突或具体故障。发生冲突时核对对应维护源，不把旧任务中的目标当作现有支持范围。

查询入口是[查询 CLI](查询CLI.md)：默认读取脚本所属库，也可在别的工作目录用 `--root` 指定。查询语料只补充作者别名、适用边界和关联，完整 105 个组件的名称、ID、类别与用途由源清单直接提供；未命中精选不等于库缺少能力。

```powershell
node scripts/query.mjs info
node scripts/query.mjs search 矩阵
node scripts/query.mjs show D01
node scripts/query.mjs read D01 api
```

`search` 返回候选与覆盖程度，`show` 给当前上下文的开工包，`read` 继续取 API 小节、源码或示例。已有明确 ID/公开名时直接 `show`，不必先 `info` 或 `search`；已有有效资料可直接制作，不要求每轮走完整流程。库的完整资产范围仍由组件目录及源清单维护。

## 加载与离线交付

~~~html
<link rel="stylesheet" href="./dist/note-library.css">
<script src="./dist/note-library.js"></script>
~~~

整库已经包含现有公开组件与NoteDemo。若控制体积，加载dist/modules下模块与其传递依赖，同页不要重复加载整库和相同模块。

现有单文件内联器接受任意本地经典脚本HTML入口：

~~~text
node scripts/build-demo-preview.mjs --template <作者index.html> --output <独立HTML>
~~~

它按入口已经列出的资源内联，不会自动按Binding计算依赖，也不会生成知识内容。作者入口当前直接引用 `dist/note-library.css` 与 `dist/note-library.js`，再用同一个模板生成[作者装配与聚焦预览](../dist/作者装配与聚焦-预览.html)；因此开发预览与离线文件消费同一份资源入口，不需要复制源脚本清单。旧示例保留index/standalone双入口是历史组织，不是作者必须遵守的要求。

## 作者入口与配方

[examples/authoring/index.html](../examples/authoring/index.html) 是普通作者入口的实例：只加载整库、一份数据与一份启动文件。数据在 `examples/authoring/data.js`，启动在 `boot.js`；不写播放器、不猜教学因果。

配方源码在 `src/demo/recipes.js`，最小用法：

~~~html
<script src='./dist/note-library.js'></script>
<script>
  var demo = NoteDemoRecipes.focusWorkbench({
    bindings: { /* Adapter 与 slot */ },
    initial: { id: 'start', caption: '…', views: { /* 每个 Binding 的完整视图 */ } },
    steps: [ { id: 'next', caption: '…', replace: { /* 按整个 Binding 替换 */ },
      scene: { bindings: [ /* … */ ], attention: { targets: [ /* 按注意顺序 */ ], stepDuration: 240 } } } ],
    sources: [ { slot: 'matrixA', title: '矩阵 A' } ],
    process: [ { slot: 'terms' } ],
    readout: { slot: 'sum', title: '逐项相加' },
    result: { slot: 'result', title: '结果' }
  });
  NoteDemo.mount(document.querySelector('[data-demo-host]'), demo);
</script>
~~~

`focusWorkbench` 只返回现有 `NoteDemo.mount` 输入，不拥有播放器。它负责区域骨架、slot 收集和 `layout.cleanup`；数据、视图、scene 参与者、after 和 attention 仍由作者给出。矩阵与单行读数两个例子共用这一配方，换内容时不应把它当成固定模板。

同一源码还提供三种区域/状态配方：

- `NoteDemoRecipes.stagePacket(options)`：阶段轨 + 报文流 + 读数/状态的主区纵向结构；至少提供 `stage` 或 `packet` 区域，其他区域可省。
- `NoteDemoRecipes.diagramTable(options)`：图形 + 状态表的主区网格结构；至少提供 `diagram` 或 `table` 区域，页脚可放读数/状态。
- `NoteDemoRecipes.repeatStages(options)`：作者给 `bindings/initial/items/expand`，配方补稳定 Frame id、caption 回退并调用 `NoteDemo.compile`；不生成第二套 Frame/Transition。

`stagePacket` / `diagramTable` 可选 `density:'compact'`：只缩小配方外壳的 gap、board/readout padding 与 head 间距，不改内容、字幕或动效；`flow-stage`/`flow-packet` 可另在 Binding.options 传 `density:'compact'` 收紧各自内部几何。`examples/flow-composition` 两段都使用 compact，并在 1366×768 / 1280×900 下按演示 section 起点对齐做同屏观察。

三者和 `focusWorkbench` 一样只返回 `NoteDemo.mount` 输入。完整中性实例见 [examples/flow-composition](../examples/flow-composition/index.html) 与 `dist/流程组合-预览.html`。

自定义图形接入时，demo-runtime 还提供 `NoteDemo.effects` 窄工具：`captureContent` / `createGhost` / `planValueSwap` / `captureStyles` / `planCueChanges` / `rectOf` / `unionRange`。`unionRange(refs)` 把移动对象和它的轨迹/标签等真实元素合成观察区域，返回 Definition 可用的 union range，不另建测量或动画。EffectSpec 支持 `type:'progress'` + `update(progress)` 驱动 SVG 数值属性（公共 scene 统一启动、取消、finished 与清理），作者不需要依赖 `NoteDemoInternals` 或自建 rAF。完整接入示例见 [examples/propagation](../examples/propagation/index.html) 与 `dist/传播过程与局部过渡-预览.html`。

局部动画结束和来源观察需要显式交接，否则很容易出现“动画结束回落隐藏、整步结束才重现”或“旧层一提交就消失”：

~~~js
// PreparedChange 内：commit 前声明本步仍要观察的来源对象；公共 scene 捕获并在 commit 后保持，
// 到该 Binding 第一个内容轨道启动时释放。
sourceElements: function () { return [sourceLabel]; },

effects: function (ctx) {
  return [{
    el: targetLabel,
    keyframes: [{ opacity: '0' }, { opacity: '1' }],
    options: { duration: ctx.timing.enterDuration, easing: ctx.timing.easing },
    group: 'reveal',
    gate: 'ready',
    handoff: 'hold'   // 正常完成后由公共 scene 保持末帧到收束；取消仍恢复来源
  }];
}
~~~

`sourceElements()` 只接受 commit 前后仍在 DOM 中的真实元素；公共层只恢复 `opacity/visibility/display`，父级整体隐藏不在保证范围。`handoff:'hold'` 只用于目标内容类 WAAPI 效果；退出副本、提示脉冲和 progress 的终态不要声明它。普通 DOM 交接见[作者入口](../examples/authoring/index.html)第三节；SVG 的 `handoff:'hold'` 与真实运动对象跟随见[传播示例](../examples/propagation/index.html)。来源保留用 `sourceElements()`，当前由普通 DOM 小例示范。

声明 `scene.attention` 的 scene 自动使用公共的较慢内容节奏（内容 enter 560 / cue 680 / reveal 420 等），普通 scene 仍使用原默认。默认舞台使用**会话级 Focus**：首次在起点软出现，按 targets 顺序迁移，最后停点快速弱化保留（虚线/低强调），正常“下一步”从弱化位置承接；取消、回退、重看、重来、跳转与销毁按导航策略隐藏或重启。Focus 的 `whenArrived()` 与 scene 的真实 ready 决定启动和承接，作者不要在 target 上另写观察计时。

target 可选字段：`groups`（省略=整 Binding 门控；`[]`=只观察不启动；非空=放行命名效果组）、`holdDuration`（0 有效；观察型目标从到达起默认 `stepDuration`，触发内容的目标默认 ready 后 0 额外停留，最后落点不倒计时）、`range`（`{kind:'local',dx,dy,width,height}`、相对形式 `{kind:'local',outset}`/`{kind:'local',inset}`，或 `{kind:'union',refs:[...]}`，把焦点框变成事件附近的合理观察区域）。local 的相对形式使用 CSS 像素、只能二选一且不能与绝对字段混用；union refs 可写 `optional:true`，缺失的可选成员跳过，必需成员或无效几何明确报错。断开/`display:none`/`visibility:hidden` 元素不算有效目标；`opacity:0` 但有真实矩形仍可用，SVG 一维线有效，零面积点必须显式范围。`table` 与四个 flow Adapter 已拆出细粒度效果组（`cell/row`、`stage/bypass`、`message/participant`、`segment/range`、`link/device`）；其他内置 Adapter 是否拆组以 Adapter 文档为准。自定义 Adapter 声明 `PreparedChange.groups()` 后，可用 `spec.group` 把图形、文字、提示与局部副本完整归入同一组，再由不同观察目标分别放行。

## 槽位、布局与作者简写

- 自定义 layout 返回 `{ root, slots, cleanup? }` 时，公共层不再强制 `main` 别名；每个 Binding 按自己的 `slot` 取得真实命名插槽。返回单个 Element 的旧用法仍映射为 `main`。
- `NoteDemo.collectSlots(root, required)` 只收集 `[data-demo-slot]`，重复或缺失直接报名称错误，不猜区域对应关系。配方使用它；自定义 layout 也可以直接使用。
- 已成功取得的 `layout.cleanup` 会在正常销毁和取得返回值后的挂载失败中恰好调用一次。layout 回调在返回前抛错时，公共层没有 cleanup 可调用，内部资源必须由该回调自行释放；配方在收集 slot 失败时会自行销毁已建布局组件。
- `NoteDemo.compile({bindings, initial, steps})` 是纯作者编译辅助：按整个 Binding 替换视图，生成每个完整 Frame 和相邻 Transition；差分使用 Adapter 规范化结果，补齐 after 引用的稳定参与者，保留 reveal 和 scene.attention，不推断 actions，也不把未声明变化静默降级为 cut。完整 Definition 仍是高级入口和可检查产物。

## 公共演示层已经管理什么

- Frame提供完整可恢复视图，Transition指定可选scene或actions。
- 普通推进保留组件实例；回退/go/reset 直接恢复明确停点，重看按入边重演；默认舞台“上一步”按 replayPreviousStep 从上一停点入边的初态重播（允许焦点跳变），`session.prev()` 仍保持直接恢复上一停点。
- scene同步提交完整目标，保持未启动源视觉，按真实句柄完成；相关变化可同窗，必要因果用 after，同一 Binding 的局部变化可用命名效果组分别放行。
- scene.attention 使用会话级焦点框，不新增文字标签、不默认遮罩或滚动；最后停点弱化保留，正常下一步承接；取消/回退/重看/跳转按导航策略隐藏或重启，减少动效时不迁移也不增加等待。观察可用 groups 区分“看哪里”和“放行什么”，用 range 表达事件附近范围。
- 默认舞台稳定下方字幕与控件，执行中下一步灰色不可用，取消和错误沿统一生命周期处理。
- Frame标记按逻辑TargetRef解析；scene内有稳定id的标记可复用，字幕与必要标记计入最终收束。
- 当前timing有公共/Adapter/scene/成员覆盖；值交换与cue由接入组件生成，不能假定全部105组件自动拥有scene能力。
- 自定义连续画面默认用 `NoteDemo.sceneAdapter.define(spec)` 复用 Adapter 生命周期胶水，最小接法见[自定义画面接入](自定义画面接入.md)；原生 BindingHandle 与 helper 的恢复/效果入口不同，完整差异见[公共编排层](公共编排层.md#author-scene-adapter)。`NoteDemo.timingFacts.watch(session)`/`collect()` 按需观察 focus 到达、效果启动、ready、finished，默认关闭、只在内存、不写文件。

作者仍提供对象稳定ID、知识数据、字幕、focus/changed、保留证据、必要after、注意顺序及正常宿主布局。公共层不猜知识因果、不从快照自动推断M01动作、不统一支持所有图形的变形。attention 只接受明确列出的目标，不从内容变化自动推断教学重点。 自定义图形若需要按局部放行，Adapter 用 PreparedChange.groups() 声明组、EffectSpec.group 归属，并在 attention target 上写 groups；组内覆盖由 Adapter 自己保证。

自定义layout现在按 Binding 真实插槽名取用，可选 `cleanup` 已接入正常销毁和取得返回值后的挂载失败；旧单区布局仍可用 `main`。若 layout 在返回前失败，其内部资源仍需自行释放。

## 直接组件组合时的责任

| 事项 | 直接组合 | 使用NoteDemo |
| --- | --- | --- |
| 子组件销毁 | 宿主逐项处理，移除DOM不等于destroy | Binding拥有的组件随session销毁；借用实例保持原所有权 |
| 机制状态 | 常驻实例才保留 undo/replay | Frame 恢复不依赖整篇演示共享私有撤销栈 |
| 按钮焦点 | B01配置更新可能重建按钮，可持有Button实例 | 默认Presentation保留控件节点与执行态 |
| 标记跟随 | 通过公开target/refresh组织 | 支持受控scene标记与稳定期跟随；不承诺任意嵌套滚动/路径插值 |
| 布局组件资源 | 宿主清理 | 自定义layout自身的观察器/事件仍需宿主负责 |
| 空间安排 | 组件内部与宿主外部间距分工 | 公共舞台稳定，不替作者决定全部布局比例 |

## 查找能力

标题正文用C01/C05，规则数据用C06/C11/B03，代码公式图片用C07—C10及C13；对象用D01—D06，流程图形用D07—D10，关注/范围/连线用R07—R09，直接动作看M01—M04/R10，局部组合看B01—B10。具体输入与限制查对应API，不把外观相似当成接口统一。

新动态组件通常mount/update/destroy；NoteExpr保留show/hide/refresh，SeqInsert保留insert/restore/replay/setData。旧公开接口继续成立。

## 能力边界与维护

- 公共层已有能力以[公共编排层](公共编排层.md)为准；消费测试是可复现入口，不构成第二套功能清单。
- blocks 分发依赖仍偏粗；六个 Adapter 以外的动态接入、外部 Focus 与目标 Binding.ready、普通非 scene keyed 标记等边界查公共编排层。
- 维护源只在 `src`；`dist` 与根 `registry.json` 统一构建，不手改。
