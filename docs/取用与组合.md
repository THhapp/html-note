# 取用与组合指南

本页是作者开工路径：一次查询取得开工包，选静态组件、配方或自定义画面，按“依据 → 主要变化 → 结果”接好演示，再正常速度观察并离线交付。详细 API、参数与生命周期以[公共编排层](公共编排层.md)为准；本页不复制整套接口。

<a id="author-start"></a>

## 作者开工：一次查询选对路径

先取开工包：

```powershell
node scripts/query.mjs show authoring:start --json
```

它返回作者开工所需的结构化入口：开工指南、作者入口完整示例、`data.js` 数据片段、最小连续画面宿主、`attention` API、本地核对入口和 table Adapter 目标说明；`usage` 给出跨区域最小的配方与 attention 目标顺序。需要某个具体组件时再用 `show <组件>` 补取，不必先通读全部资料。

开工顺序：

1. 从本次材料明确要理解的问题、观察关系和交付形式；不替作者推断知识重点。
2. 运行上面的开工查询；只有缺具体能力时才 `search`/`show`/`read` 单条。
3. 选路径：静态组件、已有配方、跨区域承接或自定义画面（见下表）。
4. 先贯通最不确定的代表过程，优先做一个真实停点链，不先铺满页面。
5. 用正常速度 `next()`/`replay()` 观察依据、主要变化和结果的承接；有具体疑点再补 probe。
6. 需要离线交付时按“加载与离线交付”内联；保留作者源文件与重新生成方式。

| 本次要做 | 先取 | 继续 |
| --- | --- | --- |
| 单个静态组件/图形，无演示运行层 | `show <ID> --context independent` | 组件 API，直接 mount/update |
| 固定区域的多个停点 | `focusWorkbench` / `stagePacket` / `diagramTable` / `repeatStages` | [作者入口与配方](#作者入口与配方) |
| 跨区域“依据→主要变化→结果”，结果表出现新行 | `authoring:start` + `diagramTable` + `scene.attention` | [跨区域演示](#跨区域演示依据-主要变化-结果) |
| 自绘画面、局部变化，希望少写 Adapter 胶水 | `public:continuous-adapter` | [自定义连续画面接入](#author-custom-scene) |
| 自备整个舞台 | `NoteDemo.create` | [公共编排层](公共编排层.md) |

配方和公共层的完整参数不在本页复制；以查询返回资源和[公共编排层](公共编排层.md)为准。

## 查询与本地观察

查询读维护源，不打开浏览器；观察打开真实页面并收集页面事实。

```powershell
node scripts/query.mjs info
node scripts/query.mjs search 表格新行
node scripts/query.mjs show authoring:start --json
node scripts/query.mjs show D01 --context independent --json
node scripts/query.mjs read authoring:start guide --json
node scripts/query.mjs read authoring:start table --json
```

- `search` 按 ID、名称、别名、用途和检索词匹配；零结果时的 suggestions 只来自真实拆词命中，不是热门推荐，也不代表库缺少能力。
- `show` 返回条目的上下文、依赖、资源和短用法；可用上下文以实际返回为准。作者开工与其他公共接法用 `authoring` 上下文。
- `read <id> <资源键>` 读取条目声明的资源；`--offset`/`--limit` 分页，章节止于下一条同级或更高级标题。常见键：`api`/`source`/`example`/`fragment`/`full`/`minimal`/`guide`/`verify`/`table`。

本地观察：

```powershell
node scripts/inspect-note.mjs "examples/authoring/index.html" --json
node scripts/inspect-note.mjs "examples/authoring/index.html" --session "window.AuthoringSessions[3]" --probe "D:/path/probe.mjs" --json
```

- `--frame <frameId>` 只调用公开 `session.go(frameId)` 恢复停点；它证明静态落点，不证明动画。过程用 probe 内 `next()/replay()` 真实推进。
- probe 导出 `default async ({ page, inspect }) => ...`，与页面同页；`inspect.sample()` 用于采样，截图只在显式调用时写文件。
- 输出区分工具执行事实、页面观察和 probe 结果；打开成功不等于作品验收通过。详细参数见[公共编排层 §8.2](公共编排层.md#author-inspect-note)。

## 优先选合适的入口

| 目的 | 入口 | 职责 |
| --- | --- | --- |
| 查能力与独立调用 | query、registry、组件 API | 静态 UI 与知识表达直接使用，不必经过演示运行层 |
| 多停点、可回看演示 | `NoteDemo.mount` + 完整 Frame + scene/actions | 公共层管理常驻组件、推进/回退/重看、字幕、标记、取消和完成；默认舞台提供演示 Focus |
| 自备整个舞台 | `NoteDemo.create` + slots | 使用公共运行核心，呈现和控件由宿主组织 |
| 简单整幅快照重绘 | B02 StepPlayer | 每步 cleanup 再 render；不自动生成对象过渡，重挂载可能失去机制历史 |
| 直接控制单个机制 | B01 + M01/R10 等公开 API | 宿主明确推进与清理，适用于需要原生动作控制的局部组合 |

示例按实际结构选：单项组件看[独立调用](../examples/run.html?id=L01)；作者多停点看[作者入口](../examples/authoring/index.html)（含跨区域第四例）；自定义连续画面先看[最小宿主](../examples/continuous-scene/minimal.html)与[完整双组示例](../examples/continuous-scene/index.html)；自定义图形按层追加看[传播示例](../examples/propagation/index.html)；阶段轨/消息流/分段长度条/设备连接看[流程图形中性示例](../examples/flow-kit/index.html)，阶段+报文+读数与图形+状态表看[流程组合示例](../examples/flow-composition/index.html)。[矩阵旧对照](../examples/reuse-matrix-product/index.html)只用于比较旧接法。题材相近不代表模型或场景结构相同，按所需部分参考。

## 加载与离线交付

~~~html
<link rel="stylesheet" href="./dist/note-library.css">
<script src="./dist/note-library.js"></script>
~~~

整库已经包含现有公开组件与 NoteDemo，作者入口只需整库加一份数据/启动文件。若要控制体积，加载 `dist/modules` 下目标模块及其声明依赖；依赖闭包用查询结果的 `dependencies`，同页不要重复加载整库和相同模块。

现有单文件内联器接受任意本地经典脚本 HTML 入口：

~~~text
node scripts/build-demo-preview.mjs --template <作者index.html> --output <独立HTML>
~~~

它只内联入口已经列出的资源，不计算未列出的依赖，也不生成知识内容。开发预览与离线文件应消费同一份资源入口；作者入口当前直接引用整库 JS/CSS，因此同模板生成的预览与开发页一致。旧示例的双入口是历史组织，不是作者必须遵守的要求。

## 作者入口与配方

[examples/authoring/index.html](../examples/authoring/index.html) 是普通作者入口：整库 + `data.js` + `boot.js`。现有四个实例：前两个用 `focusWorkbench`，第三个用自定义 Adapter 演示普通 DOM 交接，第四个用 `diagramTable` 演示跨区域依据→结果。数据在 [data.js](../examples/authoring/data.js)，启动在 [boot.js](../examples/authoring/boot.js)。

配方源码在 `src/demo/recipes.js`，都只返回 `NoteDemo.mount` 输入，不拥有播放器：

- `focusWorkbench(options)`：矩阵/单行读数类区域骨架、slot 收集与 layout.cleanup；数据、视图、scene、after 与 attention 仍由作者给出。
- `stagePacket(options)`：阶段轨 + 报文流 + 读数/状态的主区纵向结构；至少提供 stage 或 packet，其他区域可省。
- `diagramTable(options)`：图形 + 状态表的主区网格结构；至少提供 diagram 或 table，页脚可放读数/状态。跨区域示例即此配方。
- `repeatStages(options)`：作者给 bindings/initial/items/expand，配方补稳定 Frame id、caption 回退并调用 `NoteDemo.compile`；不生成第二套 Frame/Transition。

`stagePacket`/`diagramTable` 可给 `density:'compact'`，只缩小配方外壳的 gap、padding、readout/head 间距，不改内容、字幕或动效。四个配方都不推断知识因果、不生成 scene.attention；变化 binding、观察顺序与说明由作者声明。自定义图形效果工具与交接边界见[公共编排层 §5.5](公共编排层.md#author-scene-adapter)和[传播示例](../examples/propagation/index.html)。

## 跨区域演示：依据 → 主要变化 → 结果

适合“左侧依据确认后，右侧结果表才出现新行”这类跨区域承接。用 `diagramTable` 分区，`attention` 先到依据，再到表行：

```js
var recipe = NoteDemoRecipes.diagramTable({
  bindings: {
    evidence: { adapter: 'dom', slot: 'evidence' },
    table: { adapter: 'table', slot: 'table',
      options: { rowKey: 'id', stableStateLabels: false } },
    status: { adapter: 'dom', slot: 'status' }   // 辅助状态：列入 scene.bindings，但不进 attention
  },
  initial: { /* evidence 文本、空表、status 已提交 0 条 */ },
  steps: [{
    replace: { /* evidence 文本、table 行、status 文本 */ },
    scene: {
      bindings: [{ binding: 'evidence' }, { binding: 'table' }, { binding: 'status', mode: 'cut' }],
      attention: { targets: [
        { binding: 'evidence', query: { part: 'value' } },
        { binding: 'table', query: { row: 'r1' }, groups: ['row:r1'], holdDuration: 0 }
      ] }
    }
  }],
  diagram: { slot: 'evidence', title: '当前依据' },
  table: { slot: 'table', title: '结果表' },
  status: { slot: 'status', title: '已提交状态' }
});
NoteDemo.mount(host, { definition: recipe.definition, layout: recipe.layout });
```

已核实的 table 新行门控（来自真实浏览器探针）：

- 新行在 commit 时进入 DOM，行级 WAAPI 在组放行前以 `opacity:0` 暂停；`attention` 到达该行、`groups:['row:<key>']` 放行后，整行才 ready→finished。组名由 table Adapter 按 `row:<encodeURIComponent(key)>` 生成。
- 独立 table Binding 可以由 `scene.attention` 的 `{row:'<key>'}` 定位，不必与依据放在同一 Binding；“必须同 Binding 才能延后新行”不是已核对结论，不能作为接法依据。
- 已有行不被重播；只放行本步新增/变化的行组。任何视图变化的 Binding 都必须列入本步 `scene.bindings`；辅助状态用 `{binding:'status', mode:'cut'}` 同步提交，不放进 attention targets，也不逐项巡视。省略会由公共 compile 报“不能静默降级为 cut”。

是否使用 Focus 单独判断：对象运动、对齐窗口、范围变化等自然引导已能对应依据与结果时，可以不用公共 attention；只有跨区域依据/结果无法直接对应、主要变化需要寻找时，才用公共 attention。工具不猜知识重点。可运行完整第四例见[作者入口](../examples/authoring/index.html)，数据见 [data.js](../examples/authoring/data.js)；API 见[公共编排层 §5.1/§5.3](公共编排层.md#author-attention)。

## 槽位、布局与作者简写

- 自定义 layout 返回 `{ root, slots, cleanup? }` 时按 Binding 的真实插槽名取用；返回单个 Element 的旧用法仍映射为 `main`。
- `NoteDemo.collectSlots(root, required)` 只收集 `[data-demo-slot]`；重复或缺失直接报名称错误，不猜区域对应关系。
- `layout.cleanup` 在正常销毁和取得返回值后的挂载失败中恰好调用一次；layout 回调在返回前抛错时，内部资源要由该回调自行释放。
- `NoteDemo.compile({ bindings, initial, steps })` 按整个 Binding 替换视图生成完整 Frame/Transition，补齐 after 引用的稳定参与者，保留 reveal 与 scene.attention，不推断 actions，也不把未声明变化静默降级为 cut。
- `NoteDemo.timingFacts.watch(session)`/`collect()` 按需观察 focus 到达、效果启动、ready、finished；默认关闭、只在内存、不写文件。

## 模块与依赖

当前 105 条清单、20 个模块。每个模块加载自己的 JS/CSS 并先加载声明依赖；实际加载清单用 `show` 返回的 `dependencies`，完整依赖表见[构建与分发 §4.2](构建与分发.md#42-依赖表)。内置 Adapter 为 matrix、sequence、sequence-edit、sequence-insert、dom、expression、table、flow-stage、flow-packet、flow-segment、flow-device；组件模块依赖按实际 Binding 使用核对，不能因为条目属于 demo-runtime 就认为 mount 只需 core。

## 公共层与作者的职责

使用 NoteDemo 时，公共层负责 Frame/Transition 编排、常驻组件、推进/回退/重看、默认舞台控件与字幕、受控视觉接管、attention 焦点与效果组门控、取消/错误生命周期与恢复；作者提供对象稳定 ID、知识数据、视图与恢复、字幕、focus/changed、必要 after、观察顺序、来源视觉与宿主布局。

公共层不猜知识因果、不从快照推断动作、不统一支持所有图形变形；attention 只接受明确列出的目标。直接组合组件时，宿主自行管理子组件销毁、常驻实例、按钮焦点与布局资源；NoteDemo 管理 Binding 拥有的组件生命周期。详见[公共编排层](公共编排层.md)。

## 能力边界与维护

- 公共层现有能力以[公共编排层](公共编排层.md)为准；消费测试是可复现入口，不是第二套功能清单。
- `attention` 只接受明确列出的目标，不从内容变化自动推断教学重点；未声明的变化不自动降级为 cut。
- 维护源只在 `src`；`dist` 与根 `registry.json` 统一构建，不手改。

## 自定义连续画面接入

普通自定义画面优先用 `NoteDemo.sceneAdapter.define`：作者实例负责绘制/恢复、真实状态读回、目标查询与局部变化计划，helper 组织 Adapter 契约、提交顺序、减少动效与 timing。只有需要直接控制完整 Adapter 契约（`prepareChange`/`targets`/`sourceElements`/`facts` 等）时才用原生 BindingHandle；两者不是迁移关系。完整参数与差异见[公共编排层 §5.5](公共编排层.md#author-scene-adapter)，最小可运行宿主为 [minimal.html](../examples/continuous-scene/minimal.html)。

### 最小接法

整库加载后：

~~~html
<link rel="stylesheet" href="../../dist/note-library.css">
<script src="../../dist/note-library.js"></script>
~~~

```js
var definition = {
  initialFrameId: 'initial',
  bindings: { scene: { adapter: 'my-scene', slot: 'scene' } },
  frames: [
    { id: 'initial', caption: '初始状态', views: { scene: { value: 0 } } },
    { id: 'changed', caption: '一次局部变化', views: { scene: { value: 1 } } }
  ],
  transitions: [{
    from: 'initial', to: 'changed',
    scene: {
      bindings: [{ binding: 'scene', mode: 'update' }],
      attention: { targets: [{ binding: 'scene', query: { part: 'value' }, groups: ['value'] }] }
    }
  }]
};
var session = NoteDemo.mount(document.querySelector('[data-demo-host]'), {
  definition: definition,
  adapters: { 'my-scene': myAdapter },
  layout: function (container) { /* 建 data-demo-slot="scene"，返回 { root, slots } */ }
});
```

`sceneAdapter.define(spec)` 常用字段：`name` 与 adapter 名一致；`sceneModes` 常用 `['update']`，`defaultSceneMode` 必须在列表中；`sceneTimingDefaults` 可给稀疏 timing；`normalizeView(input, options)` 返回 model 或完整的 `{ model, cues }`；`mount(host, options)` 返回作者实例，至少提供 `restore(model, view)`、`readModel()`、`target(query)`、`planStep(input)`、`destroy()`。

作者实例与提交：`commit()` 必须同步提交完整目标；未放行组保持来源视觉，`effects` 只推进已放行组；`groups()` 声明本步真正变化的组，每个 EffectSpec 必须属于某个声明组；`cleanup()` 只释放本步临时资源，不承担最终显示；reduced 跳过 effects，`commit()` 直接呈现目标终态；`restore` 直接呈现完整停点，不依赖 effects。需要 `sourceElements()`/`handoff:'hold'` 时按完整契约使用，不伪造来源。

```powershell
node scripts/inspect-note.mjs "examples/continuous-scene/minimal.html" --frame changed --session "window.__inspectSession" --json
```
