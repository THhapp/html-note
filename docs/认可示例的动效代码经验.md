# 从认可示例提炼的动效代码经验

> 资料定位：研究资料，从已认可样例源码提炼实现机制；不是现行 API，也不继承整页外观。现行接口见[公共编排层](公共编排层.md)。

本文关注对象身份、完整目标画面、前后布局、效果时机与来源保持；具体接口实现以现行源码为准。

## 1. 一次推进提交一个完整目标画面

调用路径是：nextBtn点击 → go(current+1) → renderStep(step) → updateControls()。

STEPS描述目标画面，包括线路数据状态、局部标记、括线、接收端结果和字幕。例如字节填充的一步同时声明wire:'stuffed'、两个转义括线、等待还原的状态和本步字幕。它没有把“第一个插入、第一次替换、第二个插入、第二次替换、核对”变成串行播放指令。

renderStep先记录旧位置，再生成完整目标DOM，最后补上从旧位置到新位置的运动。这样本步所有效果都围绕同一份目标布局配合，不需要每个组件先独立播完再交棒。

经验：内容作者声明前后画面及重点；公共能力负责使同一批对象自然到达目标。现有公共层的Frame方向可以保留，应补足对象过渡接入，而非重新发明一套状态模型。

## 2. 对象身份与显示值分离

实际数据节选：

```js
// 原始数据中的一个字节
{ key: 'p1', text: '7E' }

// 填充后，同一个对象仍为p1，前面新增e1
{ key: 'e1', text: '7D', state: 'inserted' },
{ key: 'p1', text: '5E', state: 'replaced' }
```

原始与填充数组按key核对得到：

| 对象 | 原数据序号 | 新数据序号 | 值变化 | 表达职责 |
| --- | --- | --- | --- | --- |
| p0 | 0 | 0 | 41→41 | 保持参照 |
| p1 | 1 | 2 | 7E→5E | 让位，同时提示值替换 |
| p2 | 2 | 4 | 7D→5D | 让位，同时提示值替换 |
| p3 | 3 | 5 | 42→42 | 只让位，保留身份 |
| e1/e2 | 不存在 | 1/3 | 新增7D | 插入物入场 |

序号是上述数据数组的下标，未计首尾标志和FCS。值相同的字节也不能共用身份；值改变的同一对象不应换成新身份。

经验：按稳定ID分别识别新增、保留、退出、值改变与位置改变。新位置不等于新对象，值改变也不等于对象销毁再创建。语义角色由内容声明，结构差异可由公共过渡辅助取得。

## 3. 用前后几何位置差产生让位

renderStep的关键代码，按原实现删减：

```js
firstRects = new Map();
stage.querySelectorAll('.row-wire [data-token]').forEach(function (el) {
  firstRects.set(el.dataset.token, el.getBoundingClientRect());
});

stage.innerHTML = buildStageHTML(step, phaseChanged);

stage.querySelectorAll('.row-wire [data-token]').forEach(function (el) {
  var prev = firstRects.get(el.dataset.token);
  if (!prev) return;
  var now = el.getBoundingClientRect();
  var dx = prev.left - now.left;
  if (Math.abs(dx) > 0.5) {
    el.animate([
      { transform: 'translateX(' + dx + 'px)' },
      { transform: 'translateX(0)' }
    ], { duration: 340, easing: 'cubic-bezier(.2,.7,.2,1)' });
  }
});
```

先让浏览器排出目标布局，元素的逻辑位置已经正确，再用transform把它视觉上放回旧位置，运动到零偏移。它按实际测量处理字节、位、标志和FCS的不同宽度，没有假定每次统一右移某个固定像素值。

未移动对象不启动位移动效；没有旧位置的新增对象交给入场效果。首尾标志的身份和含义保留，其中右侧标志可随整行变长而移动，不能把“含义不变”误作“坐标必须不变”。

这是常见的前后布局补偿思路。目标DOM写入、取得新位置及登记反向位移在同一次同步调用中完成，中间没有await；如果拆到不同的可绘制帧，可能先显示目标位置、再跳回旧位开始移动。后续rAF只负责标注，不承担主要位移的起步。

公共实现可保留DOM节点，也可适配重建的DOM；这里的关键是逻辑身份与几何对应。抽取时宜先批量完成新位置测量再启动效果，避免把原版逐个测量/播放的读写交错照搬成通用实现。

## 4. 外层负责位移，内层负责入场与强调

结构由tokenHTML集中生成：

```html
<div class="token" data-token="p1">
  <span class="tag">替换</span>
  <span class="chip">5E</span>
</div>
```

位移动画作用在外层token；新增物的chipIn缩放和轻微纵移作用在内层chip；值替换的replaceFlash只改变chip背景。这让位移、缩放和强调可以同时存在，不会由两段动画争写同一个元素的transform。

```css
/* 原版的相关效果 */
@keyframes chipIn {
  from { opacity: 0; transform: translateY(-5px) scale(.92); }
  to   { opacity: 1; transform: none; }
}
@keyframes replaceFlash {
  /* 用背景提示值已替换，终态仍是正常可读的目标对象 */
}
```

经验：公共过渡应区分布局载体与内容载体，或明确各效果控制的属性。不要把让位、入场、关注、值变化都作为同一DOM元素上彼此覆盖的transform。

## 5. 连贯来自有关系的重叠和错开

字节填充使用以下CSS/WAAPI安排。这里列的是原版参数，不是新的统一标准；CSS启动与rAF登记存在帧级差异，表中不是浏览器实测时间线。

| 效果 | 启动关系 | 原版时长/延迟 | 作用 |
| --- | --- | --- | --- |
| 保留对象让位 | 同轮目标画面更新后 | 340ms | 保持对象连续性 |
| 新增chip入场 | 新节点进入目标DOM时 | 340ms | 让插入物在目标位置出现 |
| 被替换值的背景强调 | 目标DOM生成时 | 550ms | 给较小的内容变化留出辨认时间 |
| 括线说明 | 下一次rAF创建标注后 | 延迟120ms，再380ms | 与结构变化重叠，稍后补足关系 |
| 本步字幕 | 本次更新时 | 300ms | 同一段字幕进入后保持稳定 |

这些效果没有组成340+340+550+380ms的串行队列。对象正在形成目标关系时，局部说明已开始补上；同一数据线内的重叠也不同于远处多个面板各自并行播放。

接收端结果还有按对象序号45ms错开的入场；这属于同一组结果内部的配合，不是自动跳到多个理解停点。

经验：公共层应能保留效果之间的相对关系，并按整体作用收束；一个全局时长或全开/全关的动效开关不能替代这种组织。具体时长根据距离、信息量和观看判断调整。

## 6. 注释绑定逻辑对象，按目标布局定位

数据中只声明端点和关系：

```js
brackets: [
  { from: 'e1', to: 'p1', label: '7E 的转义', tone: 'amber' },
  { from: 'e2', to: 'p2', label: '7D 的转义', tone: 'amber' }
]
```

drawAnnotations在目标DOM生成后的rAF中执行，按data-token找到端点，用offsetLeft/offsetWidth求括线位置。这里取得的是目标布局的局部坐标，不是getBoundingClientRect所包含的每帧transform后视觉位置。

因此括线在目标区域稍后淡入，无须每帧追着运动中的对象重算。Resize时另行重测。count-pill也锚定b5，截断线锚定冲突对象的右缘，不靠手写全页坐标。

经验：公共标记至少要区分“跟随运动中的对象”与“指向目标布局的关系”。二者适用场合不同，不能强制所有标记每帧跟随，也不能一律静态关闭效果。

旧版的renderGen在异步标注前核对当前代次，过期rAF不会再绘制旧步骤。它只阻止旧标注提交，不等于已经取消全部旧动画；现有公共层runId/取消机制应继续承担完整生命周期。

## 7. 稳定排布给运动提供参照

三行固定承担原始数据、线路上、接收端的角色。本步主要对象在中间一行变化，原始数据持续可比。CSS还预留了：

- tag的固定高度；空tag使用visibility:hidden保留占位，没有因标签出现而把chip往下推。
- token与接收端内容的最小/固定行槽，以及始终存在的括线层。
- 字幕区域的最小高度；短字幕变化不轻易带动按钮上下跳。

这些值是该页面的排布选择，不是公共层必须冻结的尺寸，也不能据此断言所有长度下高度恒定。值得复用的是标签、注释、正文和控制各有稳定空间的办法。

窄屏时原版允许演示局部横向滚动，避免把所有字缩到不可辨认；原有小字缺陷不在本次认可范围内。

## 8. 停稳后的画面保留变化证据

还原步骤的数据仍为wire:'stuffed'，只增加deleted:['e1','e2']或deleted:['z']；插入物保留在中间行，用虚线、删除标签和划除表示待删/删除含义。同时在接收端一行显示还原结果。

读者能同时检查哪些是插入物、怎样还原以及结果与原始数据是否一致，不必赶在短暂离场副本消失前记住全过程。这里没有把中间行物理删除并压紧等同于完成整个解释。

零比特步骤也只给出counter:{key:'b5',text:'5'}和对应范围，没有自动播放计数1、2、3、4、5的等待链。主要运动用于显示插入与让位，规则由稳定标注承载。

经验：公共表达应允许保留来源、删除痕迹与结果参照。退出效果完成后是否销毁可见证据，需要依据展示角色处理，不能一律把所有离场对象清除。也不要为了模拟逐位执行而加入没有必要的自动变化。

## 9. 两处值得保留的边界控制

阶段变更时使用整组phase-enter；同阶段才做对象几何匹配。这样字节与比特之间的主题切换不会被当成同一批对象继续移动。公共身份映射需要有场景/阶段作用域。

go直接从STEPS重建目标，不依赖把若干历史微操作反向执行。这与现有公共层“Frame可恢复、过渡可选”的方向相符。改进应保留这部分可靠性。

## 10. 不能照搬的工程细节

认可动效不等于原实现已具备成熟的公共生命周期：

1. **缺少动作完成句柄与运行中禁用。** go立即更新current与按钮，next只在末步禁用。不能为还原旧效果而丢掉现在要求的执行态。
2. **部分终态依赖动画填充。** bracket的基础opacity是0，靠animation-fill-mode:forwards维持可见；dim也靠填充维持降权。通用层若直接cancel全部动画，可能让标注消失或降权失效。迁移时应把终态写入基础样式/状态，清理效果后仍正确。
3. **animate:false没有统一关闭全部效果。** 它控制几何补偿，但新DOM的CSS动画和字幕动画仍可能播放。公开运动策略需要一致覆盖CSS与WAAPI，减少动效也应静态保留正确结果。
4. **重看不是完整的入边重放。** replayBtn重建当前步骤并使用animate:false；部分CSS效果会重启，旧位置到新位置的过渡不会完整重播。公共层应保持已有准确replay语义。
5. **固定延迟不是完成依赖。** 接收端token为380ms加每项45ms；字节结果最后一项按CSS推算515ms结束，比特结果最后一项695ms结束，核对徽标却固定在280ms开始。不能把这组参数固化为所有长度的公共规则。
6. **整体DOM重建存在边界。** 小规模纯展示可依靠稳定key恢复视觉身份，但不自动保留输入焦点、外部引用或组件事件。公共层保持实例/可交互节点，适配器允许内部重建即可，不需要强推一种DOM实现。
7. **几何实现只处理水平位移。** 原版只计算dx，没有通用的纵向、尺寸或任意SVG变形能力。应提炼前后布局补偿的方法，再按接入对象补足能力，不能把这段代码直接称为全场景过渡引擎。

这些是从源码及参数计算确认的边界，不是新增的浏览器实测结论。

## 11. 向公共层提炼什么

| 旧版已经证明可行的做法 | 公共层可提炼的能力 | 仍由内容作者负责 |
| --- | --- | --- |
| 稳定key及完整目标画面 | 按身份捕获前后布局，生成整组过渡并保持结果可恢复 | 对象身份、目标内容与停点 |
| 外层让位、内层入场/强调 | 区分动画载体与属性所有权，组合移动、入场和值变化 | 何种变化值得突出 |
| 同一数据线中有关系的重叠 | 支持效果相对时机，统一完成与取消，不强制逐组件收尾 | 因果先后、主次与观看重点 |
| 逻辑端点括线与目标位置标注 | 目标布局锚定/运动跟随等定位策略，必要关系提示的生命周期 | 关系含义、说明文本 |
| 预留槽位、保留来源与删除证据 | 可选稳定空间、来源参照和痕迹保留的接入支持 | 画面采用何种比较方式 |

可采用“捕获前态 → 提交目标画面 → 测量目标 → 生成配合效果 → 完成/取消”的内部实现结构。它是从样本提炼的候选，不是现行 API；无需先开发任意时间轴或自动教学系统。

这些机制可作为公共实现的结构参照，但不是现行 API；其中已落地的部分以 [公共编排层](公共编排层.md) 的接口与 [公共层设计与取舍](公共过渡能力设计.md) 的边界为准。
