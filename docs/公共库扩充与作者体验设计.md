# 公共库扩充与作者体验设计

## 1. 目标与设计边界

降低作者从知识需求到可阅读 HTML 的重复劳动：少写通用图形、过渡与接入胶水，少猜接口，少为观察工具排错，同时保留作者对知识、观察重点和特殊表达的判断。

公共库可以根据真实制作需要扩充。已有组件和早期接口不是永久边界；有复用价值时，可完善组件、增加机制、提供组合配方或改进工具。普通制作与必要公共改进可以在明确任务范围内结合。

三类资产分工：

| 类型 | 责任 | 例子 |
| --- | --- | --- |
| 组件 | 显示对象、状态，提供稳定目标与控制接口 | 表格、设备端口图、阶段轨、报文图、长度条 |
| 机制 | 表达对象与状态怎样变化 | 沿线传播、复制分发、字段插入、行值替换 |
| 配方与接入辅助 | 复用布局、接线和生命周期处理 | 图形加状态表、阶段加报文、连续画面 Adapter |

领域规则、数值计算、字幕内容、必要因果和观察任务由作者提供。公共能力不内置 PPP、VLAN、自学习等课程规则，不从数据差分推断知识重点。

沿用现有普通 JavaScript/CSS、经典脚本、离线交付和 NoteDemo 运行方式。新能力接入现有 scene、效果组、取消、恢复和完成边界，不另建播放器或解释型时间轴。

本文件描述扩充目标与接口职责；现行支持范围以模块 API 和真实实现为准。开发时优先沿用已有同义入口，公开名称由整体接口核对确定，不为命名建立重复能力。

## 2. 继续复用的基础

以下已有能力不重复建设：

- NoteExpr.Range 的 offset，可组织不同层次括线。
- Field 的 hintSlot/errorSlot、NumberInput 的 messageSlot。
- Notice 对非法内容的明确反馈、Metric 的局部 Tokens 覆盖。
- scene 的效果组、来源保持、CSS transition 接管和恢复释放。
- effects 上下文中的 timing、减少动效直接呈现终态的接入规则。
- NoteDemo.compile、collectSlots、focusWorkbench。
- 查询 CLI、本地 inspect-note 和 build-demo-preview。
- 同布局内稳定预留、宽度变化后重新测量的默认舞台。

完善这些能力不等于维持原有内部实现。可以直接删除被替代的重复代码，保留仍有实际用途的入口和用法，不维护新旧两套同义实现。

## 3. 总体职责与依赖

制作阶段：MD/任务与阅读共识 → 作者判断 → 查询资料 → 组件、机制和配方 → 本篇装配 → 构建与必要观察。

阅读阶段：本篇领域模型与 Definition → NoteDemo → Adapter 与效果组 → 组件/图形；Presentation 配合字幕、控件和焦点。

| 部分 | 持有的事实 | 不承担的判断 |
| --- | --- | --- |
| 领域模型 | 事件、数值、条件和合法状态 | 不按焦点快慢修改因果 |
| 组件/图形 | 实例内容、稳定对象身份和实际目标 | 不选择本篇知识重点 |
| Adapter/接入辅助 | 提交、来源视觉、效果、读回和恢复的连接 | 不另持有会话历史 |
| scene/controller | 启动、依赖、完成、取消与导航 | 不解释领域含义 |
| Presentation/Focus | 阅读区域、观察交接和必要视觉提示 | 不自动推断应该框哪里 |
| CLI/Skill | 可核实资料、制作判断与按需入口 | 不代替组件执行或领域模型 |

领域时间、动画进度和观察顺序分别表达。必要并行不因逐处观察被改写；主要变化在对应观察范围及时展开，辅助状态可以同步更新。字幕不进入 Focus 迁移路径。

## 4. 聚焦与观察区域

### 4.1 默认外观

公共 attention 默认使用清楚描边、连续迁移、停稳虚线弱化。移除遮淡文字或邻近标记的半透明填充、内外辉光及循环呼吸。外观整改与运动、ready/finished 和内容放行分开处理。

基础 Focus、公共 attention 和弱化态的职责清楚，不能在公共皮肤重新叠回同样的装饰。此选择不扩成全部组件禁用蓝色或阴影，也不通过整体降低透明度削弱框线可辨认性。

### 4.2 有效范围与目标存续

- 区分节点存在、布局几何有效、内容在当前阶段可理解三件事。
- display:none、断开节点等不可用几何不能被当作视口原点参与迁移或 union。
- 待入场内容 opacity 为 0 不自动等于非法目标：应有真实可定位区域，并由来源内容和正确展开时序避免空框等待。
- SVG 线、点可能天然零宽或零高，不能一律按零尺寸拒绝；由图形提供合适区域或显式范围。禁止的是无效几何被静默当成正常矩形。
- 主目标默认必需。union 辅助成员可在确有需要时显式声明可选，必需成员失效明确定位；不自动忽略全部错误，更不退化为整屏大框。
- 目标重建后按逻辑身份重新连接。正常迁移从当前可见框承接，保留上一步有效落点；不能回到屏幕角落再飞入。
- 在现有 target/local/union 基础上提供相对真实范围的外扩、内缩。明确坐标单位，窗口变化重新测量，避免作者只能写死整块宽高；已有默认外扩不可重复叠加。

### 4.3 连续与重新建立关注

正常连续推进承接上一视线。换段或整体视觉重组时，可由作者明确重新建立关注，不以自动跳过迁移解决所有等待。

迁移仍采用统一的对称加减速规律；跟随继承对象实际运动。长距离等待先检查布局、路线、观察停留和内容启动。保留回退/重看按对应步骤初态重启、允许焦点跳变的简化规则。

## 5. 连续画面接入辅助

提炼通用 Adapter 胶水，作者提供领域视图、绘图方法、目标解析及局部变化计划；公共辅助组织既有接口，不复制 scene。

| 路径 | 模型与画面的责任 |
| --- | --- |
| 普通过渡 | 同步提交完整目标模型；未放行画面保持来源；对应效果组获得许可后及时推进 |
| 正常结束 | 目标视觉完整接管，释放临时副本与受控样式，不再迟到改变内容 |
| 减少动效 | 直接呈现完整目标，不等待不会创建的 progress/ghost |
| 直接恢复 | 完整呈现指定停点，避免残留 CSS transition |
| 取消/错误 | 使用现有运行身份与恢复路径，释放自己拥有的效果和临时资源 |

复用当前受控容器、来源与终态交接、效果句柄及真实读回规则。Adapter 不另建预期缓存冒充组件读回；模型事实和必要视觉观察分别验证。

时序规则：

- 消费 effectCtx.timing 的最终值，合法 0 有效，不夹入未声明的最低时长。
- progress 是否已应用 easing 清楚可查。局部自行分段缓动时，避免再次无意套用全局缓动。
- ready 表示后续可承接，finished 表示必要效果与清理完成；观察停留不重复充当内容延时。
- 提供按需时序观察能力，能区分焦点到达、效果启动、ready 与 finished，并关联 Frame/Binding/组。可通过已有订阅或窄回调提供，默认关闭、不写文件，不参与运行决策。

## 6. 组件与机制扩充

### 6.1 表格状态与过渡

以 C06 Table 为基础，完善稳定行、单元格身份和目标查询；改变局部值或强调时不无条件重建整表。明确排序、空行、内容更新与实例清理关系。

支持作者声明的当前、新增、刷新等可替换行状态，提供局部值替换、提示与 scene 接入。状态标签按理解需要出现，不自动给对象塞“关注/变化”元文字。

行键与列键定位真实对象。相同行内容、表项计数、字幕由本篇领域状态生成；不内置交换表学习、路由更新或老化规则。

### 6.2 Graph 边与连接路径

扩展现有 Graph 的边身份、边目标及边关注/变化能力，让 ProcessFlow 复用正式接口，替换仅能在图下另画“当前边”文字关系条的绕法。节点接口与边接口清楚区分。

提炼已有 Link/Graph 中适用的锚点、路径测量和尺寸更新能力。路径提供稳定身份、端点、长度/位置查询及可观察目标，服务箭头、旁路和传播。明确 DOM 视口与 SVG 局部坐标转换，不把元素中心连线误当作所有布局的语义。

采用作者声明路线和有限的常见路径形态，不要求任意避障、自动路由或复杂图编辑器。

### 6.3 设备—端口—链路图形

提供数据驱动的设备、命名端口、连接关系、状态和目标查询。设备、端口、链路均有稳定 ID；可定位端口、设备内容、链路和组合观察区域。

支持作者布局与必要的默认排布，允许替换设备标签及局部表现。不写死设备数量、课程图标、六端口布局、VLAN 颜色或接受规则。

### 6.4 沿线传播与一对多分发

在公共路径上表达对象发出、沿线运动、多个副本和到达；复用稳定对象身份及现有公共 progress/效果组。支持明确的同时、错开或必要依赖，不自行增加计时器播放器。

副本身份、目的与接收含义由作者给出。传播到达不自动等于接受，不从复制数量推断广播或泛洪。取消、重看、减少动效使用同一运行层。

### 6.5 阶段轨与旁路

复用 Steps、Timeline、Graph 的适用能力，提供可独立控制的阶段轨及显式旁路：当前、完成、跳过、失败等状态由作者传入，旁路端点与目标可查询。

物理连接、链路配置与网络配置等领域状态仍由作者判断。图上存在分支，不要求运行层实现完整分支剧情系统。

### 6.6 报文交换图形层

从现有 B08 SequenceDiagram 提炼可脱离内部 StepPlayer 使用的图形能力，表达参与者、方向、消息和逐步显现。原组合块可消费同一图形层，避免重复绘制两套。

参与者和消息具有稳定 ID 与目标，支持必要状态更新和公共过渡。阶段轨、报文与读数由 NoteDemo 共同协调，不嵌套两套按钮、字幕与播放器。

### 6.7 分段长度与字段变化

新增适合真实长度的分段条能力。真实值、显示尺度、最小可读宽度分别表达；支持零长度、数值变化、字段插入/移除、标签与范围目标。

比例放大或非严格比例有明确说明，不能因最小宽度暗示错误长度。图形目标供现有 Range 组织多层括线，避免另造重复批注系统。

字段插入、后续让位与标签显现可受公共 progress 控制。D01 等宽序列保留其用途，不强行变成比例长度图。填充量、帧长和标记含义由作者计算。

### 6.8 小型便利扩充

- Notice 接受节点数组，复用内容插入工具；字符串、单节点和非法对象的行为明确，校验失败不先破坏旧内容。
- Slider 支持可选刻度和显式分段映射，线性保持默认。值与位置关系单调、可核对；输入和键盘按真实值工作，边界与步长一致。移除一概禁止非线性映射的措辞，不为单个例子内置特殊阈值。
- Metric、Range 和输入提示继续使用已有配置，不为某页重复增加等价参数。

## 7. 组合配方与作者状态组织

提供可复用的图形加状态表、阶段加报文和读数、长度条加参数控件、共享尺度加比较结果等组合接法。

配方负责槽位、布局、组合及清理，允许省略无用区域；不强制四区域、右侧栏、固定页面比例或整篇主题。

重复数据与阶段的展开复用 NoteDemo.compile，可提供小型函数或示例，输出原有完整 Frame/Transition；不引入第二套运行定义。字幕、计数和图形尽量从同一领域快照派生，避免手写常量相互矛盾；公共层不生成知识解释。

## 8. 查询、文档和 Skill

### 8.1 查询资料

新组件、配方、接入辅助与工具通过现有 CLI 可查。所有条目保持准确的短用途、关键限制和资源入口，高频能力补充别名、差异、scene 上下文与最小接法。

清单负责实现与依赖事实，语料负责用途词和关联，API 负责参数与行为，示例负责真实用法。避免手工复制完整 API；show 的依赖闭包、支持模式和资源边界与实现一致。

查询仍是一次性本地 Node CLI，不建设 MCP、常驻服务、向量库或独立模型决策层。

### 8.2 文档阅读层次

按接入任务、运行 API、聚焦与过渡区分入口，将关键上下文、groups 三态、progress/easing、timing 与减少动效路径集中说明。可拆分职责明显不同的长文档，但不为凑页数拆分，也不保留重复 API 副本。

迁移章节同时更新锚点、CLI 引用、示例、打包与实际消费者。设计文档保留职责和理由，模块文档保留真实接口；删除过时过程旁白，不将其改写成逐轮验证记录。

### 8.3 Skill

SKILL.md 保留制作判断与按需导航，完整共识和制作底稿由参考文件承载，继续通过现有脚本同源同步。

独立取用试验可把库设为只读；允许扩库的任务可以补齐共享能力，不把一次试验限制升为长期禁令。发现重复成本时先比较现有实现，再决定完善接口、增加配方或组件。

沿用有效上下文，未知能力先定位，具体疑点再深入。官方最小示例与旧试作不是同一种资料；禁止读取旧试作属于特定独立测试条件。

## 9. 构建、观察与诊断工具

build-demo-preview 补齐 --help 和清楚的错误，说明模板、输出、内联资源与限制。现有命令保持清楚一致，不让作者为了知道参数通读源码。

默认呈现提供稳定的画布、字幕、控件、进度定位方式，避免 probe 猜私有 CSS 类。优先采用根内语义定位、既有实例引用或窄查询入口，不公开整个内部 DOM 作为长期契约。

inspect-note 增加可复用的推进、等待完成、读取状态、采样过程等辅助，让普通 JS probe 在同一个浏览器页面内组合必要观察和少量截图。使用现有 Edge/playwright-core，不另搭环境或常驻测试服务。

会话实际 phase、真实 next/replay、浏览器计算样式和观察事实共同说明过程。go/restore 只证明停点恢复；打开成功和工具执行成功不等于作品通过。

公共时序诊断按需提供，不默认写日志、截图或报告。截图次数、代码行数和调用数只解释成本，不当作质量或精确性能指标。

## 10. 分发依赖

默认舞台、其他组合块、作者配方与内容组件的依赖分开。DemoStage 不应仅因处于 blocks 包，就强制带入图表、公式、Markdown 等不需要的能力。

根据源码真实依赖拆分模块或入口，保持一个维护源与生成链；整库入口继续方便使用，按需模块只带实际闭包，单文件构建只内联模板采用的资源。

新增能力及模块拆分后，更新 manifest、expected-ids、registry 生成、加载顺序、文档与打包，不固定原有组件和模块数量，不手改生成物。

使用同一代表作品比较资源清单和构建体积，不以任意 MB 指标驱动重写构建系统。不建设通用打包器或复制 vendor 资源。

## 11. 协同边界与集成顺序

主控先核对实际接口、依赖和使用点，统一目标查询、稳定 ID、效果组、状态更新与最小可执行契约，再分派明确文件所有权。

| 工作流 | 主要责任 | 依赖/交接 |
| --- | --- | --- |
| 公共接入与聚焦 | 有效范围、默认外观、连续接入、时序事实和生命周期 | 与图形实现者先约定目标和效果协议 |
| 表格与基础控件 | C06、Notice、Slider 的实现与接口 | 向接入方交稳定目标、状态和支持能力 |
| 图形底座与传播 | Graph 边、路径、设备端口、传播机制 | 路径和目标契约先行，再实现传播 |
| 阶段、报文与长度 | 独立图形、字段变化和必要 Adapter | 消费统一目标、效果和接入方式 |
| 组合与作者辅助 | 配方、重复阶段展开和最小用法 | 底层入口确定后集成，不复制实现 |
| 工具与分发 | 构建 help、观察辅助、模块闭包与生成 | 构建配置、清单归属与生成只有一个负责人 |
| 文档与收口 | 现行接口、查询语料、Skill 同步和验收 | 主控统一处理，避免多方改同一文档 |

按可用并发和文件冲突分批运行，不要求同时开满所有方向。共用文件提前确定归属；实现者发现上游缺口回报，不复制或私改另一模块。

先贯通一个真实的最小组合，之后并行补齐独立能力。必要契约调整由主控决定，内部重构可直接整合；不机械串行全部工作，也不要求每位执行者重新提炼全局讨论。

## 12. 验收与结束条件

先少量真实样例确认表现，再对受影响行为做必要检查。现有有意义的回归继续复用，新增检查针对实际缺陷与新规则，不新建全量测试平台。

代表性覆盖：

- 表格：稳定行/单元目标、值与状态更新，正常推进、取消恢复及减少动效。
- 路径与传播：路径目标、多个副本身份、到达与接受分开、无临时残留。
- 阶段与报文：旁路关系、逐步显现、与读数协调，不出现嵌套播放器。
- 长度与字段：零长度、阈值两侧、字段插入与目标范围，模型值和显示映射一致。
- Focus：无辉光遮淡、正常连续承接、隐藏目标不污染范围、换段与恢复边界明确。
- 作者取用：CLI 能取得真实依赖和最小接法，辅助不要求通读实现才能使用。
- 分发：整库、必要模块组合与离线成品可打开，无多余网络依赖，许可齐全。

公共 CSS 接管、恢复释放等通用故障由公共回归覆盖，普通作者不每篇重复注入故障。局部改动不默认跑全库浏览器矩阵、全部视口、像素断言或独立审查。

外部旧试作按需少量回接，替换重复实现、保留知识与已经有效的演出；不以回接为由重新设计所有作品。新能力同时具有中性最小用法，证明不依赖某篇课程内容。

完成标准是可查、可调用、可组合，重复绘图与接入劳动确实减少，必要行为可靠。技术检查、实际动态观察和用户评价分别表述。必要验证通过后结束，不为验收材料重复取证。

设计文档在实现后直接整理为有效职责、接口理由和边界；任务分工、阶段耗时和完成流水不进入现行 API 文档。
