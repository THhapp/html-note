# 自定义画面接入

本页是默认自定义连续画面的直接入口：先用 `NoteDemo.sceneAdapter.define` 把一张自己绘制的画面接入公共 scene，完成一次有意义的局部变化。完整参数、原生 Adapter 和进阶能力仍以[公共编排层](公共编排层.md#author-scene-adapter)为准，本页不另写一份 API。

## 1. 什么时候用哪种入口

| 接法 | 适合 | 恢复入口 | 效果入口 |
| --- | --- | --- | --- |
| `sceneAdapter.define`（默认） | 普通自定义画面、局部变化、希望少写 Adapter 胶水 | 作者实例的 `restore(model, view)` | 计划的 `effects(timing, meta)`，`timing` 已是最终值 |
| 原生 BindingHandle | 需要直接控制 `prepareChange`、`targets`、`sourceElements`、`facts` 等完整契约 | `restore(view)` | `PreparedChange.effects(ctx)`，从 `ctx.timing` 取时序 |

两种入口都保留，不是迁移关系。先选默认 helper；只有需要直接控制完整 Adapter 契约时再读原生接法。不要把 helper 的 `restore(model, view)` 写成原生 `restore(view)`。

## 3. 加载、Definition 与挂载

整库加载后，公共演示入口在 `NoteDemo`：

```html
<link rel="stylesheet" href="../../dist/note-library.css">
<script src="../../dist/note-library.js"></script>
```

一个最小 Definition 只需要作者能讲清的两三个停点：

```js
var definition = {
  initialFrameId: 'initial',
  bindings: { scene: { adapter: 'my-scene', slot: 'scene' } },
  frames: [
    { id: 'initial', caption: '初始状态', views: { scene: { value: 0 } } },
    { id: 'changed', caption: '一次局部变化', views: { scene: { value: 1 } } }
  ],
  transitions: [{
    from: 'initial', to: 'changed',
    scene: {
      bindings: [{ binding: 'scene', mode: 'update' }],
      timing: { enterDuration: 420, easing: 'linear' },
      attention: {
        targets: [{ binding: 'scene', query: { part: 'value' }, groups: ['value'] }]
      }
    }
  }]
};
```

`views.scene` 是作者领域视图；`normalizeView` 把它变成可序列化的 `{ model, cues }`。`attention` 的 `query` 是目标元素查询，`groups` 是焦点到达后要放行的效果组。挂载时把 Adapter 放进 `adapters`，用默认舞台：

```js
var session = NoteDemo.mount(document.querySelector('[data-demo-host]'), {
  definition: definition,
  adapters: { 'my-scene': myAdapter },
  layout: function (container) { /* 建 slot[data-demo-slot="scene"]，返回 { root, slots } */ },
  title: '示例标题'
});
window.__inspectSession = session; // 便于本地观察入口默认找到会话
```

自有舞台时用 `NoteDemo.create`，但默认舞台已负责画面容器、字幕、控制条和 Focus。最小示例只需要自己的`layout`把画面放进 slot。

## 4. 作者与公共层各负责什么

| 作者负责 | 公共层负责 |
| --- | --- |
| 领域 model、视图和正/反向规范化 | Definition/Frame/Transition 编排、定时与几何等待 |
| 绘制、恢复、当前真实状态读回 | Binding 生命周期、受控容器接管、CSS transition 暂停 |
| 目标元素查询、局部变化计划 | `attention` 焦点移动、效果组门控与取消 |
| 本步哪些组变化、来源视觉如何保持 | 运行中推进锁、ready/finished 结算、恢复/回放 |
| `progress` 的绘制与领域值换算 | 启动/取消/完成 EffectSpec、最终 timing 透传 |

作者不需要另写播放器、私有暂停层、第二套 rAF 或等待函数；也不要在 helper 之外伪装 Adapter 的读回。

## 5. 必要契约

`NoteDemo.sceneAdapter.define(spec)` 的常用字段：

- `name`：非空字符串，与 Definition 的 `adapter` 名一致。
- `sceneModes`：常用 `['update']`；需要 cut 等模式时按公共场景接口声明。`defaultSceneMode` 必须在列表中。
- `sceneTimingDefaults`：可选稀疏 timing，数字 ≥ 0，`easing` 非空字符串。
- `normalizeView(input, options)`：返回 model 对象或完整的 `{ model, cues }`，不能只返回一半。
- `mount(host, options)`：返回作者实例。

作者实例至少提供：

```js
{
  restore: function (model, view) { /* 直接呈现 view.model，不播动画、幂等、保留对象身份 */ },
  readModel: function () { /* 读真实实例状态，不返回缓存的目标 */ },
  target: function (query) { /* query -> 真实元素或 null */ },
  planStep: function (input) { /* 见下 */ },
  destroy: function () { /* 移除画面与监听 */ }
}
```

`mount` 返回的实例也可以选择 `readView()`、`cues()`、`applyCues()`、`settleVisual()`；只有确实需要时使用。scene 参与者应保证 `readModel` 能核对提交后的真实状态。

`planStep(input)` 的输入含：

```
{ bindingId, sourceFrameId, targetFrameId, sourceView, targetView,
  sourceModel, targetModel, motion, reduced, signal }
```

它可以同步返回计划，也可以返回 Promise。计划形状：

```js
{
  groups: function () { return ['value']; }, // 本次实际变化的组
  commit: function () { /* 必须同步提交完整目标 */ },
  targets: function () { return []; },        // 可选：布局载体
  effects: function (timing, meta) {          // 只在非 reduced 时调用
    return [NoteDemo.sceneAdapter.progress({
      group: 'value',
      duration: timing.enterDuration,
      easing: timing.easing,
      gate: 'ready',
      update: function (p) { /* 只画本组变化 */ }
    })];
  },
  sourceElements: function () { /* 可选：需要公共层保持/交接的来源元素 */ },
  cleanup: function () { /* 只释放本步临时资源；不承担最终显示 */ }
}
```

关键点：

- `commit()` 必须同步提交完整目标；只有 `planStep` 允许同步或异步。
- `effects(timing, meta)` 收到的 `timing` 已是 scene 合并后的最终值，0 合法；`meta` 含 binding、motion、attention、grouped、groups，可用于诊断/调整，不必自行重算默认。
- `groups()` 声明本次真正变化的效果组。`effects` 的每个 spec 必须属于某个已声明组；未声明组时 spec 不带 group。
- `sourceElements()` 用于公共层在提交前捕获来源视觉；没有需要交接的来源时不要伪造。
- `cleanup()` 只清理临时资源；不能等它来第一次显示目标内容。

## 6. 组、attention 与来源视觉

是否使用公共 Focus，按阅读需要决定。对象运动、对齐窗口或局部强调已经清楚指出本步变化时，不必额外叠框。主要变化仍应有主次和承接，解释不应散落在多处或藏成小字；完整阅读原则见[设计共识 K03、K06、K09、K17](设计共识.md)。

`attention.targets[].groups` 与 Adapter 的 `groups()` 按名字对应：

- 目标到达前，未放行组保持来源视觉；别的组的绘制不能提前覆盖它。
- 组内的图形、文字、提示和局部副本由 Adapter 自己完整覆盖；公共层校验归属，不推断领域。
- `groups:[]` 是只观察、不启动内容的合法接法，但不能拿来消除等待。
- 不需要 Focus 的辅助读数不必强行分组；它们什么时候能更新按“目标/阶段说明”与“已发生事实”区分，见[设计共识](设计共识.md#k18-目标说明与已发生事实)。

**部分过渡使用 attention**：可以只在需要引导的 transition 声明 `scene.attention`。省略它时，效果组不等待焦点到达，仍按原有 `after` 等依赖启动，并非无条件同时启动全部效果。默认舞台正常向前推进到无 attention 的停点时，上一目标仍有效则保留弱化线索，目标失效则清除；省略 attention 不等于显式清除旧框。回退、重看、重来、跳转和减少动效继续使用各自的导航处理。若需要混用，既判断本步是否需要新引导，也判断上一弱化线索是否仍有阅读意义。

**来源视觉**：`commit()` 提交目标模型后，本步未放行的组应继续显示来源值/来源视觉；已放行组由 `progress` 从来源推进到目标。不要在一次 commit 里把所有内容瞬间改成目标后再统一淡入，也不要用外层 opacity 遮罩假装局部变化。

**恢复与减少动效**：`restore(model, view)` 必须直接呈现该停点完整画面，不依赖稍后才执行的 effects。reduced 时 helper 跳过 `effects`，`commit()` 应直接呈现目标终态；不要等待不会出现的 progress。无论正常、恢复还是 reduced，最终 `readModel()` 都应等于目标停点的真实模型。

三条路径要分别处理：

| 入口 | 模型与可见画面 |
| --- | --- |
| 普通 update 过渡的 commit | 同步提交目标模型，同时在受控事务内建立各未启动组的来源视觉；组开始后才推进相应变化 |
| restore 恢复停点 | 模型和画面直接呈现该停点完整状态，不暗播中间步骤 |
| reduced 过渡的 commit | 模型和画面直接呈现目标终态，不依赖 effects 或其 update 回调 |

例如自定义画面已有 `paint(from, to, p)` 时，普通过渡可先呈现来源，再由 progress 绘制到目标；恢复与 reduced 则直接绘制目标。这里说明视觉职责，不要求每个 Adapter 都重画整个来源画面；需要构造目标布局或使用局部载体时沿用对应接法。关键是浏览器绘制时没有提前露出尚未启动的目标，而不是仅在变量里记下来源。

## 7. 读数与画面一致

阶段名、模式、目标参数可以随提交更新；“已收到/已发出/已完成”等事实必须随领域事件或实际展示进度更新；预期结果可以提前显示，但要明确是目标/预期。是否进入 Focus 与何时更新数值分别判断，不要求所有计数分组、动画或逐处巡视。

在最小示例中，辅助状态可以写“目标已提交/等待放行”；真正的“已显现/已完成”应在 progress 完成或终态恢复时更新，不能由 commit 提前写成完成。

## 8. 本地观察

源码入口可以直接打开；需要指定停点时使用现有观察工具：

```powershell
node scripts/inspect-note.mjs "examples/continuous-scene/minimal.html" --frame changed --session "window.__inspectSession" --json
```

- `--frame <frameId>` 只调用公开 `session.go(frameId)` 恢复停点，确认实际落点后再截图/probe；它证明静态停点，不证明动画。
- 过程检查用 probe 内的 `next()/replay()` 真实推进；需要观察中间值时用 `inspect.sample()`，不要批量截静态图猜过程。
- 参数以 `scripts/inspect-note.mjs --help` 和实际返回为准；失败时保留页面观察事实，不把工具执行当作品验收。
