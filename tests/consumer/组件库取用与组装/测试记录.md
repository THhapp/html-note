> 范围：本轮只覆盖下面两个场景与所列组件；结论不扩成 99 项验收，也不替代用户评价。
> 以下 §1–§11 保存初次独立消费测试及当时的位置。原测试阶段的正式库（当时位于 `<旧候选库目录>/`）只读；目录已整合，现行位置与本轮复核见 §12。

## 0. 结论摘要

- **能取用**：只读 README、registry、模块文档即可选出组件并跑通主路径；12 个组件按模块加载，页面无 gallery 外壳、无外部请求。
- **需要翻源码的地方有 3 处**：Focus 的「框 / 下划线」互斥、M01 没有停稳回调（外部标记要自己跟帧）、B01 `setControls` 会重建按钮（想保住焦点必须传 DOM）。
- **组合边界 1 处**：B02 StepPlayer（整快照重绘）与 M01 SequenceEdit（有状态动作、undo/replay 依赖实例历史）不能同时成立；已用最小探针固定事实，场景 B 改用 B01 + 宿主步表 + 单个常驻 M01。
- **没有确认的实现缺陷**。已记录的问题集中在文档缺口（3 条）与组合参数/观感（5 条），最值得先补的是文档。
- 交付：两个自包含 HTML、离线 ZIP、本记录；103 项自建核对全部通过（这些是本次场景核对，不是库的验收项）。

## 4. 场景 A：矩阵转置知识页

### 4.1 页面结构

标题「矩阵转置：行列互换，数值不变」→ 一句导语 → 对应规则（`B_{j,i}=A_{i,j}` + 尺寸句）→ 两个矩阵（A 2×3 / B 3×2，各有一格虚线关注）→ 图注（同一元素 3 ↔ 3）→ 三组元素位置表（第 2 行高亮）→ 换一组数据（Segmented + Notice）→ 范围小字。

### 4.2 实测事实

| 核对 | 结果 |
| --- | --- |
| 公式 | `.katex` 1 处，隐藏错误区未显示；`role="math"` + 中文 label；断网后仍渲染（字体为 data URI） |
| 矩阵 A | 2 行 × 3 列、6 格，值 `1,2,3,4,5,6`，表头「行 1/2」「列 1/2/3」，caption「转置前 A · 2 行 × 3 列」 |
| 矩阵 B | 3 行 × 2 列、6 格，值 `1,4,2,5,3,6`，caption「转置后 B · 3 行 × 2 列」 |
| 关注 | A 仅 `r1/c3`、B 仅 `r3/c1` 为 `data-direct-mark="focus"`，组件下方同步写「标记：关注单元 1。」 |
| 例子 | 图注与表格第 2 行都是「A 第 1 行第 3 列 = 3 → B 第 3 行第 1 列 = 3」 |
| 换数据 | 切到 3×2：A 变 3 行 2 列、B 变 2 行 3 列；A 的表头只剩「列 1/列 2」，**无「列 3」残留**；关注自动落到 A(1,2)/B(2,1)，值均为 8；示例句、尺寸句、表格值（7,8,12）同步 |
| 布局 1280 | 两矩阵并排（同一行），矩阵不需内部横向滚动 |
| 布局 1024 | 仍并排，`scrollWidth = innerWidth`，无页面横向滚动 |
| 布局 700 / 560 | 上下排列；矩阵宽度 664 / 524，`scrollWidth = clientW`，无内部滚动 |
| 125% 缩放等效 | 无横向溢出，标题与矩阵均未被裁切（`evidence/a-zoom125.png`） |
| 键盘 | Tab 顺序：公式块 → 矩阵 A 滚动区 → 矩阵 B 滚动区 → 表格滚动区 → 分段选择；均有 3px 可见焦点环；方向键可切换示例并重绘 |

截图：`evidence/a-1280-full.png`（整页）、`a-1024.png`、`a-560.png`、`a-zoom125.png`。

### 4.3 观感

- 图与说明的物理距离足够近：图注紧贴矩阵下方，表格紧接着给出三组位置；不需要来回翻。
- 两个矩阵高度不等（B 多一行），各自的「标记：关注单元 1。」落在不同高度；不影响阅读，但整块略不齐。
- 「标记：关注单元 1。」在单格关注时容易被读成「关注第 1 个单元」（数字其实是数量）。本页靠图注与虚线框消歧，未改组件文案。

## 5. 场景 B：序列删除与交换

### 5.1 组织方式

- 机制：一个常驻 `NoteViz.SequenceEdit`（身份 a–e，`animate: true`）。
- 舞台：`NoteBlocks.DemoStage` 持有机制根、固定字幕与四个按钮；按钮是宿主创建的 `NoteUI.Button` 实例，只把 `.el` 交给 `controls`，因此可按步 `update({disabled})` 而不丢节点。
- 标记：`NoteExpr.Focus` 单个实例；第 1 步框 `d`（删除后顶到第 3 位的对象），第 2 步框 `e`（换到第 2 位的对象），第 0 步 `hide()`。
- 步表由宿主维护（3 个停点，2 个动作），符合 M01 文档「播放/回退由宿主按钮调用实例方法」的分工。

### 5.2 停点、字幕与按钮

| 步 | 动作 | 序列 | 字幕（数据驱动，摘要） | 上一步 | 下一步 | 重看 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | — | `a b c d e` | 初始序列共 5 个对象，身份 a–e… | 禁用 | 可用 | 禁用 |
| 2 | 删除 `c` | `a b d e` | 删除身份 c（显示为「C」）：它离场，后面的对象依次前移一位；外框标出顶到第 3 位的 d。 | 可用 | 可用 | 可用 |
| 3 | 交换 `b`、`e` | `a e d b` | 交换身份 b 与 e：「E」换到第 2 位，「B」换到第 4 位；外框标出 e 的新位置。 | 可用 | 禁用 | 可用 |

实测：上一步两次回到 `a b c d e` 且字幕回到初始、标记隐藏；重来从末步一步回到初始；重看不改字幕、不改 `getState()`；末步换数据回到 5 项第 1 步、无 ghost、无标记。

### 5.3 动效取样（正常速度）

删除 `c`（点击后计时，取 `transform` 与左边界）：

| 时刻 | d 左边界 | d 的 transform |
| --- | --- | --- |
| 0ms | 523 | translate3d(82.7, 6.9) |
| 60ms | 518 | translate3d(77.6, …) |
| 120ms | 476 | translate3d(36.1, …) |
| 240ms | 447 | translate3d(7.0, …) |
| 400ms | 440 | translate3d(0.6, …) |
| 560ms | 440 | none（ghost 已清理） |

重看第 2 步：0–200ms 停在「变化前」并显示「重看上一步 · 先呈现变化前状态」，约 250ms 开始位移动画，约 700ms 落定，状态行恢复「已交换「B」与「E」 · 共 4 项」。

判断：单次动作约 0.5s、重看约 0.7s，属于可追踪范围，不需要读者追赶；但删除动作的**前半段极快**（83px 位移中的大部分在前 ~150ms 完成），离场 ghost 在 285ms 内淡出，同时后一项滑入其位置，实际看到的是「瞬间合拢」，不太看得出被删对象是「离开」而不是「被覆盖」。

### 5.4 标记协作

- 关注框在动画中途跟随移动对象：80ms 与 200ms 两次取样，框中心与 `e` 中心差 ≤6px（逐帧取样本身的容差，连续 5 次重复运行稳定）。
- 关注框与 M01 自身的变化提示不冲突：对象上显示「变化」文字与浅底，框只出现一个，未叠加第二套圈。
- 停稳后框保持在最终位置；`hide()` 后 body 上的标记层立即隐藏。

### 5.5 换标签与长标签

| 数据集 | 身份 → 显示 | 结果 |
| --- | --- | --- |
| 字母 | a–e → A…E | 基准 |
| 流程 | a–e → 读取/校验/编码/缓存/输出 | 换标签后回第 1 步；两步后为「读取/输出/缓存/校验」 |
| 长标签 | 「读取请求与身份信息」等 5 条 | 560px 下卡片换成 2 行，单卡不超出舞台，页面无横向滚动；字幕换行后仍完整 |

策略已在页面上的常驻 Notice 写明：「切换显示标签后停在第 1 步（初始序列），不保留当前步」。

### 5.6 边界与减少动效

| 情形 | 观测 |
| --- | --- |
| 动画中连点两次「下一步」再「上一步」 | 终态 `a b d e`、字幕与删除步一致、无 ghost |
| 减少动效 | 60ms 时已是终态（`d` 与 600ms 后同高同位），无 ghost，`data-anim` 不为 running |
| 键盘 | 焦点在「下一步」按 Enter 推进；重绘后焦点仍在同一按钮（按钮节点未被替换） |
| 多实例/清理 | 另挂一个 SequenceEdit + Focus，动作、销毁互不影响；销毁后宿主无子节点、标记层回到原有数量、无 ghost |
| 末步换数据 | 5 项、第 1 步、无 ghost、无标记 |

## 6. StepPlayer × SequenceEdit：组合边界（最小探针）

探针：`evidence/step-player-probe.html`（同一批模块，B02 的 `steps` 是三个完整快照，`render` 内重新 `mount` M01）。实测：

| 操作 | 观测 |
| --- | --- |
| 初始 | 渲染 `abcde`，状态行「共 5 项 · 待操作」 |
| 点「下一步」50ms | 序列已是 `abde`；4 个 `li` 的 `transform` 全为 `none`；ghost 0 → **没有任何过渡** |
| 点「下一步」450ms | 与 50ms 相同 |
| 点「重看」 | `render` 收到 `ctx.replay=true`；宿主调用 `edit.replay()` 后状态行只变成「共 4 项」，无 ghost、无位移 → **重看没有发生** |

原因（源码定位，`src/viz/mechanisms.js`）：`replay()` 依赖实例内的 `replayFrom` 快照，而每次 `render` 都是新挂载，`replayFrom` 为 null，只更新状态文字。同理，`undo()` 的历史也随实例重建消失；删除步的「本步变化」标记也不会出现，除非宿主在每个 `step.state` 里自己写 `changed`。

结论：B02 适合「无状态渲染」的停点（静态图、纯数据快照），不适合驱动 M01/M02 这类有历史与动作语义的机制。场景 B 因此用 B01 + 宿主步表 + 单个常驻 M01：回退用 `undo()`、重看用 `replay()`、重来用 `reset()`，都是机制自身的公开方法，没有另写状态机。这个边界文档没有写，属于需要补的说明（§7-F3）。

## 7. 摩擦记录

分类口径：**调用**＝宿主写错；**文档**＝资料缺失/不明；**组合**＝组件之间或宿主布局的参数问题；**实现**＝可复现的组件缺陷；**观感**＝可用但可精修。

| # | 分类 | 现象 | 期望 / 实际 | 影响 |
| --- | --- | --- | --- | --- |
| F1 | 文档 | Focus 不能「框 + 文字」 | 期望 `show({el, mode:'box', text})` 在框旁给标签；实际 box 模式忽略 text（`text` 读回 null），带 text 即转为 underline 模式，找不到子串时抛 `NoteExpr.Focus: 在目标元素中找不到文本「…」` | 说明只能写进字幕；如需文字标注得改用下划线或自备说明 |
| F2 | 文档 | M01 没有停稳回调 | 期望有 `onSettle` 便于协作；实际只有 `onChange`，且在动作调用内同步触发，不是停稳通知。补充核对：M02/M03 提供此回调，M04 同样没有，不能以此推定 M01 违反既有接口 | 外部标记必须自己跟帧刷新（本次用 rAF 刷 760ms），否则动画中框会滞后 |
| F3 | 文档/组合 | StepPlayer 无法驱动 M01 | 期望 B02 的下一步/重看能播放动作；实际每步重挂载 → 无过渡、`replay()` 无效（§6） | 场景 B 改用 B01 + 宿主步表；若照文档直觉硬套会得到「静态换图」 |
| F4 | 组合 | `blocks` 模块粒度过粗 | 期望只用 B01/B02 时只加载它们需要的模块；实际模块声明含 ui-navigation、viz-chart，页面因此多载 2 个模块（约 180KB JS + 45KB CSS），单文件页 1.71MB | 取用成本；不影响运行 |
| F5 | 组合 | Grid 默认最小列宽与矩阵内容不匹配 | 期望 14rem 下并排仍可读；实际 700px 视口得到两列各 298px，而带「行 n/列 n」表头的矩阵需 408px，两个矩阵各自内部横向滚动。改为 22rem 后同宽度改为上下排列，内部不再滚动 | 宿主需按内容宽度调参；文档没有给出「带标签矩阵」的建议值 |
| F6 | 文档 | B01 `setControls` 会重建按钮 | 期望按步更新 disabled 时直接 `setControls`；实际它销毁上一批 Button 再重建，刚点击的按钮被移除、焦点回 body。传 DOM 节点可保留，但文档没说这是为了焦点 | 键盘步进会丢焦点；本次改为自建 Button 实例后 `update({disabled})` |
| F7 | 观感 | 「变化」文字让卡片变高、挤动邻居 | 实际 108px 宽卡片里「变化」换到第二行，卡高 48→62px；同行其它卡片宽度变化导致 x 位移（未参与交换的 `d` 也会移动 27px） | 不能拿绝对坐标判断「位置未变」；B01 的 `minStageHeight` 吸收了高度变化，否则字幕与按钮会上下跳 |
| F8 | 观感 | 删除的离场 ghost 几乎看不见 | 期望看到对象「离开」；实际 ghost 285ms 淡出并被后一项滑入覆盖，50/160ms 帧里只剩很淡的残影 | 删除读作「瞬间合拢」，损失一点可追踪性 |
| F9 | 观感 | Matrix 的「标记：关注单元 1。」 | 实际数字是数量，不是位置 | 单格关注时易误读为「第 1 个单元」 |

## 11. 对四个问题的回答

**1）一个新 Agent 能否仅凭现有资料选取与组装？**
能完成主路径：README 的模块表足以定位候选，registry 的 `purpose/usage/limitations` 足以判断适配，模块文档给出挂载、选项、方法与限制。但「能不能组合得对」还差三处说明：Focus 的框/文字互斥、M01 没有停稳回调、B02 与有状态机制不能直接联动。

**2）哪些顺手，哪些需要翻源码/猜接口？**
顺手：模块加载顺序与依赖声明、统一的 `mount/update/destroy` 形态、D02 换维度、C09 离线公式、B01 的字幕与控件、M01 的动作与回退。
翻源码：`note-focus.js`（box/underline 判定）、`controls.js`（Segmented 的 aria-label 走宿主属性、Button.update 保留节点）、`blocks/stage.js`（`setControls` 重建、StepPlayer 传 `.el`）、`viz/mechanisms.js`（`replayFrom` 随挂载清空、ghost 时长、状态文案）。

**3）组合后的知识说明与演示是否符合聚焦、字幕、步进与可读性原则？**
基本符合：一页一个主题；字幕固定在画面下方且同一步不改写；三步停点，回退/重来/重看后状态与字幕一致；标记只有一套，靠文字与浅底而非仅颜色。折扣在两处观感：删除动作的「离场」不够可见，以及「变化」文字换行让卡片高度在步与步之间变化。

**4）问题是调用、文档还是可复现实现问题？最值得先处理的是什么？**
- 调用：两处是我的参数选择（Grid 最小列宽、早期测试断言），已在交付代码中修正，不计为库问题。
- 文档：F1、F2、F3、F6 是资料缺口；F5 是缺少建议值。
- 组合：F3、F4、F5、F7。
- 实现：没有确认的缺陷（F10 属实现细节，无功能影响）。
- 最值得先处理：在 `docs/blocks-stage.md` 补一段「StepPlayer 是整快照重绘，不能驱动 M01/M02 的动作与历史；需要动画与回退时用 DemoStage + 宿主步表」；其次在 `docs/viz-mechanisms.md` 补「外部标记如何跟随动画」（或给 M01 一个停稳回调），在 `docs/legacy.md` 补 Focus 的 box/underline 互斥与 `setControls` 的焦点影响。
